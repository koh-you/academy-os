# UI Autosave Risk Inventory — 2026-07-29

## 판정 원칙

- 화면 경고는 실제로 남아 있는 저장 손실 가능성만 표시한다.
- 요청 성공이나 최신 요청 ID 확인만으로 서버 최종값이 최신이라고 판정하지 않는다.
- 경고 UI 정리는 저장 callback, API, Supabase 원천, 재조회 계약을 바꾸지 않는다.
- 해결된 경고는 제거하고, 미해결 경고는 저장 원천·중단 조건·복구 방향을 접힘 상세로 유지한다.

## 현재 표시 위치

현재 `AutosaveRiskNotice`는 3개 원천 계약, 7개 화면 위치에서 보인다.

| 원천 계약 | 화면 위치 | 직접 저장 원천 | 현재 보호 | 남은 위험 | 판정 |
| --- | ---: | --- | --- | --- | --- |
| `app_state key별 자동저장` | 설정·수업연구·오답관리 3곳 | `app_state`의 변경 key | 500ms debounce, 화면 request ID | 같은 key의 다중 탭 충돌, 이미 전송된 요청 역전, 저장 뒤 재조회/version 없음 | 유지 |
| `시험정보/시험 후 기록지 입력 저장` | 시험정보 관련 3곳 | `exam_prep_rows` | 행별 최신 request ID와 상태 | bulk upsert 도착 순서, 최종 row 재조회/CAS 없음 | 유지 |
| `학사일정과 시험정보 동시 갱신` | 학사일정 1곳 | `school_events`, `exam_prep_rows`, `lessons` | 화면 저장 상태, 파생 동기화 callback | 다중 원천 전체 성공·최종 대조 없음 | 유지 |

## 해결되어 이미 제거된 경고

- `app_state 전체 snapshot 저장`: 전체 snapshot 자동저장은 제거됐고 현재는 변경 key만 전송한다.
- 학생 프로필 기본정보·성적·상담의 과거 자동저장 경고: 명시 저장과 영역별 상태로 전환되어 현재 화면에 없다.
- 이번 재대조에서 추가로 제거할 현재 경고는 없다. 7개 표시 위치는 모두 아직 실제 위험 계약과 연결된다.

## 실패 시 복구 위치

- `app_state`: 현재 화면 draft/local state를 유지하고, 저장 실패·새로고침 되돌림·다른 탭 충돌이 보이면 같은 key의 추가 입력을 멈춘다.
- `exam_prep_rows`: 행별 실패 상태를 기준으로 해당 시험정보 row의 추가 편집을 멈추고 원천 중복·고사 값부터 확인한다.
- 학사일정 파생 저장: 일정 하나가 시험정보·직전수업 후보를 함께 바꾸므로, 한 원천이라도 불일치하면 추가 저장을 멈추고 세 원천을 함께 확인한다.
