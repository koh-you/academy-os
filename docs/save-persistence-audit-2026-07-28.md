# Academy OS 저장 신뢰성 재전수조사

조사일: 2026-07-28  
기준 커밋: `b4d88105` 이후 작업본  
방법: 현재 프런트 저장 호출, API 저장 helper, 저장 상태 UI, 최근 저장 신뢰성 fixture를 정적 대조했다. 운영 Supabase·Storage·Solapi에는 쓰지 않았다.

## 자동저장 위험 알림 판정

| 화면 경고 | 현재 판정 | 조치 |
|---|---|---|
| `app_state 전체 snapshot 저장` | 해결됨 | 전체 묶음 저장은 제거됐다. 기존 붉은 경고 문구를 삭제하고 `app_state key별 자동저장`으로 교체했다. |
| 설정·수업연구·오답관리의 `app_state key별 자동저장` | 위험 잔존 | 변경 key만 500ms debounce로 저장하지만, 동일 key의 다중 탭/요청 역전과 저장 뒤 재조회·version 대조가 없다. 경고 유지. |
| 시험정보/시험 후 기록지 입력 저장 | 위험 잔존 | 행별 상태는 표시되나 입력마다 bulk upsert가 발생하고, 서버 도착 순서 보장·재조회 대조가 없다. 경고 유지. |
| 학사일정과 시험정보 동시 갱신 | 위험 잔존 | 모달 저장 상태와 시험정보 저장 상태 추적은 있으나, 파생 일정의 시험정보·직전수업 연결이 다중 원천이며 최종 재조회 대조가 없다. 경고 유지. |

현재 화면에 남는 붉은 경고는 위 세 범주, 총 7개 표시 위치(설정·수업연구·오답관리 3 / 시험관리 3 / 학사일정 1)뿐이다. 학생 프로필 기본정보·성적·상담의 과거 자동저장 경고는 명시 저장 흐름 전환 뒤 이미 제거되어 있다.

## 다음 저장 신뢰성 우선순위

1. `app_state` 동일 key의 요청 역전 방지와 저장 후 재조회/version 대조.
2. 시험정보 행을 local draft + 명시 저장 또는 최신 요청 CAS로 전환.
3. 학사일정 파생 저장의 시험정보·직전수업 최종 재조회 대조.
4. 수업일지 다중 행 부분 실패와 수업 복사/되돌리기 저장 계약.

## 사람 검토 gate

배포가 최신 main을 반영한 뒤, 설정·수업연구·오답관리에서 각각 작은 값 하나를 변경하고 `저장 중 → 저장 완료` 뒤 새로고침하여 유지 여부를 확인한다. 실패·되돌림·다른 탭 값 변경이 보이면 그 화면의 다음 입력을 중단한다. 시험정보와 학사일정은 운영 시험 데이터가 바뀌므로 별도 테스트 row가 준비되기 전에는 저장을 누르지 않는다.
