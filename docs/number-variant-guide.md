# 숫자변형 문항 만드는 기준

확립일: 2026-10-03~04 (쎈B 대수 10문항 · 답 20개 수치 검증)

변형은 **같은 책 안의 자매 문항**이다. id 는 `<원본>v<단계>`(`10-19v1`), `variant_of` 가 원본을 가리키고 번호·쪽·단원·유형·꼬리표를 원본에서 물려받는다. 그래서 조판·답지·패키지·등록·화면이 기존 경로를 그대로 탄다.

## 만드는 길

```bash
# 1) 주문서 — 원본과 규칙을 한 파일로 묶는다
node scripts/latex-bank/make-variants.mjs --bank latex-bank/<책> --group <그룹id>
#    --ids a,b | --unit 01 | --all | --limit N | --level 1

# 2) 변형 작성 — 주문서를 읽고 **배치 모양**의 응답 파일을 쓴다
#    { unit, groups: [{ id, section, items: [변형id…] }], items: { 변형id: {…} } }

# 3) 조판 검증 — 임시 책으로 컴파일한다(Overfull·치명 경고 0 이어야 한다)
node scripts/latex-bank/check-batch.mjs <응답.json> --bank latex-bank/<책>

# 4) 계약 검증 후 삽입 — 위반이 하나라도 있으면 **적용하지 않는다**
node scripts/latex-bank/apply-variants.mjs --bank latex-bank/<책> --response <응답.json> --check
node scripts/latex-bank/apply-variants.mjs --bank latex-bank/<책> --response <응답.json>

# 5) 빠른정답 만들기 — 변형은 스캔 답지에 없으므로 전사본의 확정 답으로 조판한다
node scripts/latex-bank/fix-answer-crops.mjs --bank latex-bank/<책> --package <패키지> --ids <변형id…> --add

# 6) 패키지에 넣기(조판은 변형만) → 등록
node scripts/latex-bank/build.mjs --bank latex-bank/<책> --bank-only \
  --package <스캔패키지> --export <조판패키지> --only <변형id…>
node scripts/problem-bank/upload-package.mjs --package <조판패키지> --confirm
```

## 무엇을 바꾸고 무엇을 지키나

**지킨다** — 묻는 것, 풀이 방법, 단원·유형의 범위, 문항의 골조와 말투, 보기 개수, 꼬리표(대표 문제·서술형).

**바꾼다** — 숫자, 그에 따라 달라지는 답, 객관식 오답 보기.

### 규칙

1. **답이 깔끔하게 떨어지게 숫자를 고른다.** 원본이 정수로 떨어졌으면 변형도 떨어져야 한다.
2. **원본과 같은 답이 되게 만들지 않는다.** 답만 베껴 쓰면 변형이 소용없다.
3. **답 번호(①~⑤)까지 달라지게 한다.** 값이 달라도 번호가 같으면 원본을 보고 찍는다. 보기 전체를 한 칸 옮기거나, 조건의 부호를 뒤집어 답이 반대쪽 끝에 오게 한다.
4. **오답 보기도 다시 만든다.** 원본 보기를 그대로 두면 계산하지 않고도 답이 보인다. 보기의 **범위 자체**를 옮기는 것도 방법이다(`-2~2` → `-1~3`).
5. **풀이(solution)에 중간값을 적는다.** 답만 적으면 사람이 검증할 수 없다.
6. **확신이 없으면 만들지 말고 skip 에 이유를 적는다.** 틀린 변형은 없는 변형보다 나쁘다 — 학생이 틀린 답으로 채점받는다.

### 문항 모양별로 주의할 것

| 모양 | 함정 | 어떻게 |
| --- | --- | --- |
| 「다음 중 옳은 것은?」 | 본문은 발문 한 줄이고 **보기가 문항의 내용**이다 | 보기의 숫자를 바꾸고 **참인 보기의 위치를 옮긴다**. 참이 정확히 하나인지 반드시 확인 |
| 구조가 답을 강제하는 것 | 「쌍으로 묶여 1이 되는 항 4개」는 숫자를 바꿔도 답이 늘 2다 | **항의 수**를 바꾼다(4개→6개). 방법은 그대로고 쌍의 수만 는다 |
| 집합·열거 | 원소가 겹쳐 개수가 엉뚱해진다 | 값이 **전부 다른지** 수치로 확인한다. 근호 차수를 홀수로 맞추면 음수도 실근을 가져 개수가 깔끔해진다 |
| 조건을 만족하는 값의 합 | 부호가 바뀌는 자리가 어디인지가 전부다 | 이차식의 근을 옮겨 **부호 전환점**을 이동시킨다 |

### 그림

| 원본 | 할 일 |
| --- | --- |
| 없음 | 본문 숫자만 바꾼다 |
| `tikz:fig-…` | 바꾼 숫자가 그림에도 보이면 `figures/fig-<변형id>.tex` 로 복사해 좌표·라벨을 같이 고치고 `figure` 를 새 이름으로. 그림에 숫자가 없으면 원본 그대로 |
| `crop:fig-….png` | 스캔 그림이라 **그 안 숫자는 못 바꾼다**. 그림에 안 적힌 값만 바꾸고, 그림의 숫자를 바꿔야 풀리면 skip |

## 검증 — 이게 핵심이다

**답을 수치로 독립 검증한다.** 손으로 푼 것과 따로, 식을 그대로 계산하는 코드를 짜서 맞춰 본다. **원본도 함께 검증한다** — 원본 이해가 틀렸으면 변형도 틀린다.

```js
// 2026-10-03 쎈B 대수 유형 05 예
check("10-19 원본", (4 ** -4 + 2 ** -5) / 9 * (10 / (3 ** 10 + 9 ** 4)), 6 ** -8, "6^-8 (③)");
check("10-19v1   ", (4 ** -3 + 2 ** -4) / 5 * (4 / (3 ** 7 + 9 ** 3)), 6 ** -6, "6^-6 (②)");
```

열거형(집합의 원소 수, 조건을 만족하는 값의 합)은 **전부 돌려서 센다**. 참·거짓 판별형은 보기마다 참값을 계산해 **참이 정확히 하나인지** 확인한다.

이 검증을 거치지 않은 변형은 올리지 않는다. 2026-10-03~04 에 만든 10문항은 원본 포함 **20개 전부 일치**를 확인하고 넣었다.

## `apply-variants` 가 막는 것

검사는 사람이 깜빡하는 자리를 잡는다. 위반이 하나라도 있으면 **아무것도 적용하지 않는다**.

- `variant_of` 가 전사본에 있나 · id 가 `<원본>v<단계>` 모양인가 · 이미 있지 않나
- **본문도 보기도 원본과 같지 않은가** — 본문만 보면 「옳은 것은?」 류를 거절한다(2026-10-03 에 실제로 그래서 고쳤다)
- 본문·보기의 **숫자가 실제로 달라졌나**(그림만 바꿨으면 `figure_changed: true`)
- 보기 개수가 원본과 같은가 · 답이 ①~⑤ 범위 안인가 · 보기가 원본과 통째로 같지 않은가
- `solution` 이 있고 10자를 넘는가 · `variation_note` 가 있는가 · `answer_source` 가 `계산` 인가
- 스캔 그림을 그대로 쓰면 `figure_kept_reason` 이 있는가

## 화면에서 어떻게 보이나

변형은 **평소 목록에 안 보인다**(교재에 없는 문항이 번호 사이에 끼면 교재 순서가 무너진다). 오답지·시험지의 「포함할 항목 → 숫자변형」을 켤 때만 **원본 바로 뒤**에 선다. 고른 문항에 변형이 하나도 없으면 토글 자체가 안 보인다.

출처는 변형 번호표(`10-19v1`)가 아니라 **원본 번호 + 숫자변형**으로 읽는다. 교재관리의 「문항 N개」는 교재에 실린 문항만 세고 변형은 따로 적는다.
