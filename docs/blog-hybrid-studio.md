# 블로그 하이브리드 스튜디오

연구실 → 블로그 스튜디오 → 새 콘텐츠에서 시작한다.

1. 자료 준비: 내신 기록 1건을 선택하거나 학교·시험·성과를 직접 입력한다. 선생님 관찰을 적고 공개 동의와 사실 확인을 표시한다. 이미지는 링크와 설명으로 관리하고 실제 파일은 Chat에 별도 첨부한다.
2. 편집 내용 저장: API 성공 뒤 Supabase 재조회 값이 일치해야 저장 완료다. 저장하지 않고 다른 메뉴로 나가면 확인한다.
3. Chat 전달: 확인한 자료만 들어간 프롬프트를 복사해 Chat에 붙여 넣는다. 학생 ID와 원천 전체 객체는 전달하지 않는다. 자유 메모의 익명화는 교사가 확인한다.
4. 완성본: 글을 각 칸에 붙여 넣거나 JSON 미리보기 후 반영한다. 누락된 선택 항목은 기존 값을 유지하고 제목·본문이 없는 결과는 거절한다.
5. 완성본 확정 및 저장: 편집본을 새 버전으로 보존한다. 이후 편집은 기존 확정본을 변경하지 않는다.
6. 네이버에 직접 게시하고 게시물 URL·발행일을 저장한다.

## 저장 경계

기존 tenant scoped app_state의 blogHybridContents key에 콘텐츠 배열을 저장한다. 기존 postAppState 계약 및 createAppStatePersistenceController의 key별 CAS와 Supabase 재조회를 사용한다. 서버/인증/DB migration 변경은 없다. 409나 재조회 불일치에는 저장 실패를 표시하며 입력을 보존한다. 충돌 후 편집 내용을 복사해 두고 최신 서버 상태를 다시 불러와 대조한다. 자동 덮어쓰기나 충돌 강제 저장은 없다.

원본 scoreRecords는 변경하지 않고 가져온 당시 스냅샷을 보관한다. 원천이 바뀌어도 사람이 편집 중인 콘텐츠를 자동 변경하지 않는다. 공개 동의는 해당 콘텐츠 자료 범위의 확인이며 학생 전체의 전역 동의 원천을 대체하지 않는다.

## MVP 범위

- 학교별 성과·시험 분석·수업 소개는 수동 입력 템플릿이며 시험분석 v2 자동 연결은 후속 범위다.
- 이미지 파일 업로드·자동 생성, OS 내부 AI 호출, 자동 게시, 조회수 수집은 포함하지 않는다.
- 첨부 ZIP의 설계와 source model을 참고했으나 코드·SQL·AI route는 그대로 적용하지 않았다.
- 대량 콘텐츠의 독립 행 저장·학생별 동의 관리가 필요해지면 별도 서버 도메인으로 확장한다.

## SNS 확장 · 2026-09-06

메뉴는 SNS 콘텐츠 스튜디오다. 완성본의 social은 인스타그램 캡션이며 instagramHashtags는 별도 선택 필드다. 기존 저장 자료를 마이그레이션하지 않고 누락된 새 필드는 빈 문자열로 표시한다. 자료 준비의 지역은 기본 창동이며 변경·삭제할 수 있다. 자동 추천은 입력 자료로 계산하고, 반영 버튼에서만 해당 태그 편집칸을 바꾼다. 인스타그램 추천 최대 5개는 제품 기본값이다. 캡션과 태그를 각각 복사해 인스타그램에서 게시한다. 현재 발행 기록 URL은 네이버 게시물용이다.
