# 편집 교재 기획안 — 여러 교재를 모아 한 권으로

작성일: 2026-10-03 · 2026-10-03 개정(중간저장·최종 제작 · 복사 허용) · 상태: 기획(구현 전)

## 한 줄 결론

교재 제작은 **한 번에 끝나지 않는다.** 그래서 「편집 중인 초안」과 「확정한 제작본」을 처음부터 갈라 둔다. 초안은 몇 번이고 고치고 중간저장하며, 마지막에 **최종 제작**을 누르면 그 시점의 내용이 굳어 교재 한 권이 된다. 1단계(담기 → 구획 짜기 → 중간저장 → 최종 제작 → 인쇄)는 **새 표 3개 + 화면 1개**로 끝난다.

## 지금 되는 것과 안 되는 것

| | 지금 | 모자란 것 |
| --- | --- | --- |
| 여러 교재에서 문항 고르기 | **된다** — 시험지 제작의 바구니가 교재를 오가며 담는다 | 교재를 하나씩 들어가야 한다 |
| 구획(단원·유형) 단위로 고르기 | **된다** — 단원/유형 머리줄 토글로 통째로 고르고 푼다 | 고른 결과를 **구획째로** 새 교재의 단원으로 옮기지 못한다 |
| 순서 정하기 | 시험지에서 교재순·담은순·섞기 | 내가 짠 순서를 저장하지 못한다 |
| 내보내기 | 인쇄(1단/2단·워터마크) · PPTX · 빠른정답 · 해설 | 조판된 책(라텍스) 산출은 없다 |
| **중간저장** | **안 된다** — 바구니는 화면을 벗어나면 사라진다 | 이게 핵심 결손이다 |
| **확정(최종 제작)** | 없다 | 인쇄한 교재가 나중에 원본이 바뀌면 같이 변해 버린다 |

고르는 일은 이미 거의 다 된다. **기획의 무게는 「여러 번 고치고 마지막에 굳히는 길」에 있다.**

## 두 상태 — 초안과 제작본

```
  초안(draft)                              제작본(published)
  ────────────────                         ──────────────────
  참조만 한다                               그 시점 내용을 복사해 굳힌다
  담기·빼기·순서 바꾸기 자유                 더 못 고친다(고치려면 복제해 새 초안)
  저장은 몇 번이든                          번호가 고정된다
  원본 교재가 바뀌면 같이 바뀐다              원본이 바뀌어도 그대로다
  인쇄 미리보기 가능                        인쇄본과 화면이 영원히 일치한다
                        ──[최종 제작]──▶
                        ◀──[복제해 수정]──
```

**왜 초안은 참조인가.** 담았다 뺐다를 수십 번 하는 동안 문항을 복사하면 그때마다 행과 이미지가 생겼다 사라진다. 참조는 줄 하나만 움직인다.

**왜 제작본은 복사인가.** 「최종 제작」의 뜻은 *이대로 굳힌다*이다. 나중에 원본 교재를 재조판하거나 답을 고쳐도 이미 인쇄해 학생에게 준 교재는 변하면 안 된다. 2026-10-02 조판 설정 수정 때 **이미 등록한 5권의 문항 이미지 65%가 바뀌었다** — 참조만 했다면 그날 모든 제작본의 생김새가 같이 변했다.

학생이 같은 문항을 원본 교재에서도 풀고 제작본에서도 푸는 것은 **괜찮다**(사용자 확인 2026-10-03). 오답 기록이 교재별로 따로 쌓이므로 「쎈B에서 틀린 걸 내 교재에서도 틀렸다」를 각각 볼 수 있다.

## 데이터 모델

새 표 3개. 기존 표는 건드리지 않는다.

```sql
problem_bank_collections          -- 편집 교재 한 권(초안)
  collection_id text primary key
  tenant_id, title, folder_path, subject, grade
  status text          -- draft | published
  published_book_id text   -- 최종 제작으로 만들어진 교재(problem_bank_books). 초안이면 빈 값
  published_at timestamptz
  note text
  created_at, updated_at

problem_bank_collection_sections  -- 그 안의 구획(= 단원)
  section_id text primary key
  collection_id → collections (on delete cascade)
  position integer
  title text         -- "01 지수 · 유형 05" 처럼 사람이 정한다
  note text          -- 수업용 메모(인쇄에는 안 나감)

problem_bank_collection_items     -- 구획 안의 문항(초안이므로 원본 참조)
  entry_id text primary key
  collection_id → collections (on delete cascade)
  section_id    → sections     (on delete cascade)
  position integer
  item_id       → problem_bank_items (on delete cascade)   -- 원본 참조
  include_variants boolean default false   -- 이 자리에 숫자변형도 같이 낼지
  note text                                -- 「이건 빼도 될지도」 같은 피드백 메모
  unique (collection_id, item_id)
```

**최종 제작**은 초안을 읽어 보통 교재 한 권을 만든다 — `problem_bank_books` 에 행 하나(`source_kind = 'composed'`), 구획마다 `problem_bank_units`, 문항마다 `problem_bank_items` **새 행**, 이미지는 그 시점 파일을 제작본 경로로 복사한다. 그때부터 제작본은 등록된 34권과 완전히 같은 교재다 — 오답관리·시험지 제작·숫자변형이 전부 그대로 통한다. 추가로 필요한 것은 없다.

기존 표의 유일한 변경: `problem_bank_books.source_kind` 의 CHECK 에 `'composed'` 를 더한다.

```
GET    /api/problem-bank/collections         초안 목록
GET    /api/problem-bank/collection?id=…     한 권(구획 + 문항 + 원본 문항 정보)
POST   /api/problem-bank/collection          중간저장(통째 저장)
POST   /api/problem-bank/collection/publish  최종 제작
DELETE /api/problem-bank/collection          삭제
```

중간저장은 **통째 저장(replace)** 이다. 구획·순서를 끌어 옮기는 화면이라 부분 저장은 순서가 어긋나기 쉽다. `AGENTS.md` 의 `local draft → 명시적 저장 → API 성공 → 재조회 대조` 를 그대로 따른다.

## 화면 — 교재관리 안의 새 탭 「편집 교재」

왼쪽은 **오답관리의 교재 탐색 화면을 그대로 재사용**한다(단원 접기·유형 머리줄·구획 토글이 이미 있다).

```
┌─ 교재관리 ─────────────────────────────────────────────────────────────────┐
│  [교재 목록] [편집 교재]                                                    │
├──────────────────┬─────────────────────┬──────────────────────────────────┤
│ ① 고르기          │ ② 담은 것            │ ③ 짜기  내신대비 지수·로그  초안  │
│                  │                     │                                  │
│ 교재  [쎈B 대수▾] │  담음 18문항         │  ▾ 1. 지수법칙 기본      8문항 ⠿  │
│ ───────────────  │  쎈B 대수      12    │     쎈B 10-19 · 10-20 …          │
│ ▾ 01 지수   0/58 │  RPM 대수       6    │     + 숫자변형 함께      ☑       │
│   유형05 정수식  │                     │  ▾ 2. 로그의 성질       6문항 ⠿  │
│    19 20 21 22   │  [구획으로 넣기]     │     RPM 0312 · 0315 …            │
│    ■ ■ □ □       │  [비우기]           │  [+ 구획 추가]                   │
│   유형06 실수식  │                     │  ─────────────────────────────   │
│    23 24 25      │                     │  14문항 · 2구획                  │
│ ▾ 02 로그   0/61 │                     │  마지막 저장 14:32               │
│                  │                     │  [중간저장] [미리보기] [최종 제작]│
└──────────────────┴─────────────────────┴──────────────────────────────────┘
```

- **①→②** 는 지금 시험지 바구니와 같다. 교재를 바꿔도 ②가 유지되는 것이 「교재끼리 섞기」다.
- **②→③** 이 새로 필요한 한 가지 동작: 담은 것을 **구획으로 떨군다**. 기본 구획 제목은 고른 구획 이름 그대로(`01 지수 · 유형 05`).
- **중간저장**은 언제든. 저장 안 한 변경이 있으면 화면을 떠날 때 묻는다.
- **미리보기**는 지금 인쇄지를 그대로 연다 — 쪽 수와 생김새를 보고 다시 고친다. 이게 「피드백을 몇 번 거친다」의 실제 모습이다.
- **최종 제작**은 확인 대화상자를 거친다: 「문항 N개를 복사해 교재 한 권을 만듭니다. 만든 뒤에는 이 교재가 고정됩니다.」

초안 목록에는 상태가 보인다 — `초안 · 14문항 · 어제 저장` / `제작 완료 · 2026-10-03 · 교재 보기 →`.

### 구획을 만드는 세 가지 길

| 길 | 쓰임 | 구현 |
| --- | --- | --- |
| **교재 구획 그대로** (기본) | 한 교재의 유형 몇 개를 뽑아 보충 교재 | 이미 있는 `groupItemsByTypeSection` 결과를 그대로 |
| **유형으로 모으기** | 여러 교재의 같은 유형을 한 구획에 — 유형별 교재 | `type_label` 로 묶는다. 모든 문항에 이미 있다 |
| **직접** | 난이도순·수업 순서 | 빈 구획 만들고 끌어 넣기 |

「유형으로 모으기」는 데이터가 이미 있어 싸고 효용이 크다. 다만 교재마다 유형 이름이 달라(`유형 05 지수가 정수인 식의 계산` vs `03 지수법칙`) 자동으로 다 묶이지는 않는다. **같은 이름만 자동으로 묶고 나머지는 사람이 합친다** — 비슷한 이름을 AI 로 묶는 것은 1단계에서 하지 않는다(틀리게 묶이면 조용히 엉뚱한 문항이 섞인다).

## 산출물

초안 미리보기와 제작본 인쇄 모두 **지금 있는 인쇄 경로를 그대로 쓴다**. `WrongAnswerPrintSheet` 가 「문항 + 출처」 행 목록을 받으므로 1단/2단·워터마크·빠른정답·해설·출처 위치·숫자변형이 전부 따라온다. PPTX 도 같다.

**라텍스 조판본**(진짜 책 모양 · 쪽번호 · 목차)은 뒤 단계다. 참조한 문항이 라텍스 전사본이 있는 교재일 때만 되는데, 지금 34권 중 7권이다.

## 단계

| 단계 | 내용 | 완료 기준 | 크기 |
| --- | --- | --- | --- |
| **1** | 표 3개 · API 5개 · 「편집 교재」 탭 · 담기→구획→중간저장→미리보기→최종 제작 | 초안을 며칠에 걸쳐 고치고 저장했다가 제작하면 교재 목록에 새 교재가 선다 | 중 |
| **2** | 유형으로 모으기 · 끌어 옮기기 · 번호 다시 매기기 · 중복 경고 | 여러 교재를 유형으로 묶어 한 권이 나온다 | 중 |
| **3** | 제작본 복제해 수정 · 제작 이력(2판·3판) | 작년 교재를 복제해 몇 문항만 갈아 올해 판을 만든다 | 소 |
| **4** | 라텍스 조판본 내보내기(목차·쪽번호) | 7권 범위에서 책 모양 PDF 가 나온다 | 대 |

1단계만으로 「여러 교재를 모아 몇 번 고친 뒤 한 권으로 굳힌다」가 된다.

## 결정이 필요한 것 (제안 포함)

1. **제작본을 교재 목록에 같이 보일까** — 제안: **같이 보이되 배지로 구분**(`제작` 배지). 오답관리·시험지 제작에서 쓰려면 같은 목록에 있어야 하고, 제작본은 기술적으로 보통 교재와 완전히 같다. 초안은 「편집 교재」 탭에만 둔다.
2. **번호를 다시 매길까** — 제안: **제작할 때 1부터 다시 매긴다.** 출처 줄에 원본(`쎈B 대수 · 01 지수 · 19번`)이 남아 어디서 왔는지 늘 보인다. 초안 단계에서는 원본 번호로 보여 준다(고르는 중에는 원본 번호가 더 쓸모 있다).
3. **같은 문항이 두 교재에 있을 때 걸러낼까** — 제안: **1단계에서는 안 한다.** 이미지·본문 비교가 필요해 싸지 않고, 틀리게 걸러내면 문항이 조용히 사라진다. 2단계에서 「유형·답이 같은 문항」만 노란 표시로 알린다(막지 않는다).
4. **한 권의 상한** — 제안: **초안 300문항.** 넘으면 인쇄 미리보기가 느려진다(지금 바구니도 같은 한계). 넘으면 막지 말고 「미리보기가 느릴 수 있습니다」로 알린다.
5. **제작본을 고치고 싶을 때** — 제안: **제작본은 못 고치고, 「복제해 수정」으로 새 초안을 만든다.** 굳힌다는 말과 고칠 수 있다는 말은 같이 설 수 없다. 복제는 싸다(참조 목록만 다시 만든다).
6. **제작할 때 이미지도 복사할까** — 제안: **복사한다.** 안 하면 원본 교재를 재조판하는 날 제작본의 생김새가 같이 바뀐다(2026-10-02 에 5권 65% 가 바뀌었다). 교재 한 권이 100~300장이라 비용은 작다.

## 안 하는 것

- **문항 본문을 편집 교재 안에서 고치는 기능.** 원본을 고치는 길(전사본 → 재조판 → 재등록)과 둘로 갈라지면 어느 쪽이 원천인지 알 수 없게 된다. 고쳐야 하면 원본을 고치고 다시 제작한다.
- **AI 가 문항을 골라 주는 기능.** 고르는 것은 사람이 한다. AI 는 숫자변형처럼 사람이 확정하는 초안까지만 만든다.
