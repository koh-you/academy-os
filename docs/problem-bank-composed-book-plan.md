# 편집 교재 기획안 — 여러 교재를 모아 한 권으로

작성일: 2026-10-03 · 상태: 기획(구현 전) · 결정 필요 항목은 맨 아래

## 한 줄 결론

문항을 **복사하지 않고 참조**하는 「편집 교재」를 교재관리 안에 새 탭으로 만든다. 등록된 34권에서 단원·유형·문항을 골라 담아 구획을 짜고, 저장해 두고 다시 꺼내 쓰고, 인쇄·PPT·시험지로 낸다. 1단계(담아서 저장하고 인쇄까지)는 **새 표 3개 + 화면 1개**로 끝난다.

## 지금 되는 것과 안 되는 것

| | 지금 | 모자란 것 |
| --- | --- | --- |
| 여러 교재에서 문항 고르기 | **된다** — 시험지 제작의 바구니가 교재를 오가며 담는다 | 교재를 하나씩 들어가야 한다. 한 화면에서 여러 교재를 못 본다 |
| 구획(단원·유형) 단위로 고르기 | **된다** — 단원/유형 머리줄의 토글로 통째로 고르고 푼다 | 고른 결과를 **구획째로** 새 교재의 단원으로 옮기지 못한다 |
| 순서 정하기 | 시험지에서 교재순·담은순·섞기 | 내가 짠 순서를 저장하지 못한다 |
| 내보내기 | 인쇄(1단/2단·워터마크) · PPTX · 빠른정답 · 해설 | 조판된 책(라텍스) 산출은 없다 |
| **저장** | **안 된다** — 바구니는 화면을 벗어나면 사라진다 | 이게 핵심 결손이다 |
| 학생에게 주기 | 교재 단위로만 오답 기록이 쌓인다 | 편집 교재 단위의 진도·오답 집계가 없다 |

즉 **고르는 일은 이미 거의 다 되고, 그 결과를 「한 권」으로 남기는 길이 없다.** 기획의 무게는 새 UI가 아니라 저장 모델에 있다.

## 핵심 설계 결정 — 복사하지 않고 참조한다

편집 교재의 문항을 `problem_bank_items` 에 **새 행으로 복사**할 수도 있다. 하지만 하면 안 된다.

1. **학생 오답 기록이 갈라진다.** `problem_bank_attempts` 는 `(student_id, item_id, round)` 로 유일하다. 같은 문항을 복사해 새 `item_id` 를 주면 「쎈B 19번을 틀렸다」와 「내 교재 3번을 틀렸다」가 서로 다른 문항이 된다. 반복 출제의 의미가 사라진다.
2. **이미지가 통째로 복제된다.** 지금 등록된 34권이 2.5만 문항이다. 100문항짜리 편집 교재 하나가 이미지 100장을 새로 올린다. 조판 수정이 있을 때마다 사본이 전부 낡는다.
3. **원본을 고치면 같이 고쳐져야 한다.** 조판 설정·답 수정·숫자변형 추가가 편집 교재에 자동으로 반영되는 쪽이 맞다.

그래서 편집 교재는 **순서 있는 참조 목록**이다. 문항의 원본(이미지·답·해설·유형·출처)은 늘 원래 교재의 것을 본다.

반대급부(받아들이는 한계): 원본 교재를 삭제하면 그 문항을 쓰던 편집 교재에 구멍이 난다. 삭제 확인 대화상자에 「이 교재의 문항 N개를 편집 교재 M권이 쓰고 있습니다」를 띄우고 막는다.

## 데이터 모델

새 표 3개. 기존 표는 건드리지 않는다(= 지금 등록된 34권은 그대로).

```sql
problem_bank_collections          -- 편집 교재 한 권
  collection_id text primary key
  tenant_id, title, folder_path, subject, grade
  status text  -- draft | ready
  note text
  created_at, updated_at

problem_bank_collection_sections  -- 그 안의 구획(= 단원)
  section_id text primary key
  collection_id → collections (on delete cascade)
  position integer
  title text         -- "01 지수 · 유형 05" 처럼 사람이 정한다
  note text          -- 수업용 메모(인쇄에는 안 나감)

problem_bank_collection_items     -- 구획 안의 문항(원본 참조)
  entry_id text primary key
  collection_id → collections (on delete cascade)
  section_id    → sections     (on delete cascade)
  position integer
  item_id       → problem_bank_items (on delete restrict)  -- 원본. 복사하지 않는다
  include_variants boolean default false   -- 이 자리에 숫자변형도 같이 낼지
  override_number text default ''          -- 편집 교재 안에서 다시 매긴 번호(비면 원본 번호)
  unique (collection_id, item_id)           -- 한 권 안에 같은 문항이 두 번 들어가지 않는다
```

`on delete restrict` 가 위에서 말한 「원본 삭제 시 구멍」을 DB 단에서 막는다.

API 는 기존 `problemBankRouteRegistry` 에 네 개만 더한다.

```
GET    /api/problem-bank/collections            목록
GET    /api/problem-bank/collection?id=…        한 권(구획 + 문항 + 원본 문항 정보 조인)
POST   /api/problem-bank/collection             만들기·이름/구획/순서 저장(통째 저장)
DELETE /api/problem-bank/collection             삭제
```

저장은 **통째 저장(replace)** 로 둔다. 구획·순서를 끌어 옮기는 화면이라 부분 저장은 순서가 어긋나기 쉽다. `AGENTS.md` 의 `local draft → 명시적 저장 → API 성공 → 재조회 대조` 를 그대로 따른다.

## 화면 — 교재관리 안의 새 탭 「편집 교재」

교재관리는 지금 교재 목록 + 상세다. 여기에 탭을 하나 더 둔다. 3단 레이아웃이고, 왼쪽은 **오답관리의 교재 탐색 화면을 그대로 재사용**한다(단원 접기·유형 머리줄·구획 토글이 이미 있다).

```
┌─ 교재관리 ─────────────────────────────────────────────────────────────────┐
│  [교재 목록] [편집 교재]                                                    │
├──────────────────┬─────────────────────┬──────────────────────────────────┤
│ ① 고르기          │ ② 담은 것            │ ③ 짜기 (편집 교재)                │
│                  │                     │                                  │
│ 교재  [쎈B 대수▾] │  담음 18문항         │  제목 [내신대비 지수·로그 ]       │
│ ───────────────  │  쎈B 대수      12     │  폴더 [고2 / 내신대비 ]           │
│ ▾ 01 지수   0/58 │  RPM 대수       6     │  ─────────────────────────────   │
│   유형05 정수식  │                     │  ▾ 1. 지수법칙 기본      8문항 ⠿  │
│    19 20 21 22   │  [모두 구획에 넣기]  │     쎈B 10-19 · 10-20 …          │
│    ■ ■ □ □       │  [비우기]           │     + 숫자변형 함께      ☑       │
│   유형06 실수식  │                     │  ▾ 2. 로그의 성질       6문항 ⠿  │
│    23 24 25      │                     │     RPM 0312 · 0315 …            │
│ ▾ 02 로그   0/61 │                     │  [+ 구획 추가]                   │
│                  │                     │  ─────────────────────────────   │
│ 다른 교재 담기 →  │                     │  14문항 · 2구획   [저장] [인쇄]   │
└──────────────────┴─────────────────────┴──────────────────────────────────┘
```

- **①→②** 는 지금 시험지 바구니와 같은 동작이다. 교재를 바꿔도 ②가 유지되는 것이 「교재끼리 섞기」다.
- **②→③** 이 새로 필요한 한 가지 동작: 담은 것을 **구획으로 떨군다**. 기본은 「고른 구획 이름 그대로」(예: `01 지수 · 유형 05`)를 구획 제목으로 쓴다 — 교재의 구획을 그대로 가져오는 것이 가장 흔한 쓰임이다.
- **③** 안에서 구획과 문항을 끌어 옮긴다. 번호는 저장할 때 1부터 다시 매긴다(원본 번호는 출처 줄에 남는다).

### 구획을 만드는 세 가지 길

| 길 | 쓰임 | 구현 |
| --- | --- | --- |
| **교재 구획 그대로** (기본) | 한 교재의 유형 몇 개를 뽑아 보충 교재 | 이미 있는 `groupItemsByTypeSection` 결과를 그대로 구획으로 |
| **유형으로 모으기** | 여러 교재의 같은 유형을 한 구획에 — 유형별 교재 | `type_label` 로 묶는다. 모든 교재의 모든 문항에 이미 있다 |
| **직접** | 난이도순·수업 순서 | 빈 구획 만들고 끌어 넣기 |

「유형으로 모으기」는 데이터가 이미 있어 싸고, 효용이 가장 크다. 다만 교재마다 유형 이름이 달라(`유형 05 지수가 정수인 식의 계산` vs `03 지수법칙`) 자동으로 완벽히 묶이지는 않는다. **같은 이름만 자동으로 묶고 나머지는 사람이 합친다** — 비슷한 이름을 AI 로 묶는 것은 1단계에서 하지 않는다(틀리게 묶이면 조용히 엉뚱한 문항이 섞인다).

## 산출물

1단계는 **지금 있는 인쇄 경로를 그대로 쓴다**. `WrongAnswerPrintSheet` 가 「문항 + 출처」 행 목록을 받으므로, 편집 교재를 그 모양으로 넘기면 1단/2단·워터마크·빠른정답·해설·출처 위치·숫자변형이 전부 바로 따라온다. PPTX 도 같다.

2단계로 **라텍스 조판본**(진짜 책 모양 · 쪽번호 · 목차)을 둔다. 편집 교재의 참조 목록을 `latex-bank` 의 임시 책으로 펴서 `build.mjs` 에 넘기는 방식인데, 참조한 문항이 **라텍스 전사본이 있는 교재**일 때만 된다(스캔 크롭만 있는 교재는 이미지 배치로 떨어진다). 지금 34권 중 라텍스 전사본이 있는 것은 7권이다. 그래서 2단계로 미룬다.

## 단계

| 단계 | 내용 | 완료 기준 | 크기 |
| --- | --- | --- | --- |
| **1** | 표 3개 · API 4개 · 「편집 교재」 탭 · 담기→구획→저장 · 인쇄/PPT | 편집 교재를 만들어 저장하고, 새로고침·다른 기기에서 그대로 열리고, 인쇄가 나온다 | 중 |
| **2** | 유형으로 모으기 · 끌어 옮기기 · 번호 다시 매기기 · 중복 경고 | 여러 교재를 유형으로 묶어 한 권이 나온다 | 중 |
| **3** | 학생 배정 · 편집 교재 단위 오답 기록·진도 | 학생별 오답 화면이 편집 교재로도 보인다 | 중 |
| **4** | 라텍스 조판본 내보내기(목차·쪽번호) | 7권 범위에서 책 모양 PDF 가 나온다 | 대 |

1단계만으로도 지금 못 하는 일(여러 교재를 모아 한 권으로 저장·재사용)이 된다. 2~4단계는 쓰면서 정한다.

## 결정이 필요한 것

1. **편집 교재를 교재 목록에 같이 보일까, 따로 보일까.** 같이 보이면 「34권 + 내가 만든 N권」이 한 트리에 선다(오답관리에서도 바로 고를 수 있다). 따로 보이면 원본 교재 목록이 안 더러워진다. — 제안: **같이 보이되 배지로 구분**한다. 오답관리에서 쓰려면 같은 목록에 있어야 한다.
2. **번호를 다시 매길까, 원본 번호를 둘까.** — 제안: **다시 매기고**(1, 2, 3…) 출처 줄에 원본을 남긴다. 숫자변형과 같은 규칙이다.
3. **같은 문항이 두 교재에 있을 때**(쎈과 RPM 의 고전 문항) 자동으로 걸러낼까. — 제안: **1단계에서는 안 한다.** 이미지·본문 비교가 필요해 싸지 않고, 틀리게 걸러내면 문항이 조용히 사라진다. 2단계에서 「유형·답이 같은 문항」만 노란 표시로 알린다.
4. **한 권의 상한.** — 제안: 300문항. 넘으면 인쇄 미리보기가 느려진다(지금 바구니도 같은 한계).

## 안 하는 것

- 문항 본문을 편집 교재 안에서 **고치는** 기능. 원본을 고치는 길(전사본 → 재조판 → 재등록)과 둘로 갈라지면 어느 쪽이 원천인지 알 수 없게 된다.
- AI 가 문항을 **골라 주는** 기능. 고르는 것은 사람이 한다. AI 는 숫자변형처럼 사람이 확정하는 초안까지만 만든다.
- 편집 교재의 문항 이미지를 따로 저장하는 것. 위의 「복사하지 않는다」와 같은 이유.
