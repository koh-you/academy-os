# 자체 교재 기획안 — 여러 교재를 모아 한 권으로

작성일: 2026-10-03 · 2차 개정(중간저장·제작 · 복사 허용) · 3차 개정(시중/자체 분리 · 번호 다시 매김 · 제작본 수정 · 이미지 새로 조판) · 상태: 기획(구현 전)

## 한 줄 결론

교재 제작은 한 번에 끝나지 않는다. **초안을 몇 번이고 고치며 중간저장하다가 「제작」을 누르면 그 내용으로 자체 교재 한 권이 선다.** 제작한 뒤에도 초안을 고쳐 다시 제작하면 그 교재가 갱신된다. 문항 이미지는 원본에서 **복사하지 않고 새 번호로 다시 조판한다** — 등록된 34권 전부에 라텍스 전사본이 있어서 가능하다(29,634문항).

## 지금 되는 것과 안 되는 것

| | 지금 | 모자란 것 |
| --- | --- | --- |
| 여러 교재에서 문항 고르기 | **된다** — 시험지 바구니가 교재를 오가며 담는다 | 교재를 하나씩 들어가야 한다 |
| 구획(단원·유형) 단위로 고르기 | **된다** — 단원/유형 머리줄 토글 | 고른 결과를 **구획째로** 새 교재의 단원으로 옮기지 못한다 |
| 내보내기 | 인쇄(1단/2단·워터마크) · PPTX · 빠른정답 · 해설 | 「교재」로 남지 않는다 |
| **중간저장** | **안 된다** — 바구니는 화면을 벗어나면 사라진다 | 핵심 결손 |
| **번호 다시 매기기** | 안 된다 — 이미지에 원본 번호가 찍혀 있다 | 다시 조판해야 한다 |
| 시중 교재와 내 교재 구분 | 없다 — 한 목록에 섞인다 | 등록 단계에서 갈라야 한다 |

## 1. 시중 교재와 자체 교재를 갈라 등록한다

배지로 표시만 하는 게 아니라 **등록 자체를 두 갈래로 나눈다.**

```
교재관리
├─ 시중 교재            쎈B · RPM · 개념원리 · 베이직쎈 · 라이트쎈 · 100발100중 …
│   └─ 출판사 교재를 스캔·전사해 등록한 것. 지금 34권.
└─ 자체 교재            내신대비 지수·로그 · 2학기 중간 보충 · 유형별 집중 …
    └─ 시중 교재에서 뽑아 내가 짠 것. 원본 출처가 문항마다 남는다.
```

`problem_bank_books.source_kind` 에 `'composed'` 를 더해 가른다(지금은 `pdf_text · pdf_scan · hwpx`). 교재 목록·오답관리·시험지 제작의 교재 고르개가 모두 이 두 묶음으로 나뉘어 보인다. 폴더(`folder_path`)는 지금처럼 각 묶음 **안에서** 쓴다.

갈라야 하는 이유는 화면 정리가 아니라 **다루는 법이 다르기 때문**이다. 시중 교재는 패키지를 통째로 다시 등록해 고치고, 자체 교재는 초안을 고쳐 다시 제작해 고친다.

## 2. 초안과 제작본 — 고치는 길은 늘 초안이다

```
   초안(collection)                      자체 교재(problem_bank_books · composed)
   ────────────────                      ────────────────────────────────────────
   담기·빼기·순서·교체 자유        ──제작──▶  번호 1,2,3… 으로 새로 조판된 교재
   저장은 몇 번이든                           오답관리·시험지·숫자변형 전부 통한다
   미리보기로 쪽 수 확인                      학생에게 주고 기록을 쌓는다
         ▲                                            │
         └──────────── 고쳐서 다시 제작 ────────────────┘
```

**제작본을 직접 고치지 않는다. 초안을 고쳐 다시 제작하면 그 교재가 갱신된다.** 위치를 바꾸거나 문항을 교체하는 일이 전부 초안에서 일어난다 — 「중간 중간 문항을 수정한다」가 이 길이다. 제작본을 직접 편집하게 두면 초안과 제작본이 서로 다른 원천이 되어 어느 쪽이 맞는지 알 수 없게 된다.

**다시 제작해도 학생 기록은 살아 있다.** 제작본의 `item_id` 를 **자리(position)가 아니라 원본 문항**에서 짓는다.

```
  item_id = <자체교재 book_id>-<원본 item_id>
```

그래서 문항을 **위로 옮겨도** 번호만 바뀌고 id 는 그대로다 — 그 문항의 오답 기록이 유지된다. 문항을 **빼면** 그 id 가 사라지고 기록도 함께 지워지므로, 뺄 때 알린다: 「빼는 문항 3개에 학생 기록 12건이 있습니다.」

## 3. 문항 이미지는 복사하지 않고 새로 조판한다

번호를 다시 매기기로 했으므로 이미지를 **복사할 수 없다** — 번호가 이미지 안에 찍혀 있다(`\setcounter{dmproblemcount}` 로 조판 시점에 박힌다). 19번을 그대로 복사하면 자체 교재 3번 자리에 19가 찍힌 그림이 선다.

등록된 34권 **전부**에 라텍스 전사본이 있어 다시 조판할 수 있다.

```
  29,634 문항 전사 완료 · 34권
  베이직쎈 대수 1689 · 베이직쎈 공통수학1 1570 · 라이트쎈 공통수학1 1414 · RPM 공통수학1 1184 …
```

제작할 때 고른 문항의 전사본을 모아 임시 책으로 펴고 `build.mjs` 를 돌린다. id 를 `0001 · 0002 …` 로 주면(`id_style: "number"`) **build.mjs 수정 없이** 1, 2, 3… 으로 찍힌다. 출처 배지만 원본을 가리키도록 문항별 덮어쓰기(`source_badge`)를 더하면 된다 — 지금은 책 제목에서 만든다.

```
  ┌────────────────────────────────────┐
  │                  쎈B 대수 10쪽 19번 │  ← 출처는 원본. 문항별로 덮어쓴다
  │  3.  (4^-3 + 2^-4)/5 × 4/(3^7+9^3) │  ← 번호는 자체 교재의 새 번호
  │      ① 6^-7  ② 6^-6  ③ 6^-5 …      │
  └────────────────────────────────────┘
```

덤으로 따라오는 것: 자체 교재의 모든 문항이 **같은 조판 설정**으로 나온다. 지금은 교재마다 전사 시점이 달라 섞어 인쇄하면 글꼴 크기·여백이 조금씩 다르다.

### 제작은 로컬에서 돈다 — 이것은 알고 시작해야 한다

조판에는 XeLaTeX 이 필요하고 Render 서버에는 없다. 그래서 화면의 「제작」은 **제작 요청을 남기는 것**이고, 실제 조판·등록은 지금 교재를 등록하는 것과 같은 길(로컬 스크립트 → 패키지 → 업로드)로 돈다.

```
  화면: [제작 요청]  →  상태 「제작 대기」
  로컬: node scripts/latex-bank/build-collection.mjs --collection <id>
          서버에서 초안을 읽는다 → 전사본을 모아 임시 책 → build.mjs → 패키지
        node scripts/problem-bank/upload-package.mjs ...
  화면: 상태 「제작 완료 · 교재 보기 →」
```

사용자가 git·터미널을 직접 다루지 않으므로 이 단계는 AI 가 수행한다. 지금 34권이 등록된 방식과 똑같다. 100문항 기준 조판 2~4분.

## 제작 설정 — 출처 표기 등은 「제작 전에」 정한다

자체 교재의 **출처는 이미지 안에 박힌다.** 조판할 때 문항 위 오른쪽에 배지로 들어가기 때문이다
(`renderItemBody` 가 `\dmkichul{...}` 로 넣는다). 그래서 오답지의 출처 토글처럼 인쇄 직전에 켜고 끌 수 없고,
**제작 설정**으로 미리 정해야 한다. 바꾸려면 다시 제작한다(조판이 다시 돈다).

초안에 설정을 들고 있는다(`problem_bank_collections.print_settings jsonb`).

```
┌─ 제작 설정 ────────────────────────────────────────────────┐
│  출처 표기    ○ 안 함                                      │
│               ○ 교재 이름만            쎈B 대수             │
│               ● 교재·쪽·번호 (기본)    쎈B 대수 10쪽 19번   │
│                                                            │
│  구획 머리줄  ☑ 유형 이름 보이기    유형 05 지수가 정수인…  │
│  숫자변형     ☑ 있으면 원본 옆에 같이                       │
│  빠른정답     ☑ 맨 뒤에 모아서                              │
│  해설         ☐ 넣지 않음                                   │
│  표지·목차    ☑ 넣기                                        │
└────────────────────────────────────────────────────────────┘
```

| 설정 | 기본 | 왜 |
| --- | --- | --- |
| **출처 표기** | 교재·쪽·번호 | 안 하면 학생이 원본을 찾아 답을 베낄 수 없다. 하면 교사가 원본을 되짚을 수 있다. **시험·평가용은 끄고 보충 교재는 켜는** 쪽이 보통이라 셋 중 고른다 |
| 구획 머리줄 유형 이름 | 켬 | 교재의 구획을 그대로 가져왔을 때 이름이 있어야 무슨 유형인지 안다 |
| 숫자변형 | 켬 | 변형이 있는 문항만 짝으로 선다. 없으면 아무 일도 없다 |
| 빠른정답 | 켬(맨 뒤) | 학생 자가 채점용 |
| 해설 | 끔 | 해설까지 넣으면 쪽 수가 두 배가 된다. 교사용으로 따로 뽑는 쪽이 낫다 |
| 표지·목차 | 켬 | 「교재」 모양을 만드는 것이 자체 교재의 목적이다 |

출처를 끄더라도 **서버에는 원본 연결이 남는다**(`item_id` 가 원본에서 만들어진다). 종이에 안 보일 뿐
교사 화면에서는 늘 「이 문항은 쎈B 대수 19번」을 볼 수 있다. 출처를 끄는 것과 출처를 잃는 것은 다르다.

인쇄지(미리보기·오답지)의 출처 토글은 지금처럼 따로 남는다 — 그쪽은 화면에서 얹는 글이라 언제든 켜고 끈다.

## 데이터 모델

새 표 3개 + 기존 CHECK 한 줄.

```sql
problem_bank_collections          -- 자체 교재의 초안
  collection_id text primary key
  tenant_id, title, folder_path, subject, grade
  status text          -- draft | requested | published
  print_settings jsonb -- 출처 표기·유형 이름·숫자변형·빠른정답·해설·표지 (위 「제작 설정」)
  published_book_id text   -- 제작으로 만들어진 자체 교재(problem_bank_books)
  published_at timestamptz
  note text
  created_at, updated_at

problem_bank_collection_sections  -- 구획(= 단원)
  section_id text primary key
  collection_id → collections (on delete cascade)
  position integer
  title text, note text

problem_bank_collection_items     -- 구획 안의 문항(원본 참조)
  entry_id text primary key
  collection_id → collections (on delete cascade)
  section_id    → sections     (on delete cascade)
  position integer
  item_id       → problem_bank_items (on delete cascade)
  include_variants boolean default false
  note text
  unique (collection_id, item_id)

-- 기존 표의 유일한 변경
alter table problem_bank_books drop constraint …_source_kind_check;
alter table problem_bank_books add constraint …_source_kind_check
  check (source_kind in ('pdf_text','pdf_scan','hwpx','composed'));
```

```
GET    /api/problem-bank/collections         초안 목록
GET    /api/problem-bank/collection?id=…     한 권(구획 + 문항 + 원본 문항 정보)
POST   /api/problem-bank/collection          중간저장(통째 저장)
POST   /api/problem-bank/collection/request  제작 요청(상태만 바꾼다)
DELETE /api/problem-bank/collection          삭제
```

중간저장은 **통째 저장(replace)**. 순서를 끌어 옮기는 화면이라 부분 저장은 어긋나기 쉽다. `AGENTS.md` 의 `local draft → 명시적 저장 → API 성공 → 재조회 대조` 를 따른다.

## 화면

교재관리에 탭을 하나 더한다. 왼쪽은 **오답관리의 교재 탐색 화면을 그대로 재사용**한다.

```
┌─ 교재관리 ─────────────────────────────────────────────────────────────────┐
│  [시중 교재] [자체 교재] [편집 중]                                          │
├──────────────────┬─────────────────────┬──────────────────────────────────┤
│ ① 고르기          │ ② 담은 것            │ ③ 짜기  내신대비 지수·로그  초안  │
│                  │                     │                                  │
│ 교재  [쎈B 대수▾] │  담음 18문항         │  ▾ 1. 지수법칙 기본      8문항 ⠿  │
│ ───────────────  │  쎈B 대수      12    │     1  쎈B 10-19     ⠿ [교체][×] │
│ ▾ 01 지수   0/58 │  RPM 대수       6    │     2  쎈B 10-20     ⠿ [교체][×] │
│   유형05 정수식  │                     │     + 숫자변형 함께      ☑       │
│    19 20 21 22   │  [구획으로 넣기]     │  ▾ 2. 로그의 성질       6문항 ⠿  │
│    ■ ■ □ □       │  [비우기]           │     9  RPM 0312      ⠿ [교체][×] │
│   유형06 실수식  │                     │  [+ 구획 추가]                   │
│    23 24 25      │                     │  ─────────────────────────────   │
│ ▾ 02 로그   0/61 │                     │  14문항 · 2구획 · 저장 14:32     │
│                  │                     │  [중간저장] [미리보기] [제작 요청]│
└──────────────────┴─────────────────────┴──────────────────────────────────┘
```

- **②→③** 담은 것을 **구획으로 떨군다**. 기본 구획 제목은 고른 구획 이름 그대로(`01 지수 · 유형 05`).
- **③ 안에서** 문항을 끌어 옮기고(`⠿`), 빼고(`×`), **교체**한다 — 교체는 ① 에서 고른 다른 문항으로 그 자리를 바꾼다.
- 번호는 ③ 에 **지금 자리의 번호**(1, 2, 3…)로 보이고, 오른쪽에 원본(`쎈B 10-19`)이 붙는다.
- **미리보기**는 지금 인쇄지를 그대로 연다 — 쪽 수와 생김새를 보고 다시 고친다. 이게 피드백 왕복의 실제 모습이다.
- 제작한 교재를 다시 고칠 때는 「편집 중」 탭의 같은 초안을 열어 고치고 다시 제작 요청한다.

### 구획을 만드는 세 가지 길

| 길 | 쓰임 | 구현 |
| --- | --- | --- |
| **교재 구획 그대로** (기본) | 한 교재의 유형 몇 개를 뽑아 보충 교재 | 이미 있는 `groupItemsByTypeSection` 결과 |
| **유형으로 모으기** | 여러 교재의 같은 유형을 한 구획에 | `type_label` 로 묶는다. 모든 문항에 이미 있다 |
| **직접** | 난이도순·수업 순서 | 빈 구획 만들고 끌어 넣기 |

「유형으로 모으기」는 교재마다 유형 이름이 달라 다 묶이지는 않는다. **같은 이름만 자동으로 묶고 나머지는 사람이 합친다** — 비슷한 이름을 AI 로 묶는 것은 하지 않는다(틀리게 묶이면 조용히 엉뚱한 문항이 섞인다).

## 아직 결정하지 않은 것

1. **같은 문항이 두 교재에 있을 때**(쎈과 RPM 의 고전 문항) 자동으로 걸러낼까 — 제안: **1단계에서는 안 한다.** 이미지·본문 비교가 싸지 않고, 틀리게 걸러내면 문항이 조용히 사라진다. 4단계에서 「유형·답이 같은 문항」만 노란 표시로 알리고 막지는 않는다.
2. **한 권의 상한** — 제안: **300문항.** 넘으면 막지 말고 「미리보기가 느리고 조판이 10분 넘을 수 있습니다」로 알린다.
3. **자체 교재에 답지·해설을 붙일까** — 원본의 빠른정답·해설 이미지는 그대로 쓸 수 있다(번호가 안 찍혀 있다). 제안: **붙인다.** 추가 비용이 거의 없다.

## 안 하는 것

- **문항 본문을 자체 교재 안에서 고치는 기능.** 원본을 고치는 길(전사본 → 재조판 → 재등록)과 둘로 갈라지면 어느 쪽이 원천인지 알 수 없게 된다. 고쳐야 하면 원본 전사본을 고치고 다시 제작한다.
- **AI 가 문항을 골라 주는 기능.** 고르는 것은 사람이 한다. AI 는 숫자변형처럼 사람이 확정하는 초안까지만 만든다.

## 확정된 결정

| | |
| --- | --- |
| 시중 교재 / 자체 교재 | **등록 단계에서 가른다**(`source_kind = 'composed'`). 배지로만 구분하지 않는다 |
| 번호 | **자체 교재 안에서 1부터 다시 매긴다.** 출처 배지에 원본이 남는다 |
| 제작본 수정 | **초안을 고쳐 다시 제작한다.** 문항 이동·교체·삭제가 전부 초안에서 일어난다 |
| 문항 이미지 | **복사하지 않고 새 번호로 다시 조판한다**(34권 전부 전사본 있음) |
