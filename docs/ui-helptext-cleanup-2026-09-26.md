# 화면 상시 설명 문구 정리 · 2026-09-25~26

사용자 요청: "화면에 설명글이 너무 많다. 어떤 건 너무 당연해서 지워야 하고, 어떤 건 가끔 필요해서 읽어야 하는데 늘 떠 있어서 정리가 안 된다. 버튼·컴포넌트 옆에 물음표 같은 작은 표시를 두고 커서를 올리면 설명이 나오는 구조로 만들고 싶다."

원칙은 `docs/ui-principles.md` §9, 화면 구조 감사는 `docs/ui-audit-2026-09-19.md`.

## 조사

`src/**/*.{jsx,js}` 전체에서 화면에 **항상 렌더되는 한국어 문장형 설명**을 스캔해 **275건 / 10,728자**를 확정했다(버튼·라벨·aria-label, placeholder, 확인 대화상자 문구, 저장·발송 결과 같은 동적 메시지, 알림톡 발송 본문은 제외). 패턴은 안내 박스 112 · 본문 문단 41 · 작은 캡션 62 · 모달 subtitle 35 · 페이지·섹션 헤더 22 · 기타 7. 화면별로는 시험분석 48 · 수업일지 38 · 학생관리 36 · 보충관리 21 · 특강 18 순이었다.

## 남긴 기준 — 판단 규칙

제안이 '툴팁' 이어도 다음은 상시 노출을 유지한다. 단위마다 이 규칙을 지침에 넣었고, 실제로 유지 판정이 대상의 60%를 넘었다.

1. **빈 상태 안내** — "표시할 운영 알림이 없습니다", "조건에 맞는 학생이 없습니다". 숨기면 화면이 비어 보이기만 한다.
2. **진행 상태** — "…확인하고 있습니다", Suspense fallback.
3. **실행 직전 경고·부작용 고지** — "보존된 출결은 출결 통계·결석보강 후보에서 제외됩니다"(휴강 전환), "저장 후 미래 정규수업 명단·출결 매칭·지각 판정에 반영됩니다"(개별 스케줄), 정산 계산 기준 11건, 발송·예약이 나가는지 여부.
4. **확인 모달의 부제** — "이렇게 하면 무슨 일이 생긴다" 를 말하는 유일한 자리.
5. **필수 입력·형식 안내** — "폴더에 문항·정답·해설이 함께 있어야 합니다", 워터마크 전제.
6. **값이 들어간 동적 문구** — "7일 초과 미래 결석 N건은 접어두었습니다" 처럼 숫자가 정보인 것은 정적 설명만 분리해 물음표로 보낸다.
7. **오류·복구 안내** — 로그인 실패, `AppErrorBoundary`.
8. 그 자리 CSS·구조 때문에 물음표를 붙일 수 없는 곳 — `<label>`/`<button>` 안(접근 가능한 이름이 깨진다), `display:none` 헤더, 아이콘 레일에서 숨는 라벨, 인쇄 PDF 출력물, 이미 접기 토글 뒤에 있는 것.

삭제는 "제목·버튼 문구를 되풀이해 정보가 0인 것" 에만 적용했고, 지운 문장에 제목에 없는 조각(열거·조건·범위)이 섞여 있으면 그 조각만 물음표로 남겼다.

## 공용 컴포넌트

`src/shared/components/HelpTip.jsx` + `HelpTip.css`

- `<HelpTip label="<대상 이름>" text="<설명>" />`. `label` 은 필수이며 `aria-label="<대상> 설명"` 이 된다("도움말" 같은 뭉뚱그린 라벨 금지).
- hover · 키보드 focus · 터치 클릭 모두로 열리고, Esc · 바깥 클릭 · 포커스 이탈로 닫힌다. 클릭으로 열면 고정된다.
- `role="tooltip"` + `aria-describedby`. 닫혀도 DOM 에 남으므로 스크린리더는 트리거에 닿는 순간 설명을 읽는다.
- 말풍선은 `position: fixed` 로 떠서 `overflow: clip|hidden|auto|scroll` 조상을 벗어난다(#417). 열릴 때 트리거 rect 를 재 좌우를 뷰포트 안으로 당기고, 아래 공간이 모자라면 위로 뒤집고, 열려 있는 동안 scroll·resize 에 재계산한다.
- 표시/숨김은 `display` 가 아니라 `visibility` 이고 규칙은 `.helpTip > …`(0,2,0) 이다. **화면 CSS 에서 `.helpTipBubble` 로 열림/닫힘을 흉내내지 마라** — 닫힘이 영영 열리지 않는다. 눌리면 화면 쪽 포괄 규칙을 좁히는 것이 정답이다.
- `Modal`·`PageHeader`·`SectionHeader` 는 `titleAdornment` prop 으로 받는다. `Modal` 은 열린 말풍선이 있으면 Esc 를 양보한다.
- 640px 이하 전역 `min-height: 44px !important` 를 되돌려 트리거는 24×24 를 유지하고, 히트 영역은 `::before` 가 44px 로 따로 보장한다.

## 검증

단위마다: 관련 단위 스크립트 · `scenario-tests-production.cjs` 829/829 · `check:fast` · `test:production` 469/469 · 관련 Playwright(`--workers=1`) · dev:safe 스크린샷(1440·390, 툴팁 열린 상태). GitHub Production checks 9 PR 전부 통과.

마지막에 **전체 회귀 점검**을 돌렸다 — 사이드바 18개 화면을 1440·390 두 폭에서 훑어 물음표를 하나씩 열고, 말풍선 안쪽 10px inset 9지점을 `document.elementFromPoint` 로 찍어 전부 말풍선 자신을 집는지 확인했다(모서리 2px 는 `border-radius` 때문에 오탐이 난다). 결과: **잘림 0 · 트리거 24×24 유지 · 뷰포트 이탈 0 · pageerror 0**, 앞 단위가 심은 물음표가 어느 화면에서도 사라지지 않았다. `origin/main` 기준선과 대조해 델타가 h7 추가분에서만 +인 것도 확인했다.

브라우저 테스트도 보강했다: `tests/browser/help-tip.spec.js` 에 focus·클릭·Esc 흐름, 클리핑 조상 밖 렌더, 위로 뒤집기, 스크롤 추적, 390px 을 넣었고, `scripts/test-help-tip.mjs` 는 CSS 를 선택자 단위로 파싱해 `position: fixed`·직접 자식 스코프·`display` 비의존을 잠근다.

## 남은 것

- **오답관리 390px 가로 넘침** — `.problemBankMetrics` 고정 154px 5열과 776px 번호 그리드 때문에 문서 폭이 822px 이 된다. `origin/main` 에서도 동일하게 재현되는 기존 문제이고 이번 diff 와 무관함을 확인했다(페이지에서 `.helpTip` 을 모두 제거해도 동일). 별건으로 고친다.
- **시험분석 산출물 패널의 도움말 방식 이원화** — `작성 도움말 보기` 토글(`data-help`, 기본 꺼짐)이 입력칸 안내 14건을 켜고 끄는데, 이번에 추가한 물음표는 그 토글의 영향을 받지 않는다. 한 화면에 방식이 두 개다. 토글을 없애고 14건을 물음표로 통일하거나 반대로 물음표를 `data-help` 에 연동해야 한다.
- **학사일정 일정 수정 모드 물음표의 브라우저 커버리지** — 등록 모드만 라이브로 확인했다. 수정 모드는 시험기간 카드에서만 열려 fixture 준비가 필요하다.
- **색 토큰 위반 baseline**(`test-ui-color-token-hygiene.cjs`)은 `main` 에서도 실패하는 기존 부채다. 이번 작업은 새 위반을 더하지 않았다.
- 학생·학부모 포털은 dev:safe 에서 실계정 로그인이 안 된다(`safe-local-api.mjs` 의 `/api/auth/login` 이 role 과 무관하게 교사 계정만 돌려준다). 학생 포털은 교사 화면의 미리보기 모달로 확인했다.
