## 준비

1. UI-9E에서 최신 `origin/main`이 Production에 반영됐다는 확인 뒤 시작한다.
2. desktop `1440px` 브라우저와 iPhone Safari `390px` 또는 실제 기기 폭을 준비한다.
3. desktop은 기존 교사 자동 로그인, 모바일은 로그인 화면부터 확인한다.
4. 화면명·기기·동작·문제 설명·스크린샷을 한 메모에 계속 추가한다.

홈 화면 바로가기는 같은 Production URL을 사용하므로 정상 접속되면 다시 만들 필요가 없다. Safari는 정상인데 기존 바로가기만 과거 빈 화면을 유지할 때에만 기존 바로가기를 지우고 Safari 공유 메뉴의 `홈 화면에 추가`로 다시 만든다.

## 통과·실패 판정

아래 다섯 조건을 모두 만족하면 일괄 시각 검수 통과다.

1. 어떤 화면도 페이지 전체의 가로 스크롤을 만들지 않는다.
2. modal의 제목·닫기와 필요한 하단 action이 화면 밖으로 사라지지 않는다.
3. 탭·필터·선택·focus 상태가 색상 외 문구·윤곽으로도 구분된다.
4. 긴 학생명·본문·파일명·provider 참조가 카드나 지정 scroll 영역 밖으로 침범하지 않는다.
5. desktop 동작을 모바일 한 열에서도 같은 의미로 찾을 수 있다.

실패 시에는 `화면명 / desktop·mobile / 직전 동작 / 기대 결과 / 실제 결과 / 스크린샷`만 남긴다. 여러 실패를 모아서 한 번에 전달해도 된다.
