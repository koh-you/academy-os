# Academy OS 요청 분류·배포 정책

업데이트: 2026-08-01

모든 요청은 구현 전에 아래 5가지 중 하나로 분류한다. 먼저 사용자에게 `분류 / 이유 / 이번 작업의 종료 지점`을 짧게 알리고 실행한다. 사용자의 최신 명시적 지시가 이 기본 정책보다 우선한다.

## 판단 순서

1. 현재 배포를 즉시 되돌려야 하는가? 그러면 **5. 긴급 롤백**이다.
2. 운영 SQL·데이터 쓰기/삭제/대량 변경, 실제 알림 발송·예약·취소, 유료 AI 호출, 계정 로그인·권한·관리자 승인, 파괴적 인프라 변경이 필요한가? 그러면 **4. 사람 Gate**다.
3. 운영 사용을 막거나 저장·표시·산출물을 잘못 만들거나, 보안·데이터 무결성을 해치거나, 이미 되던 기능이 깨졌는가? 그러면 **1. 운영 긴급 버그**다.
4. 사용자에게 보이는 버그이지만 안전한 우회 방법이 있는가? 그러면 **2. 일반 버그**다.
5. 그 밖의 기능 추가, UI 개선, 성능 개선, 리팩터링, 테스트·문서·inventory, 읽기 전용 조사는 **3. 기능·개선**이다.

긴급성과 사람 Gate가 함께 있으면 4번으로 분류하되 운영 긴급도도 함께 기록한다. 실제 side effect 전까지 가능한 수정·검증·배포 준비는 끝내고 정확한 사람 행동만 남긴다.

## 1. 운영 긴급 버그

예: 수업일지 저장 불가, 과거 기록 오연동, 출결·알림 대상 오류, 운영 화면 진입 불가, 데이터 손상 위험이 있는 회귀.

1. 원천 데이터와 저장·표시 경계를 읽기 전용으로 분석한다.
2. 가장 작은 수정과 회귀 테스트를 만든다.
3. 로컬 검사, commit, branch push를 완료한다.
4. 해당 commit의 GitHub 검사가 통과한 것을 확인한다.
5. 사람 Gate가 없으면 main에 통합하고 main 검사를 기다린다.
6. 배포된 commit을 대조한 뒤 집중 browser/API 운영 smoke를 읽기 전용 또는 안전한 범위로 수행한다.

자동 작업이 main까지 진행할 때는 작업 시작 시 확인한 `origin/main`이 그대로인지 다시 확인하고, 정확한 branch HEAD의 원격 검사가 모두 통과했으며 fast-forward push가 가능한 경우에만 `HEAD:main`을 push한다. main이 바뀌었거나 동시 통합 owner가 있거나 충돌이 나면 중단한다. force push는 금지한다.

main 검사나 운영 smoke가 실패하면 5번 긴급 롤백으로 전환한다.

## 2. 일반 버그

예: 일부 UI 오류, 불편하지만 안전한 우회가 있는 문제, 특정 비핵심 조건의 표시 문제.

작은 수정, 관련 로컬 검사, commit, branch push, 정확한 commit의 GitHub 검사까지 완료한다. 통과한 branch는 당일 또는 별도로 정한 일일 통합 시간에 main으로 묶어 배포한다. 사용자가 즉시 main 통합을 명시하면 바로 진행한다.

## 3. 기능·개선

예: 새 기능, UX 개선, 성능·구조 개선, 테스트 보강, 문서·규칙 변경, 안전한 inventory.

변경이 있으면 작은 단위로 구현하고 위험도에 맞는 로컬 검사, commit, branch push, GitHub 검사까지 완료한 뒤 일일 main 통합 대기로 둔다. 읽기 전용 조사·설명 요청은 결과만 보고하고 commit이나 push를 만들지 않는다. 사용자가 즉시 main 통합을 명시하면 따른다.

## 4. 사람 Gate

코드, SQL 파일, 영향 범위, dry-run·fixture·정적검사, 실행·복구 체크리스트 등 안전한 준비를 먼저 완료한다. 실제 운영 side effect 직전에서 멈추고 다음 세 가지를 남긴다.

- 사람이 해야 할 최소 행동
- 대상과 예상 영향
- 완료 후 Codex가 재개할 정확한 검사·배포 단계

Gate가 필요한 side effect를 승인 없이 실행하거나, Gate를 피하려고 동작 범위를 바꾸지 않는다.

## 5. 긴급 롤백

현재 배포가 운영을 깨뜨렸고 안전한 즉시 수정이 불확실할 때 적용한다. 문제를 만든 가장 작은 commit을 revert하고 핵심 검사만 우선 실행한 뒤 main push, main 검사, 배포 commit 대조, 집중 운영 smoke까지 완료한다. 원인 수정은 별도 branch의 후속 작업으로 분리한다.

## 공통 완료 기준

- 모든 코드 변경은 `npm run lint:runtime`, 관련 전용 테스트, `npm run build`를 통과한다.
- 운영 저장·출결·알림·시험·보충 흐름은 `npm run test:production`과 필요한 안전 browser smoke를 추가한다.
- GitHub 검사가 실패한 commit은 main에 넣지 않는다.
- main push만으로 배포 완료라고 하지 않는다. main GitHub Actions, 실제 배포 commit, 위험도에 맞는 운영 확인이 모두 끝나야 한다.
- 분류가 작업 도중 바뀌면 즉시 새 분류와 종료 지점을 알리고 그 규칙으로 전환한다.

## 오전 9시 자동 작업의 실행 조건

현재 Academy OS 자동화는 로컬 clone을 사용하는 Codex 데스크톱 예약 작업이다. 예약 시각에 컴퓨터가 켜져 있고 Codex 데스크톱 앱이 실행 중이어야 한다. 완전히 종료된 컴퓨터에서는 실행을 보장할 수 없으며, 재부팅 후 누락 실행을 자동 보장하는 규칙도 두지 않는다.

일반 자동 개발은 3번으로 시작한다. 작업 중 운영 긴급 버그가 명확히 확인된 경우에만 1번으로 바꾸며, 위의 main 안전 조건과 사람 Gate 제한을 모두 지킨다.
