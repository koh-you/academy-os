## 막는 것 하나 — 서버에 본문이 없다

```
서버(DB)   번호 · 쪽 · 유형 · 태그 · 답 · 이미지 경로
전사본      본문 LaTeX · 보기 · 그림 소스 · 풀이      ← 로컬에만
```

변형을 만들려면 원본의 **본문과 그림 소스**가 필요한데 서버에 없다. 그래서 1단계가 선행이다.

## 단계

### 1단계 — 전사본을 서버에 올린다 (선행 · 중)

패키지 manifest 에 본문·보기·풀이·그림 소스를 넣고 DB 에 저장한다.

- `build.mjs` export 가 manifest item 에 `body` · `choices` · `figure_source` · `solution` 추가
- `problemBankStore` 가 새 칼럼에 저장 (SQL 마이그레이션 1개 · 사람 Gate)
- 34권 재등록 — **이미지는 md5 가 같아 0분대**(2026-10-04 실측: 1,000장 넘는 책도 0분)

변형 말고도 쓸모가 크다: 문항 **검색**, 자체 교재의 **중복 문항 경고**가 전부 여기서 나온다.

### 2단계 — 기준 데이터를 few-shot 으로 (소)

**사용자가 「좀 더 실험한 뒤에 등록하고 싶다」고 했다(2026-10-04). 바로 박지 말고 먼저 실험한다.**

지금 가진 것: 쎈B 대수 10문항. 공교롭게 모양 다섯 가지를 다 덮는다.

| 모양 | 문항 | 바꾼 방법 |
| --- | --- | --- |
| 계산형 | `10-19v1` `10-20v1` | 지수·분모를 바꿔 답이 떨어지게 |
| 참·거짓 판별형 | `7-01v1` | 참인 보기의 **위치**를 ③→② 로 |
| 집합 열거형 | `7-04v1` | 근호 차수를 홀수로 → 음수도 실근 (6→8) |
| 조건 합계형 | `7-06v1` | 이차식의 근을 옮겨 부호 전환점 이동 (31→30) |
| 구조 강제형 | `10-21v1` | 숫자로는 답이 안 변해 **항의 수**를 바꿈 (2→3) |

**실험할 것** — 이 예시들을 프롬프트에 넣었을 때 품질이 어떻게 달라지는지:

1. 예시 **없이** vs **1개** vs **5개(모양별)** 로 같은 문항 10개를 만들어 비교
2. `variation_note`(바꾼 이유)를 예시에 **포함할 때와 뺄 때**
3. 검산식을 **같이 내게 할 때와 따로 요구할 때** — 답 정확도 차이
4. 다른 교재(RPM·개념원리)에도 통하는지 — 쎈B 로만 맞춘 예시가 과적합인지

평가 기준: **답 정확도**(수치 검증 통과율), 답 번호가 바뀐 비율, 보기를 다시 만든 비율, 사람이 보고 「쓸 만한가」.

실험 결과가 나온 뒤에 `docs/number-variant-guide.md` 에 예시를 확정해 넣는다.

### 3단계 — 생성·검증 API (대)

```
POST /api/problem-bank/variant-draft   (원장 전용 · 유료)
  입력  itemId[]
  동작  전사본 + 기준 + 예시로 AI 호출
        → 변형 + 검산식 + 그림 TikZ(있으면)
        → 검산식을 샌드박스에서 실행(node:vm · 전역 없음 · 1초 제한)
        → 답이 안 맞으면 거부
  저장  review_status = "확인 필요" 로 전사 저장
```

**검산식을 같이 내게 하는 것이 핵심이다.** 2026-10-03 에 손으로 한 검증(원본과 변형의 답을 식으로 계산해 대조)을 기계가 하게 만든다. **원본도 함께 검증한다** — 원본을 잘못 이해하면 변형도 틀린다.

### 4단계 — 화면 (중)

- 오답관리·교재관리에서 문항을 고르고 **「숫자변형 만들기」**
- 만들어진 것은 **「확인 필요」 목록**에 — 선생님이 본문·답을 보고 확정
- 본문이 LaTeX 로 저장되므로 **브라우저에서 수식으로 바로 보여 준다**(이미지는 나중)

### 5단계 — 조판 대기분 모아 돌리기 (소)

확정된 변형을 모아 조판·등록한다. **자체 교재 제작(`build-collection.mjs`)과 거의 같은 구조**다.

## 그림

| 종류 | 비율(쎈B 대수) | 변형 |
| --- | --- | --- |
| 없음 | 85% | — |
| **TikZ** | 13% | **된다** — 소스가 텍스트라 좌표·라벨을 고친다. **컴파일 성공으로 1차 검증** |
| 스캔 크롭 | 1% | 안 된다 — 그림 안 숫자를 못 바꾼다. skip |

전체의 **99%가 변형 가능**하다. 다만 「좌표가 맞게 바뀌었는지」는 그려 봐야 알아서, **그림이 바뀐 변형은 반드시 확인 필요로 띄운다.**

## 정해야 할 것

1. **비용 상한** — 문항당 유료 호출 1회. 하루/월 상한을 둘까? (지금 답안지 판독 route 에는 상한이 없다 — 같은 자리)
2. **확정 없이도 쓸 수 있게 할까** — 검산을 통과하면 바로 쓸 수 있게 둘지, 반드시 사람 확정을 거칠지. 제품 규칙은 `AI 초안 → 사람이 편집·확정` 이다
3. **한 번에 몇 개** — 10개? 한 유형 전체? 비용과 대기 시간이 여기서 갈린다
