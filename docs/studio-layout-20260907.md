# 시험분석·SNS 스튜디오 공통 레이아웃 · 2026-09-07

## 변경 범위

프런트엔드 표현·선택 방식만 변경한 중위험 UI 작업이다. 원본 데이터, local draft, API/DB, 저장 revision, 사람 확정값, 권한, AI 실행 경계는 기존 소유자에 유지한다. 공유 컴포넌트 StudioWorkspace는 슬롯과 단계 선택 콜백만 받으며 데이터를 저장하지 않는다.

| 기존 기능/위치 | 변경 후 위치 |
| --- | --- |

## 조작 규칙

- 자료 목록은 두 화면 모두 같은 버튼으로 접고 연다. 준비 단계로 돌아오면 목록을 보여주고 편집 단계에서는 본문 폭을 확보한다.
- 필터를 바꾼 뒤 분석본 카드를 선택하는 기존 동작을 유지한다.
- 최종 미리보기의 차트·주요문항은 높이를 제한한 키보드 접근 가능한 영역에서 읽는다. 카드 제작은 긴 편집이므로 기존 본문을 그대로 사용한다.
- 미리보기 선택 전환은 표시만 변경한다. 카드 제작 입력·임시 메모·역할 펼침 상태를 유지한다.
- 공통 PageHeader / WorkspaceTabs / StudioWorkspace / StudioEditor / StudioDialog / StickySaveBar / Disclosure를 재사용한다. 저장 대상과 성공 판정은 도메인별 기존 계약을 유지한다.

## 제한

- 운영 PDF 업로드, 유료 AI 실행, 실제 플랫폼 게시·운영 DB 쓰기는 수행하지 않았다. 시험 원본 비교는 가상 PDF 링크 fixture다.
- 긴 카드 제작·SNS 자료 입력 자체는 긴 본문으로 남는다. 최종 미리보기의 여러 결과를 한꺼번에 이어 붙이던 구조를 제거한 것이며 전체 페이지 높이를 고정하지 않는다.
- 병합과 운영 배포는 아직 진행하지 않았다. 저장 API·DB migration 변경 없음.


## 후속: 넓은 화면 공간 활용

사용자가 보고 있던 Chrome의 2844×1038 화면을 직접 확인했다. 앱 메뉴 오른쪽에 1440px 작업 프레임이 중앙 정렬되어 큰 여백이 남았고, 시험 정보 아래에 PDF가 쌓였으며 SNS 콘텐츠가 0개일 때 본문은 비어 있었다.

공통 프레임의 최대 너비와 중복 바깥 padding을 없애 앱 본문 정렬선을 공유한다. 늘어난 공간은 다음처럼 역할별로 사용한다.

| 작업 | 넓은 본문(1100px 이상) | 좁은 본문 |
| --- | --- | --- |
| 시험 원본 준비 | 360~420px 기본정보 + 나머지 PDF 자료 | 기존 세로 순서 |
| SNS 자료 준비 | 기본자료 / 선생님 메모·이미지 자료·공개 확인 | 기본자료 다음 메모·공개 확인 |
| SNS Chat 전달 | 340px 안내·복사 / 전달 자료 미리보기 | 안내 다음 전달 자료 |
| 완성본 편집 | 기존 편집/미리보기 2열을 가용 폭에 맞게 확대. 미리보기 텍스트는 최대 72ch | 기존 편집/미리보기 전환 |
| SNS 빈 화면 | 3단계 시작 안내 + 첫 콘텐츠 만들기 | 안내 카드가 가용 폭에 맞춰 내려감 |

컨테이너의 실제 가용 폭으로 배치를 결정하므로 자료 목록을 열거나 닫아도 적절히 전환된다. 기존 입력/동의/복사/저장 이벤트 및 서버 재조회 로직은 그대로 사용한다. 화면 확인 중 운영 입력이나 저장은 하지 않았고, 사용자 탭은 원래 SNS 화면으로 돌려놓았다.

검증: tests/browser/studio-width.spec.js에서 2844·1920·1024·390 너비, 두 화면의 동일 폭, 부모 가용 폭 채움, 가로 넘침 없음, 시험 정보/PDF 및 SNS 자료/메모 병렬 배치, 편집·미리보기 동시 표시를 확인했다. SNS 3개 저장/실패 검사, 시험분석 2개 집중 검사, check:fast와 CSS hygiene 통과. 가상 화면 이미지는 로컬 worktrees/studio-width-evidence에 보관한다. 아직 운영 배포 전이다.
