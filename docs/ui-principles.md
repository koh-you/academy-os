# 공통 UI 원칙

업데이트: 2026-09-19 (전체 UI 구조 감사 · `docs/ui-audit-2026-09-19.md` 에서 도출)

버튼의 *종류*는 `docs/ui-button-hierarchy.md`, 반복 렌더(행·카드)의 액션 배치는 `docs/ui-row-actions.md` 가 정한다.
이 문서는 그 위에서 **화면·모달·폼·피드백·반응형**을 어떻게 짜는지에 대한 소수의 규칙이다. 새 화면을 만들거나
기존 화면을 고칠 때 이 12개만 지키면 된다. 학습 비용이 낮고 예측 가능한 구조가 독창적인 디자인보다 우선한다.

## 1. 페이지 헤더

- 사이드바에서 들어가는 1차 뷰는 공용 `PageHeader` 로 시작하고 `title` 은 **사이드바 라벨과 같은 글자**다(숙제현황·시험지관리처럼 제목이 없거나 다른 h1 을 쓰지 않는다).
- 영문 eyebrow(`SETTINGS`, `OPERATIONS` …)는 쓰지 않는다. 설명은 `description` 한 줄.
- 헤더 `actions` 에는 그 화면의 확정 액션(primary 1개)과 소수의 보조 액션만 둔다. 저장 상태 pill 은 헤더 우상단(수업일지처럼) 또는 저장 바에 둔다 — 둘 다 그리지 않는다.

## 2. primary 는 화면·모달당 1개

- `primaryButton` 은 화면(뷰) 또는 모달마다 정확히 1개. 반복 행·카드 안에는 primary 를 두지 않는다(`softButton compact`).
- 비활성 버튼은 렌더하지 않는다. 눌러도 아무 일도 없는 버튼(읽기 모드의 편집 버튼 등)도 렌더하지 않고, 필요한 이유는 문구로 적는다.
- 저장과 외부 발송·예약·AI 실행은 별개의 버튼이며, 발송 쪽이 primary 가 되지 않는다(출결 모달: `[취소][저장만 primary][저장 후 알림톡 발송 soft]`).

## 3. 버튼 순서

- 푸터·툴바 순서는 `[파괴적] … [ghost 부수] [soft 취소/닫기] [primary 확정]`. 파괴적 버튼은 **왼쪽 끝**(`margin-right:auto`) 또는 `OverflowMenu`(⋯, `tone="danger"`) 안.
- 인쇄·닫기 같은 보조 툴바도 같은 순서를 따른다(닫기 → 부수 → 확정).
- 같은 의미의 액션은 화면마다 같은 이름을 쓴다('수업 취소', '변경 저장', '취소'/'닫기').

## 4. 확인 단계

- 외부 발송·예약, 되돌리기 어려운 삭제, 다른 사람 자료를 바꾸는 행동은 반드시 **확인 대화상자**를 거친다. 공용 `ConfirmDialog`(`src/shared/components/ConfirmDialog.jsx`)를 쓴다: `[취소][확정]`, 파괴적이면 `tone="danger"`, 진행 중이면 `busy`.
- 확인은 진입점만 감싼다. 실제 저장·발송·삭제 함수와 인자는 그대로 호출한다.
- `window.confirm` 은 새로 쓰지 않는다. 남아 있는 것은 화면 단위에서 순차 교체한다(목록은 감사 보고서 §9).

## 5. 초안 보호

- 저장하지 않은 변경(dirty)이 있는 상태에서 닫기(×·Esc)·취소·다른 항목 선택·화면 이동은 확인을 거친다.
- 편집 모드에는 항상 **취소 출구**가 있다(수업일지 `[편집 취소]`).
- 저장 중에는 `Modal closeDisabled` 로 닫기를 막는다. `onClose={isSaving ? () => {} : onClose}` 같은 빈 함수 패턴은 쓰지 않는다.
- 사용자 입력은 초기값·템플릿·파생값·AI 초안이 덮어쓰지 않는다(`seed → local draft → persisted`).

## 6. 저장 방식과 피드백

- 한 화면 안에서 자동저장과 명시적 저장을 섞지 않는다. 섞여 있는 곳(오답관리 번호 그리드 즉시 저장 + 메모 명시 저장)은 어느 쪽인지 **문구로 표시**한다.
- 저장 상태 문구는 `InlineSaveStatus` 의 6종(`idle/dirty/saving/verifying/saved/failed`)만 쓴다. 버튼 라벨에 상태를 섞지 않는다('저장됨' 버튼 금지).
- 여러 행을 편집하는 표는 행별 저장 버튼 대신 `StickySaveBar` 하나(R2). 저장 실패 사유·부분 저장·변경 건수는 **행동한 그 표면**(모달이면 모달 안, 저장 바면 저장 바)에 보인다. 뒤에 가려진 화면에만 띄우지 않는다.
- 성공·실패·진행은 `AsyncOperationStatus`(state: loading/success/partial/error)로 그린다. 메시지 문자열에 '실패'가 있는지로 색을 정하지 않는다.

## 7. 모달·드로어·페이지 선택

- **모달**: 짧고 즉각적인 결정, 필드 몇 개의 편집. **별도 뷰**: 필드가 많거나 독립적인 작업. 단순 확인·상태 안내는 인라인 피드백.
- 모달 위 모달은 확인 대화상자까지만 허용한다. 편집 모달 위에 편집 모달을 쌓지 않는다(학생 프로필·수업일지의 기존 중첩은 보류 항목).
- 모달 푸터는 공용 `ModalFooter`. 닫기는 `onClose` 하나로 통일하고 dirty 가드는 그 앞에 둔다.

## 8. 목록 ↔ 상세

- 목록 행의 기본 행동은 '열기' 하나. 행 안의 버튼은 지금 누를 수 있는 것만(R1), 파괴적·저빈도는 ⋯(R3), 다중 처리는 `SelectionToolbar`(R5 — 선택이 있을 때만 표시).
- 검색·필터·정렬은 표 위 `FilterBar`/`SearchField` 한 줄. 상세에서 돌아오면 탭·필터·검색 상태가 유지된다.
- 빈 상태는 공용 `EmptyState`(상자 스타일은 컴포넌트가 소유). 로딩·오류도 같은 컴포넌트의 tone 으로.

## 9. 폼

- 섹션 제목 → 필드 → 도움말 순. 필수는 라벨의 `*`(aria-required), 오류는 필드 아래 `role="alert"`.
- 반복 입력(날짜 범위·시작/종료 시간·수학시험 회차 리피터)은 같은 필드 순서와 라벨을 쓴다. 리피터 행 제거는 `iconButton ×` + aria-label, 유일한 행이면 렌더하지 않는다(R4).
- 숫자 입력은 타이핑 중 클램프하지 않는다(로컬 draft → blur/Enter 에서 정규화).
- 가끔 필요한 설명은 상시 노출하지 않고 공용 `HelpTip`(`src/shared/components/HelpTip.jsx`) 뒤에 둔다. 설명하는 대상(제목·버튼·입력) 옆에 물음표를 두고 hover·focus·클릭으로 연다. 빈 상태 안내·실행 직전 경고·필수 입력 안내는 상시 노출을 유지한다.

## 10. 상태 배지

- 같은 의미에는 같은 색·같은 컴포넌트. '확인 필요/미체크' 계열은 `--status-pending`, 완료는 `--status-success`, 실패·위험은 `--status-danger`.
- 배지는 상태를 보여줄 뿐 버튼이 아니다. 버튼처럼 보이는 배지, 배지처럼 보이는 버튼('확인 완료' 토글)을 만들지 않는다.

## 11. 반응형

- 교사 화면은 데스크톱 우선이되 **641~1100px(iPad 가로)** 에서 사이드바는 아이콘 레일(86px, sticky), ‹ 토글로 오버레이 드로어. 640px 이하는 상단 메뉴 토글.
- 어떤 폭에서도 문서가 가로로 넘치지 않는다(`scrollWidth <= innerWidth`). 다열 그리드는 `minmax(0, 1fr)` + 폭 기준 접힘. 표·다이어그램만 자체 `overflow-x: auto`.
- 학생 화면(태블릿 우선)·학부모 화면(모바일 우선)의 터치 요소는 `--academy-touch-target`(44px) 이상.
- 시험분석·SNS 스튜디오는 데스크톱 기준이며 모바일 최적화를 완료 조건에 넣지 않는다.

## 12. CSS 위치와 잠금

- 새 CSS 는 `src/app/App.css` 가 아니라 도메인 css(`src/domains/<domain>/*.css`) 또는 공용 컴포넌트 css. App.css 에서는 삭제만 한다. 같은 셀렉터를 두 파일에 두지 않는다(`test-ui-css-hygiene`).
- 색은 `--academy-*` / `--status-*` 토큰만.
- 화면 문구·구조를 잠근 테스트(`scripts/scenario-tests-production.cjs`, `scripts/test-*.mjs`, `tests/browser/*.spec.js`)를 바꿀 때는 날짜와 이유를 주석으로 남긴다. 테스트는 사용자 동작과 저장 계약을 검증하고 버튼 위치·정확한 개수에는 결합하지 않는다.
