**Rule (v2 · 2026-07-16 세션 46 후반부 마스터 지시)**: `\criticalpoint{}` 함정 서술 4원칙 준수.

1. **`\cplabel{}`은 완성 문장** — 명사구·수식만·keyword 나열 절대 금지 · 서술어·종결어미 포함
2. **본문은 자연 국어** — "~한다·~이다·~된다·~여야 한다" 종결 · 구어체·압축 신조어 금지
3. **함정 명명은 학습자 사고 유도형** — 관찰·이유·조건·결과 표현
4. **🆕 짧고 굵게** — 각 함정 본문 1~2문장 이내 · 핵심 포인트만 · 장황 금지 (마스터 세션 46 후반 지시)

**v2 갱신**: v1 원칙 (완성 문장) + **짧고 굵게** 결합. 완성 문장 유지하되 부연·배경 최소화.

**Why (세션 46 DeeP-Red-2 답지 사건)**:

CP 3함정을 정점 3문 (#14·#16·#17) 답지에 작성한 결과, 마스터가 "문장들이 어색한데 왜 이렇게 적는건지" 지적.

**원인 분석**:
- `\cplabel{}` 매크로 자체를 "짧은 label" 인상으로 인식 → 압축 keyword 강박
- 오렌지 강조 시각 관례에 맞춰 keyword 스타일 시도
- solution-author agent 프롬프트가 자연 국어보다 압축 우선

**How to apply**:

### solution-author agent 프롬프트 강화
- `\cplabel{}` label 작성 원칙 명문화
- 예시 3종 (관찰 유도·조건 서술·결과 명제) 제공

### solution-review agent 검수 축 추가 (S8.4·S8.5 뒤)
- **S8.6 cplabel 완성 문장 검증** — 명사구·수식만·keyword 나열 발견 시 RED
- **S8.7 본문 자연 국어 종결 검증** — 종결어미 부재·구어체·압축 신조어 감지

### 자동 도구 신설 (선택)
`scripts/cplabel-completeness-check.mjs` (기존 `cplabel-style-check.mjs` 확장):
- label 안 마지막 문자가 종결어미 (~다·~는가·~한다·~이다) 인지 검사
- 수식만·명사구 종결 감지

### 원칙 요약 (Agent 재사용 문구)

**\cplabel{} 작성 규칙**:
1. 반드시 완성 문장 (~다/~한다/~이다/~여야 한다/~된다)
2. 명사구 나열 금지 ("A의 조건") → "A가 조건을 만족한다"
3. 수식만 label 금지 ("$k=12$의 모순") → "$k=12$일 때는 조건과 모순된다"
4. 압축 keyword 나열 금지 ("접점 조건은 수직") → "접점에서는 수직이다"

**CP 본문 작성 규칙 (v2 · 짧고 굵게)**:
1. 종결어미 완성 (~한다·~이다·~된다)
2. 구어체 지양 ("헤맨다·튀어나온다·척척")
3. 압축 신조어 지양 ("~로부터 즉시 배제·~로 옮기면")
4. 사고 유도 (관찰·이유·조건·결과를 자연 서술)
5. **🆕 각 함정 1~2문장 이내** — 부연 설명·배경 정보 최소화 · 핵심 포인트만
6. **🆕 장황 금지** — 문제 조건 재진술 회피 · CP는 핵심 통찰만 강조
