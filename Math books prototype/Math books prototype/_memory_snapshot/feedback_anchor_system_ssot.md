# 🔴🔴 앵커 시스템 — 착수 전 두 가지가 의무다

> **마스터 요구 (2026-08-01)**: 「지금 완성하는 시스템은 **다시는 기복이 없어야** 해.
> 최종본으로 남겨서 **어떤 세션에서도 동일하게 작동**해야 해.」

## 착수 전 (예외 없음)

1. **정독**: `bank/앵커시스템-SSOT-v1.md` — 앵커·난이도 판정의 단일 진입점.
   다른 문서와 값이 어긋나면 **SSOT 가 이긴다**
2. **검사**: `node scripts/anchor-system-check.mjs` → 🔴 **RED 0 이어야 착수**

배선: `CLAUDE.md` §난이도 체계 최상단

## Why — 문서만으로는 실패한다는 것이 실증됐다

세션 107 에서 이런 일이 실제로 일어났다:
- 사다리 **한 파일이 「18문」·「A5 5문」·「계 19문」 세 값**을 동시에 말함
- `MEMORY.md` 는 CM2 20문, 실물은 19문
- 🔴 **폐기된 「문번→밴드 정답표」가 규약 파일에 표시 없이 살아남아 되살아남** —
  메모리에는 「문번은 깊이 신호가 아니다」가 있었는데도 조사하니 옛 표가 먼저 잡혔다
- 관측값(잡음비 0.042)이 **통과선으로 승격**돼 기준 행세
- 시판 앵커가 학평 앵커와 **같은 문항인 채로 두 밴드를 겸함**

이미 등재된 [[feedback_document_only_rule_gap]]·[[feedback_ssot_routing_gap]] 의 재발이다.
**그래서 이번엔 기계가 검사한다.**

## 검사기가 잡는 것

| 코드 | 무엇 |
|---|---|
| `L1`·`L2` | 사다리 실제 앵커 수 ≠ SSOT 선언값 (밴드별까지) |
| `L3` | 한 파일이 문항 수를 여러 값으로 선언 |
| `L4` | **같은 출처가 두 자리** — 한 문항이 두 밴드의 대표 |
| `L5` | 시판 앵커 출처에 **교재명 누락** |
| `D1`·`D2` | 폐기 규칙이 폐기 표시 없이 생존 · 관측값의 통과선 승격 |
| `M1`·`M2` | `MEMORY.md` 와 실물 불일치 |

🔴 **검사기 자신도 틀릴 수 있다.** 첫 실행에서 RED 8건 중 7건이 검사기 결함(사다리마다 표 형식이
달랐다)이었다. RED 가 뜨면 **실물과 검사기 중 무엇이 틀렸는지 먼저 판단**한다.

## 절대 규칙 4개 (상세는 SSOT)

- 🔴 **정답표는 사다리다.** 학평 문번으로 평가하지 않는다
- 🔴 **앵커 수를 그럴듯한 관찰로 바꾸지 마라** — 바꾸려면 **실험 결과를 인용**한다.
  현행 CM2 19 · CM1 21 **동결**
- 🔴 **시판 앵커는 3단 게이트 필수** — 시판이 학평 문항을 그대로 싣는 사례 **3건** 확인
- 🔴 **`tier_mapping`·`star_premium`·`premium_ratio` 를 등급 근거로 쓰지 마라**

## 변경 절차 (SSOT §5)

1. **실험 결과를 인용**한다 (관찰·직관 금지)
2. 통과선은 **관측 전 사전 등록** — 관측값을 통과선으로 승격하지 않는다
3. SSOT §2 표에 **근거·결정자·변경조건**을 함께 적는다
4. **폐기되는 옛 값은 폐기 표시와 함께 남긴다.** 지우면 다음 세션이 다시 발명한다
5. 검사기를 돌려 **RED 0** 확인
