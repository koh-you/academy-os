# 정답 표기 최종 값·표현만 (RED)

`\soltitle`의 정답 인자, quickgrid, answerbox 등 학생이 정답을 확인하는 zone에는 **최종 값·최종 표현만** 표기. 유도 과정을 설명하는 괄호 부연 금지.

## 원칙

정답 표기 = "값" 그 자체. 어떻게 그 값에 도달했는지는 풀이 본문에서 상세히 설명. 정답 zone에 유도 힌트를 넣으면 학생이 값과 유도 방식을 혼동하거나 값 확인이 지연됨.

## 잘못된 예 vs 좋은 예

| 상황 | 🔴 잘못 | ✅ 좋음 |
|---|---|---|
| $k$ 값들의 합 | `52 ($k = 4, 12, 36$의 합)` | `52` |
| 최댓값의 근거 | `10 (\overline{AB} 최대일 때)` | `10` |
| 개수 계산 근거 | `8개 (순서쌍 나열 결과)` | `8개` |
| 조건 부연 | `3개 (짝수 3개 존재)` | `3개` |
| 좌표 근거 | `(3, 4) (원 위 첫 사분면)` | `(3, 4)` |

**Why**: 
- 정답 zone은 학생이 자신의 답을 대조 확인하는 곳. 값 자체만 있어야 즉각 확인 가능
- 유도 설명은 이미 풀이 본문(자연어 서술 + 디스플레이 수식)에서 상세히 설명됨. 정답 zone에 반복 = 노이즈
- 풀이의 강조점은 "값이 왜 나왔는가"인데, 정답 zone이 유도를 미리 요약하면 풀이의 논리 흐름 약화

**How to apply**: `\soltitle`·`quickgrid`·`answerbox` 등 정답 zone 작성 시 괄호 부연 (`(... 의 합/곱/차/평균/이유)`, `(... 근거)`, `(... 위치)` 등) 자체 grep. 검출 시 즉시 제거.

## 예외

다음은 정답의 **일부**로 반드시 필요한 경우 (부연이 아니라 값의 구성 요소):

- 순서쌍 안의 콤마: `(3, 4)` ✅
- 값의 조건 표기: `x = ±5` ✅
- 여러 값 나열: `p = 15, q = 30` ✅
- 개수 표현: `3개` `2가지` ✅ (값의 단위)

부연이 값의 **의미 확인**이 아니라 **유도 방법 설명**인지가 기준.

## 자동 검출 어려움

정답 zone 안의 괄호가 유도 설명인지 값의 일부인지는 문맥에 따라 다름. 자동 grep으로 완전 검출 어려움. 다음 heuristic으로 후보 검출 가능:

```
정답 zone 내 다음 어구 등장 시 YELLOW:
- "의 합" "의 곱" "의 차" "의 평균" "의 최댓값" "의 최솟값"
- "이유" "근거" "때문" "이므로"
- "결과" "도출" "유도"
- "존재" "가능"
```

`scripts/permanent-policy-check.mjs`에 §1.4f로 등재 (soltitle 2nd arg 대상 grep).

## 배경 (2026-07-08 와부고 CM2 답지 사건)

soltitle 재설계 (출제의도 삭제 → 정답 인라인) 후, #13 정답이 "(1) p=15, (2) 8개, (3) 52 ($k=4,12,36$의 합)"으로 표기됨. 마스터가 "굳이 (k=...) 이런 설명은 필요없어. 이것도 지침"으로 지적하며 재발방지 요청.

풀이 본문 (line 246~249)에 이미 "$k = 4, 12, 36$이고 합은 $4 + 12 + 36 = 52$"라고 명시되어 있어 정답 zone의 괄호 부연은 정보 중복.
