**규칙 1 — 디스플레이 직후 짧은 한국어 텍스트 금지**: 디스플레이 수식 `\[...\]`/`$$...$$` 직후에 50자 미만의 짧은 한국어(예: "가 성립할 때", "의 값을 구하시오", "이 있다.")가 단독으로 오는 패턴 금지.

**규칙 2 — 인라인 수식 임계점 명확화**: 인라인 수식 `$...$`이 다음 중 하나면 디스플레이로 분리한다.
- 등호 + 이항연산자(+, -, ×, |..|, ÷ 등)의 합이 **2개 이상**
- 시각적 길이 12em 이상 (분수/제곱근/절댓값 포함 시 보수적으로 평가)
- 컬럼 폭 좁은 2단 레이아웃(B5 minipage 0.45·textwidth ≈ 70mm)에서는 인라인 + 한국어 + 인라인 누적 패턴도 위험

**규칙 3 — 본문 작성·수정 후 PDF 시각 점검 의무**: `Underfull badness ≥ 2000` 로그 검출만으로는 부족. badness < 2000인 미세 줄바꿈, 인라인 수식 중간 분리, 시각적 어색함은 로그가 잡지 못한다. **본문 수정 후 반드시 PDF를 시각으로 확인 (Read 도구의 PDF 페이지 비전 분석)**.

**Why** (반복 발생 4회 누적):
1. `style.sty`의 `\binoppenalty=10000`, `\relpenalty=10000`이 페널티만 부과할 뿐 컬럼 폭이 좁으면 결국 수식 중간에서 줄바꿈 발생.
2. badness가 낮은(< 1000) 줄바꿈은 LaTeX 로그에 보고되지 않아 자동 검출이 약함.
3. 검수 에이전트가 "임계점 근접"을 차단 처리하지 않고 "주의" 정도로만 분류한 사례 다수.
4. 본문 수정 후 PDF 시각 확인을 생략하고 빌드 로그만 신뢰한 사례 반복.

**How to apply**:
- 나쁜 예 (규칙 2 위반): `"함수 $f(x) = a\sin\dfrac{\pi x}{4} + b$ 가 있다. 집합 ..."`
- 좋은 예: `"다음 함수가 있다. \[ f(x) = a\sin\dfrac{\pi x}{4} + b \] 집합 ..."`
- 나쁜 예 (규칙 1 위반): `"부등식 $$...$$ 가 성립할 때, $a+b$를 구하시오."`
- 좋은 예: `"다음 부등식이 성립할 때, $a+b$를 구하시오. $$...$$"`
- 빌드 후 `_파일명.log`에서 `Underfull \hbox (badness [1-9][0-9]{3,})` (1000 이상으로 임계값 하향) 또는 `Overfull` 검출 시 본문 재구성.
- **추가 의무**: 검출 결과 0건이어도 PDF 페이지를 시각 확인. 의심 페이지는 Read 도구로 PDF 페이지 비전 분석. Explore 서브에이전트에 전 페이지 시각 점검 위임 가능.

**자동 점검**: `scripts/check-display-math.mjs`로 빌드 후 모든 TeX 출력 로그를 일괄 검사 + PDF 페이지별 시각 비교 (향후 모든 교재·시험지 작성에 적용).

**관련 메모리**: [[feedback-natural-korean-wording]] (자연스러운 한국어 흐름과 함께 검토).
