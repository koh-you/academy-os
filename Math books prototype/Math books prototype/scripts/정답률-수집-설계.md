# 정답률 수집 — 설계 문서 (통합)

> **상태**: v0.3 (2026-06-14). EBSi 자동 수집 부적합 판정 + 깊이와통찰 자체 자료 발견 → 자동화 가능 노선 확정. 본 문서는 정답률 데이터 흡수의 단일 설계서.
> **목적**: 우리 `bank/problems/*.md`의 `external_labels.actual_correct_rate` / `cohort_normalized_star` 필드 일괄 흡수. schema.md §10 calibration의 ground truth 입력.
>
> 📌 **현재 채택 노선**: 깊이와통찰 14개 PDF의 자동 추출(§4) + cohort=academy_internal 정규화(§5). EBSi(§3)는 자동화 부적합으로 미사용.

## 1. 배경 — 왜 정답률인가

schema §10.1 외부 라벨 출처 매핑:

| 후보 출처 | 장점 | 단점 | 채택 여부 |
|---|---|---|---|
| **EBSi 가채점 통계** | 학평 직후 가채점 수만~수십만 명 입력 | robots.txt 차단·서비스 준비중 — §3 | ✗ |
| **자이스토리·기출의바이블 등 가공본** | 출판사가 EBSi+사설학원 흡수 가공 | 마스터 보유 자료 한정. 수동 입력 | 보류 |
| **마더텅 자체 표기** | 이미 보유 | 정답률 표기 없음 (마스터 확인) | ✗ |
| **📌 깊이와통찰 학원 자체 자료 (2,010문항, 22년치 학평)** | **정답률 표기 + 학평 회차 + 시판 책 페이지 모두 보유** | 학원 자체 표본(작음, 상위권 편향) → 자료 내 정규화 필요 | **✅ 채택** |
| 사설학원(메가스터디 등) | 자체 가채점 | 회원 전용 | ✗ |
| 평가원·교육청 공식 | 최고 신뢰 | 공식 미공개 | ✗ |

→ **깊이와통찰 자동 추출 + cohort 정규화 노선 확정**. EBSi(§3)는 자동화 부적합 결론, 미사용.

## 2. 채택 노선 요약 — 깊이와통찰 자동 추출

### 2.1 파이프라인

```
[1] PDF 자동 추출 (extract-deepinsight.mjs)
    14개 PDF → 약 2,010문항 메타 (유형명·정답률·학평회차·배점·유사출처)
        ↓
[2] cohort 분포 정규화 (normalize-deepinsight-cohort.mjs)
    파일 단위로 mean·std 산정 → z-score → 상대 ★
        ↓
[3] T-code 매핑 (typename-to-tcode.json + map-deepinsight-types.mjs)
    유형명 → 우리 통합 T-code 매핑
        ↓
[4] bank/problems/DI-*.md 일괄 등록 (status: meta_only)
    external_labels.cohort_type=academy_internal 채움
        ↓
[5] schema §10.2 calibration 자동 산정 + 마더텅과 교차 매핑
```

### 2.2 단계별 스크립트 (모두 scripts/ 아래)

## 3. EBSi 1차 조사 결론 (2026-06-14) — 미채택

### 3.1 robots.txt 명시 차단

```
User-agent: *
Disallow: /*.ajax$              ← Ajax/XHR 응답 자동 호출 금지
Disallow: /*retrieveSbjtDtl*    ← 과목 상세정보 API 차단
Disallow: /*TotalSearch*
Disallow: /*Qna*  /*Epilogue*  /*/html/*  ...
```

가채점·정답률 데이터는 거의 모두 Ajax 응답으로 노출 → 자동 호출 명시 금지. 한국 법적 환경상 robots.txt 명시 차단 무시 크롤링은 운영자 의사에 반함.

### 3.2 "역대 등급컷/오답률" 페이지 서비스 준비중

`/ebs/xip/xipa/retrievePastGrdCutWrongAnswerRate.ebs` 확인 결과 "서비스 준비중" 메시지. 고1 공통수학1 학평 정답률 직접 데이터 미공개.

### 3.3 표본 수 미표기

발견 가능한 정답률 데이터에 `sample_n` 미표기 → schema §10.2 표본 가드 적용 곤란.

### 3.4 종합 — EBSi 자동 수집 폐기

| 평가 | 판정 |
|---|---|
| 자동화 합법성 | ✗ (robots.txt 명시 차단) |
| 데이터 가용성 | ✗ (등급컷/오답률 페이지 준비중) |
| 표본 신뢰도 | ✗ (sample_n 표기 없음) |

### 3.5 EBSi 자동화 재검토 조건 (장기 점검 — 연 1회)

다음 조건 모두 충족 시 재검토:

## 4. extract-deepinsight.mjs 명세 (Phase 1)

### 4.1 자료 정체 요약

| 항목 | 값 |
|---|---|
| 위치 | `참고자료/고1 모의고사 변형 모음/260614_수능&모의 공통*.pdf` |
| 파일 수 | 14개 (메인 + (1)~(13)) |
| 총 문항 | 약 2,010 (메인+1~12 × 150 + 13 × 60) |
| 시기 | 2004~2026 (고1 학평 22년치) |
| 라벨 | 정답률(%) + 학평 회차·번호·배점 + 유사 시판 책 페이지 |
| cohort_type | `academy_internal` (학원 자체 시험 → schema §10.6 정규화) |

### 4.2 PDF 페이지 구조 (관찰)

페이지당 2단 컬럼(좌·우), 각 컬럼 1문항.

각 문항 텍스트 블록 표준 형식:
```
| 유형명 | 정답률 NN%          ← 좌측 상단 1줄 (정답률은 형광 박스)
[유사] 책 - 단원, 페이지 N    ← 유사 출처 1줄
[유사] 책 - 단원, 페이지 N    ← 유사 출처 2줄
NN [YYYY년 M월 고1 NN번/N점]  ← 문항 번호 + 학평 회차
   문항 본문...
   ① ... ② ... ③ ... ④ ... ⑤ ...
```

### 4.3 입력·출력

```
INPUT:  참고자료/고1 모의고사 변형 모음/*.pdf  (14개)
OUTPUT: data/deepinsight-raw.json
        [
          {
            "file": "260614_수능&모의 공통.pdf",
            "page": 1,
            "column": "left" | "right",
            "problem_no": "01",
            "type_name_raw": "복소수의 사칙연산",
            "correct_rate": 0.90,
            "exam_year": 2026, "exam_month": 6,
            "exam_grade": "고1", "exam_number": 1, "score_points": 2,
            "similar_sources": [
              {"book": "라이트쎈", "subject": "공통수학1", "page": 50, "no": 327},
              {"book": "라이트쎈", "subject": "공통수학1", "page": 50, "no": 331}
            ],
            "body_text": "..."        # 본문 텍스트 (수식 포함, 정확도 80~90% 추정)
          }, ...
        ]
```

### 4.4 파싱 알고리즘

```
[1] 각 PDF 파일을 페이지별로 순회 (pdfjs-dist getDocument → getPage → getTextContent)
[2] 페이지 텍스트 아이템마다 좌표(transform[4]=x, transform[5]=y)·텍스트 추출
[3] 좌측 컬럼(x < page_width/2) / 우측 컬럼 분리
[4] 컬럼 내 텍스트를 y 좌표 내림차순(상→하) 정렬, 같은 y는 x 오름차순
[5] 정규식 추출:
    - 유형명·정답률:   /\|\s*(.+?)\s*\|\s*정답률\s+(\d+)\s*%/
    - 유사 출처:       /\[유사\]\s*(.+?)\s+-\s*(.+?)\s*,\s*(\d+)p\s*(\d+)/
    - 학평 회차:       /\[(\d{4})년\s+(\d+)월\s+고(\d)\s+(\d+)번\/(\d+)점\]/
    - 문항 번호 헤더:  /^\s*(\d{2})\s*$/  (컬럼 시작 부근)
[6] 추출 데이터 검증 → JSON 출력
```

### 4.5 의존성

```json
{
  "dependencies": {
    "pdfjs-dist": "^4.x",
    "js-yaml": "^4.x"
  }
}
```

`pdfjs-dist`가 좌표 정보 제공 — 다단 컬럼 분리 필수. `pdf-parse`는 좌표 없어 컬럼 분리 어려움.

### 4.6 에러 처리

| 케이스 | 대응 |
|---|---|
| 유형명·정답률 패턴 매치 실패 | `errors.json`에 기록, 해당 문항 스킵 |
| 학평 회차 누락 | `exam_*` 필드 null, 진행 |
| 정답률 < 5% 또는 > 99% | 의심 케이스 — `warnings.json` |
| 페이지 컬럼 분리 실패 | 페이지 전체 raw text로 fallback, 수동 검토 표시 |

### 4.7 검증 단계 (자동)

1. 추출 문항 수 = 마스터 표기 150(메인) 또는 60(13번 파일) 일치
2. 출제 회차 분포 sanity (예: 메인은 2024.10~2026.06 안)
3. 정답률 평균·표준편차 출력 (cohort 분포 확인)
4. 수기 26문항(매핑 인덱스 §3.1) vs 자동 추출 26문항 비교 — **정확도 검증**

## 5. normalize-deepinsight-cohort.mjs 명세 (Phase 2)

`extract-deepinsight.mjs` 결과를 schema §10.6 `academy_internal` 정규화.

```
INPUT:  data/deepinsight-raw.json
OUTPUT: data/deepinsight-normalized.json
        각 문항에 추가:
          "cohort_unit": "260614_수능&모의 공통.pdf",
          "relative_difficulty_z": -0.69,
          "cohort_normalized_star": 4

알고리즘:
  group by cohort_unit (파일 단위)
  for each group:
    rates = group.map(r => r.correct_rate)
    mean = average(rates), std = stddev(rates)
    for each problem p in group:
      z = (p.correct_rate - mean) / std
      star = z_to_star(z)         # schema §10.6 매핑
      p.relative_difficulty_z = z
      p.cohort_normalized_star = star

  통계 보고 (cohort별):
    mean / std / star 분포 (★1~★5 카운트)
```

유형별 정규화 (선택): 같은 유형 표본 ≥ 20이면 유형 단위 분리 정규화.

## 8. cross-source-match.mjs 명세 (Phase 6)

같은 학평 회차 문항이 마더텅·깊이와통찰 양쪽에 있으면 calibration ground truth 강화.

```
INPUT:  bank/problems/*.md (전체)
OUTPUT: data/cross-source-matches.json + 보고서

알고리즘:
  [1] 모든 문항 스캔, external_labels 추출
  [2] 매칭 키: (exam_year, exam_session, exam_number, exam_grade)
  [3] 마더텅 출처 ↔ 깊이와통찰 출처 페어 검색
  [4] 매칭 페어:
      {
        "exam_year": 2024, "exam_session": "6월학평", "exam_number": 4,
        "motherteng_id": "CM1-PL-027", "motherteng_star": 1,
        "di_id": "DI-2024-118", "di_cohort_star": 1,
        "delta": 0
      }
  [5] delta ≥ 2 발견 시 mismatch 보고 → 8축 점수 재검토 또는 변형 정도 확인
  [6] 통계 보고:
      - 총 매칭 페어 수
      - delta 분포 (-4 ~ +4)
      - mismatch 문항 목록 (단원·★별)
```
