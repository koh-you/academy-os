## §0. 문서 목적 · 세션 100 재설계 신호

### §0.1 세션 100 발견 — 골드 스탠다드 붕괴

v1.1의 Phase A 완결 조건은 **"자동 판정과 마스터 blind 판정의 90% 일치"** 였다. 세션 100에서 이를 실측하려고 5 pair(원본 anchor 5 + 창작 5)를 시각화 PDF·PNG로 렌더링해 마스터께 blind 판정을 요청했으나:

> **결과: 마스터가 5 pair 전부 "다 똑같은 문항으로 보인다" 판정. 개별 pair 발문 수준에서 A(창작)·B(원본) 구별 불가.**

이는 v1.1의 근본 논리를 무효화한다 — **마스터 판정을 골드 스탠다드로 쓸 수 없다.** 마스터가 정상 pair를 구별하지 못하기 때문이다.

### §0.2 재해석 — 붕괴가 아니라 신호

| | 해석 |
|---|---|
| ✅ 긍정 | 창작이 마스터 눈에도 원본과 구별 불가 = **CM2-GM-원 소단원에서 창작 능력이 이미 원본급** → 이건 **PASS 신호** |
| ⚠️ 부정 | Master-as-gold-discriminator 전제 붕괴 → 정상 pair "누가 더 나은가" 측정은 불가능 |

**핵심 재프레임**: 마스터가 *좋은* 창작과 *좋은* 원본을 구별 못 하는 것은 시스템 실패가 아니라, **그 소단원의 창작이 판별 임계 아래로 원본에 수렴했다는 실측**이다. 따라서 마스터의 역할을 바꾼다.

### §0.3 세션 99 실측이 준 두 번째 신호 — 마스터·심층 판정은 *결함*은 잡는다

세션 99에서 마스터·Opus·reverse-check는 **정상 pair는 구별 못 해도 결함 있는 창작은 잡았다**:

- **BT-002 (F5 답 비유일)**: 창작 문항의 대칭중심 case가 2개(a+b = -15/4 또는 -27/4)라 답이 유일하지 않은 설계 결함. Sonnet은 정방향에서 놓쳤으나 **마스터·Opus가 감지 · reverse-check가 Sonnet 오판정 교정**.
- **BT-003 (답 청결도 결함)**: 창작 답 4√34 vs anchor 답 56. r² 대신 r로 물은 창작 실수.

**결론**: 마스터·자동 pipeline은 "정상 vs 정상" 구별에는 실패해도 "정상 vs 결함" 구별에는 성공한다. **이 판별력(discrimination)이 v1.2 신뢰도의 새 축**이다.

## §1. v1.2 재프레임 요약 — 무엇이 바뀌었나

| 항목 | v1.1 (붕괴) | v1.2 (재설계) |
|---|---|---|
| **골드 스탠다드** | 자동 판정 vs 마스터 blind 판정 90% 일치 | **C 결함 삽입 판별 테스트** (정상군은 통과·결함군은 차단) |
| **마스터 역할** | blind pairwise 판별자 ("어느 쪽이 창작?") | **심층 감사관 · 회귀 감시** (직접 풀이·교육성·well-defined) |
| **정상 pair 처리** | 마스터가 우열 판정 (불가) | **자동 3축(B)이 record standard** · 마스터 구별 불가 = PASS |
| **Phase A 완결 조건** | 정확도 ≥ 90% | **3중 AND** (C 판별 ≥90% + 마스터 감사 전건 통과 + 자동 3축 안정) |
| **신뢰의 근거** | 마스터가 자동을 검증 | **자동은 결함을 잡는 능력으로, 마스터는 자동이 놓친 의미 결함으로 상호 보증** |

**한 문장**: v1.2는 마스터를 "정상 pair 심판"이 아니라 "결함 사냥꾼"으로 재배치하고, 시스템 신뢰도를 "얼마나 정답을 맞히나"가 아니라 **"얼마나 나쁜 걸 잡아내나(판별력)"** 로 측정한다.

## §2. 3대 핵심 원칙 (계승 + v1.2 보강)

### 2.1 원칙 1 — 측정 우선 (Measurement Before Freedom)

창작 결과에 대한 정량 판정 없이 자유도 확대 절대 금지. **v1.2 보강**: 측정의 정의를 "정답 일치율"에서 **"판별력(결함 검출율) + 마스터 심층 감사 무결 + 자동 3축 안정"** 으로 재정의.

### 2.2 원칙 2 — 셀 단위 점진 (Cell-by-Cell Gradual)

소단원 × 통찰 유형 × ★ 등급 매트릭스 각 셀별 독립 게이지·독립 자유도. 한 셀 상승이 다른 셀에 파급 금지. (계승)

### 2.3 원칙 3 — 양방향 게이지 (Bidirectional Meter)

성공 시 상승·실패 시 즉시 하향. 마스터 kill switch 항상 유지. (계승)

### 2.4 원칙 4 (신규) — 마스터는 판별자가 아니라 감사관

**규칙**: 마스터의 정상 pair 구별 불가는 시스템 실패가 아니라 품질 PASS 신호로 해석한다. 마스터는 (a) 창작을 직접 풀어 well-defined·답 청결도·교육적 가치를 심층 감사하고 (b) 자동 pipeline이 놓친 의미적 결함을 회귀 감시한다.

**Why**: 세션 100 실측. 창작이 원본급으로 수렴하면 "누가 더 나은가"는 측정 불가·무의미하나, "결함이 있는가"는 여전히 측정 가능·필수.

## §3. 4-Layer 아키텍처 (v1.2 재편)

### 3.0 Layer 개요

| Layer | v1.2 역할 | 핵심 도구 |
|---|---|---|
| **A · 판정 (Judgment)** | ① 자동 3축(B 메커니즘) ② C 결함 판별 테스트 ③ 마스터 심층 감사 | `blind-twin-evaluate.mjs` · `discrimination-test-runner.mjs` (신규) · `master-audit-log.md` |
| **B · Freedom Gauge** | 셀별 rolling 성공률 → 자유도 unlock | `freedom-gauge.mjs` |
| **C · Retrospective Learner** | 실패 원인 자동 분류(F1~F10) · 프롬프트 강화 diff 제안 | `retrospective-learner.mjs` · `prompt-diff-suggest.mjs` |
| **D · Safe Rollback** | 3연속 실패·급락·kill 감지 시 복귀 | `creation-rollback-check.mjs` |

> ⚠️ 용어 주의: Layer 이름 C(Retrospective Learner)와 재설계 방향 C(결함 삽입)는 다른 개념. 본 문서에서 "메커니즘 C" = 결함 삽입 판별, "Layer C" = 회고 학습.

### 3.1 Layer A · 판정 (Judgment) — v1.2 3-메커니즘 재편

v1.1의 "Blind Twin 판정"을 3개 메커니즘 A·B·C로 재편한다.

#### 3.1.1 메커니즘 B — 자동 3축 (정상 pair record standard)

정상 창작 pair의 판정을 담당하는 자동 pipeline. **마스터가 구별 못 하는 정상 pair의 기록 표준**이 된다.

| 축 | 도구 | 판정 대상 | 신뢰 특성 |
|---|---|---|---|
| **A1 자동 도구** | **`scripts/lib/cfes-a1.mjs` SSOT** (cm1-curriculum-check·master-feedback-check exit-code · 세션 102 신설) · 스코프·정책 hard-violation 결정론 검출 | 형식적 판정 (규칙 기반) | 재현성 100% · 문맥 판단 X |
| **A2 에이전트** | problem-review · solution-review · independent-solve | 문맥적 판정 | 재현성 ~80% · 문맥 판단 O |
| **A3 LLM Pairwise** | `llm-pairwise-rank.mjs` (F6 · Opus+Sonnet 앙상블 · reverse-check) | 상대적 순위 | 재현성 ~70% · 상대 판단 특화 |

**안정 조건 (Phase A 완결 3중 AND의 B 항)**:
- A3 reverse-check 일치율 ≥ 80% (정·역방향 판정 동일)
- 3축 일치율 ≥ 70% (A1·A2·A3 동일 판정 비율)
- 정상 pair를 A1 어느 축도 RED로 오판하지 않음 (false positive 통제)

#### 3.1.2 메커니즘 C — 결함 삽입 판별 테스트 (신규 · 새 골드 스탠다드)

**목적**: 자동 pipeline(B)이 *나쁜 창작*을 잡아내는지 실측 → 판별력 신뢰도 확보. 마스터가 정상 pair를 구별 못 해도, 시스템이 결함 창작을 차단하면 판별력이 입증된다.

**구성**:

| 군 | 정의 | 자동 pipeline 기대 판정 |
|---|---|---|
| **정상군 (clean control)** | 세션 99에서 결함 미검출된 창작 (**creation-01·04·05** · 원본급) | **WIN / 동등** (통과) — false positive 없어야 |
| **결함군 (flawed)** | F1~F10 결함 삽입 창작. seed = **creation-02(BT-002 · F5 답 비유일)** + 정상군에 통제 주입한 신규 결함 | **LOSS / PENDING** (차단) — 잡아내야 |

> ⚠️ 세션 102 정정: v1.1 §10이 creation-01~05 전체를 정상군으로 두면서 BT-002·003을 결함 seed로 둔 것은 모순 (BT-002=creation-02·BT-003=creation-03). 정확히는 **creation-01·04·05 = 정상군**, **creation-02 = F5 결함 seed**, **creation-03 = 답 청결도(M2) 결함** — creation-03의 "답 청결도" 결함은 F1~F10에 정확히 대응 안 되므로 **마스터 심층 감사(A) M2로 기록** (`master-audit-log.md`). 이는 오히려 **A(마스터 감사)가 C 카탈로그 밖 결함을 잡는 3중 AND의 가치를 실증**한다.

**판별력 지표**:
```
판별력(discrimination) = 결함군 중 LOSS/PENDING으로 잡은 비율    [목표 ≥ 90%]
오판율(false positive)  = 정상군 중 결함으로 오판한 비율          [목표 ≤ 10%]
```

**도구 (신규 2종)**:
- `scripts/flaw-injection-generator.mjs` — 정상 창작에 F1~F10 결함을 통제 주입 (예: F5 답 비유일화·F4 교과 침투·F1 통찰 제거)
- `scripts/discrimination-test-runner.mjs` — 정상군+결함군 일괄 → `blind-twin-evaluate` 실행 → 판별력·오판율 리포트

**seed 재활용 (R4)**: BT-002·BT-003은 세션 99에서 이미 실측된 결함이므로 결함군 seed로 즉시 편입. 나머지 결함은 `flaw-injection-generator`로 F1~F10 유형별 최소 1건씩 신규 생성.

#### 3.1.3 메커니즘 A — 마스터 심층 감사 (재정의)

**폐기**: v1.1의 blind pairwise "어느 쪽이 창작?" (구별 불가 실증).

**신규**: 마스터가 창작 **3~5건(R3)** 을 직접 풀어보고 4개 관점으로 심층 감사.

| # | 감사 관점 | 세션 99 근거 사례 | 체크 |
|---|---|---|---|
| M1 | **well-defined** (답 유일? case 중복 없나?) | BT-002 대칭중심 case 2개 | 답 유일성·조건 완결성 |
| M2 | **답 청결도** (답이 지저분? r vs r²?) | BT-003 답 4√34 vs 56 | 답 형태 자연스러움 |
| M3 | **교육적 가치** (통찰이 진짜 변별? 절차 조합 아님?) | — | insight 실체 |
| M4 | **자연스러움** (발문 한국어·조판) | — | 발문 어투·표기 |

**전건 통과** = 감사한 3~5건에 M1~M4 결함 0. (3중 AND의 A 항)

**저장소**: `bank/master-audit-log.md` (신규 · `blind-twin-master-anchor.md` 역할 전환·계승). 형식:

#### 3.1.4 3중 AND 통합 — Phase A 완결 조건

```
Phase A 완결 (→ Phase B 진입 자격) =
    (C) 판별력 ≥ 90%  AND  정상군 오판율 ≤ 10%
  AND (A) 마스터 심층 감사 전건 통과 (누적 감사 pair 목표 · §7.1)
  AND (B) A3 reverse-check 일치율 ≥ 80%  AND  3축 일치율 ≥ 70%
  AND 마스터 명시적 "Phase B 진입 승인"
```

**미달 시**: v1.1의 "즉시 원상 복귀"가 아니라 **편향 완화·판별 카탈로그 보강 iteration (최대 3회)**. 3회에도 미달 시 해당 소단원 Phase A 유예 + 마스터 재지시 대기 (전 시스템 원상 복귀는 마스터 kill switch로만).

### 3.2 Layer B · Freedom Gauge (계승)

셀 = (unit, insight, star). Rolling window 최근 20 창작 시도. `gauge = success / total`.

| 게이지 | 자유도 등급 | 허용 창작 유형 |
|---|---|---|
| 0~60% | **L0 · Locked** | 숫자만 변경 (v1.7 방안 F · 현재 default) |
| 60~75% | **L1 · Constrained** | 조건 재조합 · 동등 변형 |
| 75~90% | **L2 · Expanded** | 새 조건 도입 · 통찰 조합 확장 |
| 90%+ | **L3 · Autonomous** | 자유 창작 (마스터 batch 승인 유지) |

**v1.2 보강**: 게이지의 "success" 정의 = **메커니즘 B 자동 3축 WIN** (정상 pair 판정). 즉 Phase B에서 각 창작은 자동 3축으로 기록되고, 마스터는 3~5건 심층 감사로 회귀 감시. 승격/하향 조건은 v1.1 §3.2.4 계승.

### 3.3 Layer C · Retrospective Learner (계승)

실패 창작 → 원인 분류(F1~F10) → 카탈로그 카운트 → 빈도 threshold 초과 시 프롬프트 강화 diff 제안 → **마스터 승인 후** 적용(자동 금지 · 결정 #7). **v1.2 연동**: 메커니즘 C 결함군이 Layer C 원인 분류의 라벨 정답셋(ground truth)이 된다 — 어떤 결함을 심었는지 알고 있으므로 원인 분류 정확도를 직접 측정 가능.

### 3.4 Layer D · Safe Rollback (계승)

셀 3연속 실패 → L0 복귀. gauge 20%p 급락 → -1단계. 마스터 kill switch → 전 셀 L0(v1.7 방안 F 복귀). CLI + 파일 이중 kill switch (`bank/creation-freedom-lock.md` 존재 시 자동 lock). (v1.1 §3.4 계승)
