# 마스터 지적 누적 시스템 (단일 출처)

> **2026-06-25 마스터 명시 (7회차 v2 검수 직후)**: "지적 사항이 나오면 반복이 안 되는 게 필요할 것 같아. 구조적인 점검이 필요할 것 같아."

## 1. 목적

마스터의 *부정 지적*(금지 표현·금지 패턴·금지 행동)이 다음 작업에서 *반복되지 않도록* 자동 차단하는 단일 출처 시스템.

### 1.1 본 시스템이 해결하는 결함 (3중 누적)

| 결함 | 원인 | 결과 (반복) |
|---|---|---|
| 결함 1 | 마스터 지적이 메모리에 자동 등록 안 됨 | 다음 세션에 잊힘 |
| 결함 2 | 워딩사전·카탈로그 등 단일 출처에 마스터 의향 미반영 | 시스템이 *반대* 권장 |
| 결함 3 | 검수 에이전트가 *과거 지적 디렉토리* 매번 안 읽음 | 검수도 못 잡음 |

### 1.2 본 시스템 원칙

1. **모든 부정 지적은 본 디렉토리에 1지적 = 1파일로 등록 의무**
2. **등록 즉시 메모리(`feedback_*.md`)에도 동시 등록**
3. **자동 차단 도구 `scripts/master-feedback-check.mjs`에 키워드 자동 추가**
4. **워딩사전·카탈로그 등 충돌 단일 출처가 있으면 *동시 정정***
5. **검수 에이전트 4종 (problem-review·exam-review·solution-review·solution-author)이 *매번 본 디렉토리를 읽는 것* 의무화**

## 2. 디렉토리 구조

```
bank/마스터-지적/
├── README.md            # 본 파일 (시스템 정의)
├── INDEX.md             # 등록된 지적 목록 + 차단 키워드
└── YYYY-MM-DD-{슬러그}.md  # 각 지적 1파일
```

## 3. 지적 파일 양식

각 지적 파일은 다음 양식을 따른다 (단일 출처 표준):

```markdown
---
date: 2026-06-25
master_quote: "마스터의 원문 인용"
context: 발생 맥락 (어느 작업·어느 슬롯)
severity: RED (자동 차단) / YELLOW (검토 권장)
forbidden_keywords:
  - 패턴1 (regex)
  - 패턴2
alternatives:
  - 대안 표현1
  - 대안 표현2
related_memory: feedback_*.md (있다면)
related_catalog: bank/4점-패턴-카탈로그/*.md (충돌 단일 출처)
auto_check: scripts/master-feedback-check.mjs 키워드 등록 여부
---

## 지적의 본질
(한 문단으로 마스터가 무엇을 *왜* 지적했는지)

## 차단 키워드 명세
(grep 가능한 정확한 패턴)

## 대안 표현
(마스터 의향 추정 또는 명시된 대체 표현)

## 적용 범위
(본문 / 답지 / 청사진 / 모두)

## 정정 이력
(과거 시점·작업·정정 결과)
```

## 4. 등록·갱신 워크플로우

### 4.1 새 지적 등록 (마스터 부정 지적 발생 시 — *즉시*)

1. `bank/마스터-지적/YYYY-MM-DD-{슬러그}.md` 신규 작성 (양식 §3)
2. `bank/마스터-지적/INDEX.md`에 한 줄 추가
3. `memory/feedback_{슬러그}.md` 신규 (메모리 호환)
4. `memory/MEMORY.md`에 한 줄 추가
5. 충돌 단일 출처 (워딩사전·카탈로그) 정정 — *동시*
6. `scripts/master-feedback-check.mjs`에 키워드 추가 — *동시*

### 4.2 검수 에이전트 의무 (매 호출 시)

- problem-review·exam-review·solution-review·solution-author 모두 *호출 직후* `bank/마스터-지적/INDEX.md`를 *읽는 것*이 의무
- 각 지적의 `forbidden_keywords`로 본문/답지 grep — RED 발견 시 *즉시 보고*

### 4.3 자동 차단 (G4' 게이트)

`scripts/master-feedback-check.mjs`가 본문·답지·청사진 모든 .tex/.yaml에서 등록된 키워드 grep. RED 있으면 빌드 차단.

## 5. 시스템 보장

본 시스템 도입 후 다음을 보장한다:

- 한 번 등록된 지적은 *모든 미래 세션에서 자동 회피*
- 검수 누락 → *불가능* (검수 에이전트가 의무 점검)
- 충돌 단일 출처 → *동시 정정*으로 차단
