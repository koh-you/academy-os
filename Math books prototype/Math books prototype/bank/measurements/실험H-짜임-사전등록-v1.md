# 실험 H — 짜임 (사전 등록)

**묻는 것**: 「얽힘」을 **연결된 개수 세기**에서 **길의 모양 고르기**로 바꾸면 자가 더 나아지는가.

🔴 **이 문서는 앵커를 다시 읽기 전에 쓴다.** 다시 읽고 나서 고치면 검정이 아니다.

---

## 0. 왜 바꾸는가 (관측 전 진술)

세션 108 의 얽힘은 **연결된 소문항·조건의 개수**로 칸을 정했다. 두 가지가 걸렸다.

1. **끝없는 물음** — 개수를 세려면 무엇이 셀 것인지 경계를 그어야 하고, 경계를 하나 그으면 그 옆에 새 물음이 생긴다. 세는 법에 아직 답이 없는 자리가 **둘** 남아 있었다 (한 라벨 안 여러 식 · 값을 내놓는 조건 vs 대상만 정하는 조건).
2. **선 정책과 어긋남** — 「★ 4·5 에서 카운팅으로 노동량을 늘려 난이도를 높이는 형태는 지양」 (마스터 영구 정책 2026-06-27 · `feedback_inference_over_counting`). 난이도 재는 자를 개수 세기로 만든 것이 이 정책과 반대 방향이었다.

> **마스터 (2026-08-02 세션 109)**: 「얽힘이라는 건 결국 통찰의 영역. 몇 가지 통찰이 얼마나 입체적인 구성으로 문항이 설계되어 있느냐. 그것이 정방향으로 흐르느냐 역방향으로 흐르느냐.」

---

## 1. 재는 것 — 짜임

### 판정 질문 (하나)

> **첫 수를 두고 난 뒤, 답까지 가는 길이 한 줄로 곧게 뻗어 있는가. 아니면 도중에 갈아타고 되돌아와야 하는가.**

**갈아탄다** = 성격이 다른 도구로 옮긴다 (식 → 그림 · 그림 → 식 · 세는 일 → 식 · 다른 단원의 도구).
**되돌아온다** = 갈아타서 얻은 것을 **원래 자리로 가지고 와서 다시 쓴다.**

### 칸 다섯

| 칸 | 등급 | 길의 모양 |
|:-:|:-:|---|
| **1** | ★ 1~2 | **곧은 길** — 주어진 것을 순서대로 처리하면 답에 닿는다 |
| **2** | ★ 3 | **한 번 꺾임** — 도중에 한 번 갈아탄다. 꺾은 뒤에는 다시 곧게 간다 |
| **3** | ★ 4 | **되돌아옴** — 갈아타서 얻은 것을 원래 자리로 가지고 와서 다시 쓴다 |
| **4** | ★ 5 | **두 겹으로 되돌아옴** — 되돌아오는 일이 두 번 있거나, 두 도구가 서로 결과를 주고받는다 |
| **5** | ★ 5 프리미엄 | **길을 학생이 세운다** — 어디서 꺾을지, 무엇으로 갈아탈지 발문이 알려 주지 않는다 |

🔴 **개수를 세지 않는다.** 판정자는 다섯 모양 중 하나를 **앵커와 견주어** 고른다.

### 🔴 깊이와 가르는 선 (한 줄)

> **첫 줄이 안 써지면 깊이다. 첫 줄은 써지는데 그 다음 길이 문제면 짜임이다.**

용어 사전에 이미 그렇게 적혀 있다 — 「깊이가 높으면 **첫 줄이 안 써진다**」 · 「실행 부담이 높으면 **첫 줄은 써지는데 끝까지 못 간다**」.

🔴 **칸 5 가 이 선을 가장 세게 시험한다.** 「길을 학생이 세운다」는 깊이의 정의와 가깝다.
**여기가 무너지면 이 축이 무너진다.** 아래 확인 둘 「깊이와 갈리는가」가 그것을 잡는다.

## 2. 설계

| 항목 | 값 |
|---|---|
| **1단계 대상** | 얽힘 앵커 **36문** — `bank/anchors/얽힘-사다리-v1.md` v1.4 |
| **자료** | `bank/anchors/실행부담-발췌본-v1.md` (발문 전문) |
| **판정자** | **H1 · H2** 둘. 서로의 산출물을 보지 않는다 |
| **판정자가 보는 것** | 발문 전문 · 짜임 칸 다섯 정의 |
| **판정자가 못 보는 것** | 🔴 **지금 앉아 있는 칸 · 연결된 개수 · 학교·회차·문번·배점** |
| **2단계 대상** | 재검정 v2 맹검지 (별도 등록) |
| 신규 문항 | 0 · 정점 칸 소모 0 |

🔴 **1단계에서 앵커의 현재 자리를 가리는 이유** — 가리지 않으면 판정자가 옛 칸을 그대로 옮겨 적는다.
그러면 「자산이 살아남았다」가 아니라 **「베꼈다」**가 된다.

## 3. 지표

| 지표 | 계산 |
|---|---|
| **재현성** | H1 ↔ H2 이산 일치율 (같은 칸을 고른 문항의 비율) |
| **변별** | 칸별 문항 수 분포 |
| **깊이와 갈리는 정도** | 짜임 칸 ↔ 깊이 칸이 **함께 움직인 문항의 비율** |
| **자산 보존율** | 새 칸이 옛 칸과 **같거나 한 칸 차이**인 문항의 비율 |

🔴 **이산 일치율을 쓴다.** 연속 잡음비는 판정자가 중간값 표기를 쓰면 불일치가 반으로 접힌다 (SSOT §2).

## 4. 🔴 통과선 넷 (관측 전 고정 · 관측값에서 만들지 않는다)

| # | 확인 | 기준 | 근거 |
|:-:|---|---|---|
| **판정자 둘이 맞는가** | **재현성 ≥ 70%** · 두 칸 차이 **0건** | 절대 | 세션 108 얽힘 개수 세기의 실측 재현성이 70~75% 였다. **그보다 못하면 바꿀 이유가 없다** |
| **깊이와 갈리는가** | **깊이와 함께 움직인 비율 < 80%** | 절대 | 🔴 **이 축이 무너질 자리.** 80% 넘으면 짜임은 깊이의 다른 이름이다 |
| **칸이 다 쓰이는가** | **칸 다섯이 모두 쓰인다** — 각 칸에 **3문 이상** | 절대 | 상수가 되는 축을 거른다 (`feedback_axis_validation_dual_criteria` · 축 F 16슬롯 전례) |
| **앵커가 살아남는가** | **자산 보존율 ≥ 60%** | 절대 | 앵커 36문을 다시 모으는 데 세션 하나가 들었다. 절반 넘게 흩어지면 바꾸는 값이 너무 크다 |

**넷 다 만족해야 통과.**

### 미달했을 때 무엇을 하는가 (관측 전 고정)

| 미달한 것 | 처분 |
|---|---|
| **「판정자 둘이 맞는가」만 미달** | 칸 정의의 말을 다듬고 **다시 잰다.** 폐기가 아니다 |
| **「깊이와 갈리는가」 미달** | 🔴 **짜임 폐기.** 안 A(흐름 방향)로 간다. 「깊이와 겹치니 합치자」로 가지 않는다 |
| **「칸이 다 쓰이는가」 미달** | 빈 칸을 **없애고 칸을 넷으로** 줄인다. 칸을 억지로 채우지 않는다 |
| **「앵커가 살아남는가」 미달** | 짜임은 유지하되 **앵커를 다시 모은다.** 자산이 아까워서 축을 되돌리지 않는다 |

🔴 **결과가 이상해 보인다고 깎거나 보류하지 않는다** (`feedback_measure_by_definition_not_conclusion` · 통합관리 C27).

## 5. 🔴 폐기해도 지우지 않는 것

짜임이 떨어지면 **안 A(흐름 방향)**로 간다. 안 A 는 이렇게 남겨 둔다.

> **안 A — 흐름 방향**: 발문이 준 것에서 답으로 곧장 가는가, 답 쪽에서 거꾸로 짚어 올라오는가. 되짚기가 몇 겹인가.
> **후보에서 밀린 까닭** (2026-08-02 · 관측 전 판단): 같은 문항을 대입으로 풀면 정방향, 인수정리로 읽으면 역방향이라 **판정이 문항이 아니라 판정자의 풀이 선택에 달린다.** 「오로지 문항으로 판단한다」(`feedback_item_only_not_scoring_policy`)와 어긋난다.

**안 B — 짜임만 따로 (갈아타기만 보고 방향은 안 봄)** 도 후보였다. 짜임에 흡수됐다.

---

## 6. 🔴 미리 밝혀 두는 한계

1. **판정자가 풀이를 어느 정도 그려야 한다.** 길의 모양은 길을 걸어 봐야 보인다. 개수 세기보다 품이 든다.
2. **1단계는 앵커 자신을 재는 것이라 표본이 치우쳐 있다.** 앵커는 칸이 고르게 되도록 고른 것이라 실제 시험지 분포가 아니다. **변별(확인 셋)은 2단계 맹검지에서 다시 본다.**
3. **깊이 칸은 기존 `bank/anchors/깊이-앵커-사다리-v1.md` 판정을 쓴다.** 이번에 새로 매기지 않는다.
4. **이름 「짜임」은 잠정이다.** 마스터 확정 전이다.
