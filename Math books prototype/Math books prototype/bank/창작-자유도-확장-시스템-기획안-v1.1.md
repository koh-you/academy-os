## §0. 문서 목적

세션 96 후반 마스터 지시에 따라 **창작 자유도 확장 시스템 (Creation Freedom Expansion System · 이하 CFES)** 의 완성도 있는 구체 기획안을 정립한다.

**핵심 질문 (마스터)**: "F6도 만들었을 때의 이점과 수학 문제 창작 자유도를 높이기 위한... 즉 현재 문제 제작 지침으로 만든 문제들보다 더 같거나 더 좋은 문제들을 창작하기 위한 능력이 향상되었을 때 자유도가 늘어나야 하기 때문에... 어떤 시스템을 구축해야 지금 내가 원하는 바가 실현될 수 있는지 알려줘."

**본 기획안의 응답**: 창작 능력 **측정 시스템**을 먼저 확립하고, 측정 신뢰도가 확보된 후 **셀 단위**로 자유도를 점진 개방하는 4-Layer 아키텍처 + Phase A/B/C rollout.

**본 기획안은 실행 문서가 아닌 설계 문서**. 마스터 승인 후 Phase A-1 부터 실제 착수.

## §1. 배경 · 현재 시스템의 한계

### 1.1 현재 상태 (2026-07-28 세션 96 종료 시점)

- **feedback loop 자동화율**: ~68% (P0 4건 + P1 2건 완료 · 세션 60 목표 초과 달성)
- **자산 pool**: ~6,600문 · 23 벤더 회귀 · 50 premium 원형 카탈로그
- **v1.7 방안 F 원칙**: **"Agent 창작 금지 · 원본 pick + 최소 변형"**
- **결과**: 품질은 안정적이나 창작 자유도는 원천 차단

### 1.2 v1.7 방안 F의 성립 근거 (원상 유지 조건)

v1.7이 창작을 금지한 이유는 3가지:

1. **품질 판정 시스템 부재** — 창작 문항이 원본과 동등 이상인지 자동 판정 불가
2. **자기평가 편향 위험** — LLM이 스스로 만든 문제를 스스로 판정 시 신뢰 붕괴
3. **fake premium 위험** — Agent 창작이 star_5 라벨 자체 부여 시 실측 star_3~4에 star_5 낙인 위험

이 3가지는 **여전히 유효**하다. 따라서 CFES는 이 3 조건을 우회하지 않고 **정면 돌파**하는 시스템이어야 한다.

### 1.3 재설계 원리 — 능력·자유도 매핑

**핵심 통찰**: "Agent 창작 금지"는 창작 **능력**이 없어서가 아니라 창작 **결과의 품질을 측정할 수 없어서** 취한 방어책. 즉, 측정 시스템이 확립되면 자유도는 논리적 귀결로 확장 가능.

**공식**:
```
자유도(cell_i) = f( 측정 신뢰도(cell_i), rolling 성공률(cell_i), 마스터 kill switch )
```

- **cell_i** = (소단원 × 통찰 유형 × ★ 등급) 매트릭스의 각 셀
- 각 셀은 **독립 게이지**를 갖는다. 한 셀에서 자유도가 확대되어도 다른 셀은 유지.

## §2. 3대 핵심 원칙

### 2.1 원칙 1 — 측정 우선 (Measurement Before Freedom)

**규칙**: 창작 결과에 대한 정량 판정 없이 자유도 확대 절대 금지.

**적용**: Phase A (판정 시스템 신뢰도 확립) 완결 전에는 창작 자유도 확대 없음. Phase B·C는 Phase A 통과 조건.

**Why**: 판정 없이 확대하면 fake premium 재발 · v1.7 방안 F 방어선 붕괴.

### 2.2 원칙 2 — 셀 단위 점진 (Cell-by-Cell Gradual)

**규칙**: 소단원 × 통찰 유형 × ★ 등급 매트릭스 각 셀별로 독립 게이지 · 독립 자유도.

**적용**:
- 한 셀에서 게이지가 상승해도 다른 셀의 자유도는 그대로.
- 시리즈 전체 자유도 일괄 확대는 금지.

**Why**: 한 셀 실패가 시스템 전체 자유도를 오염시키지 않도록 격리.

### 2.3 원칙 3 — 양방향 게이지 (Bidirectional Meter)

**규칙**: 게이지는 성공 시 상승 · 실패 시 즉시 하향. **마스터 kill switch 항상 유지**.

**적용**:
- 3연속 실패 → 해당 셀 자동 rollback (자유도 → 최저 단계 · 원본 pick 모드)
- 마스터 최종 검수 미통과 → 게이지 -10%p 즉시 감쇠
- 마스터가 kill switch 발동 시 즉시 v1.7 방안 F 원상 복귀 (전체 시스템)

**Why**: 자유도 확대는 신뢰의 부산물. 신뢰 잃으면 즉시 회수.

## §3. 4-Layer 아키텍처 상세

### 3.1 Layer A · Blind Twin 판정 (Blind Twin Evaluation)

**목적**: 창작 문항 X와 anchor 원본 Y를 blind pair로 3축 판정. "동등 이상" 판정 시 통과.

#### 3.1.1 판정 3축

| 축 | 도구 | 판정 대상 | 신뢰 특성 |
|---|---|---|---|
| **A1 자동 도구 축** | copyright-similarity · insight-depth-check · structure-signature-check · figure-answer-leakage · standard-check | 형식적 판정 (규칙 기반) | 재현성 100% · 문맥 판단 X |
| **A2 에이전트 축** | problem-review · solution-review · exam-review (independent-solve) | 문맥적 판정 (에이전트 서브프롬프트) | 재현성 ~80% · 문맥 판단 O |
| **A3 LLM Pairwise 축** | `llm-pairwise-rank.mjs` (F6) | 상대적 순위 (직접 비교) | 재현성 ~70% · 상대 판단 특화 |

#### 3.1.2 Blind Twin 프로토콜

```
입력: 창작 X, 원본 Y (anchor), 판정 대상 (unit, insight, star)

1. 순서 무작위화 · 원본/창작 라벨 제거 · 익명화 pair (P, Q) 생성
2. A1 자동 도구 3~5종 실행 → P·Q 각각 score
3. A2 에이전트 2종 (problem-review, solution-review) 병렬 호출 → P·Q 각각 등급
4. A3 LLM Pairwise (F6) 호출 → "P > Q · P = Q · Q > P" 판정
5. 3축 결과 통합 → 최종 판정 (동등 이상 · 열등 · 판정 불가)
```

#### 3.1.3 승리·실패 조건

**승리 (창작 문항 편입 승인)**:
- A1: score 차이 ≤ 10% (P·Q 유사도 GREEN · leakage 없음 · insight-depth 동등)
- A2: 2 에이전트 모두 "동등" 또는 "P (창작) 우세"
- A3: LLM 판정 "동등" 또는 "P 우세" (신뢰도 ≥ 0.6)
- **3축 모두 통과 시에만 승리**

**실패 (창작 문항 기각)**:
- 하나라도 "Q (원본) 우세" 판정 → 실패
- A1의 어느 하나라도 RED → 실패
- A3 신뢰도 < 0.5 → 판정 불가 → 마스터 수동 개입

#### 3.1.4 편향 완화 3원칙

**LLM 자기평가 편향 완화**:
1. **역방향 판정**: F6는 (P, Q)와 (Q, P) 두 순서로 판정 · 결과 일치 확인
2. **다중 모델 앙상블**: F6 = Claude Opus + Sonnet + Haiku 3개 모델 다수결 (선택)
3. **마스터 대조 sample**: 20 pair마다 마스터 판정으로 대조 · 편향 감지

### 3.2 Layer B · Freedom Gauge (자유도 게이지)

**목적**: 소단원 × 통찰 유형 × ★ 등급 매트릭스 각 셀의 rolling 성공률 → 자유도 unlock 매핑.

#### 3.2.1 매트릭스 구조

**셀 정의**: (unit, insight, star)

- **unit**: CM1-PL·EQ·CB·MX · CM2-GM·ST·FN·RF 각 소단원 세분 (예: CM1-EQ-이차·CM2-GM-원)
- **insight**: I-EQV·I-CON·I-PD·I-XU·I-SYM·I-VF·I-MI·I-SC·I-BW·I-RT (schema.md 통찰 유형)
- **star**: ★ 2·3·4·5·premium

**셀 수**: ~ 소단원 32 × 통찰 10 × ★ 5 = **1,600 셀** (실제로는 vacant 셀 많음 → active ~ 300~500)

#### 3.2.2 게이지 정의

**Rolling Window**: 최근 20 창작 시도 (셀별)

**게이지 지표**:
```
gauge(cell) = success_count / total_attempts     [rolling 20]
```

**보정**:
- 시도 5회 미만 → 게이지 계산 X · pending 상태 (기존 pick 모드 유지)
- premium 승리 (마스터 승인) → +2 가중치
- 마스터 kill → -10%p 즉시 감쇠

#### 3.2.3 자유도 4단계

| 게이지 | 자유도 등급 | 허용 창작 유형 |
|---|---|---|
| 0~60% | **L0 · Locked** | 숫자만 변경 (현재 default · v1.7 방안 F) |
| 60~75% | **L1 · Constrained** | 조건 재조합 · 동등 변형 (schema.md §7 "2순위 동등 변형") |
| 75~90% | **L2 · Expanded** | 새 조건 도입 · 통찰 조합 확장 (1~2개 통찰 카드 신설) |
| 90%+ | **L3 · Autonomous** | 자유 창작 (원본 pick 없이 · 마스터 batch 승인 유지) |

**임계값 확정 (마스터 결정 #4)**: 판정 정확도 90%와 정합. L1 셀 많이 · L2·L3 극소 예상. 오판 위험 최소.

#### 3.2.4 자유도 확대 조건 (Guard)

L0 → L1 승격:
- gauge ≥ 60% 유지 **10 창작 연속**
- A3 신뢰도 평균 ≥ 0.7
- 마스터 kill 이벤트 0건 (최근 10 시도)

L1 → L2 승격:
- gauge ≥ 75% 유지 **10 창작 연속** (일회성 상승 방지)
- A3 신뢰도 평균 ≥ 0.8
- 마스터 kill 이벤트 0건 (최근 10 시도)

L2 → L3 승격:
- gauge ≥ 90% 유지 **20 창작 연속**
- A3 신뢰도 평균 ≥ 0.85
- 마스터 batch 승인률 ≥ 90% (최근 5 batch)

**하향**:
- gauge < 임계값 → 즉시 하향 (5 시도 이내)
- 3 연속 실패 → 두 단계 하향

### 3.3 Layer C · Retrospective Learner (회고 학습)

**목적**: 실패한 창작 → 원인 자동 분류 → 프롬프트 강화 diff 제안 → 다음 창작 개선.

#### 3.3.1 회고 사이클

```
실패 창작 → 원인 분류 (F1~F10) → 카탈로그 카운트 append
    → 특정 원인 빈도 ≥ threshold → problem-author 프롬프트 강화 diff 제안
    → 마스터 승인 후 프롬프트 갱신 → 다음 창작 사이클
```

#### 3.3.2 원인 자동 분류 방법론

**신호 매칭**:
- Layer A 3축 결과 → 원인 후보 (예: A1 insight-depth RED → F1 통찰 얕음)
- 실패 문항 시그니처 → 원인 카탈로그 매칭 (embedding 유사도)
- LLM 자동 분류 (F6 재사용 · "다음 원인 중 무엇에 해당하는가?")

**신뢰도**:
- 3가지 신호 중 2개 이상 동일 원인 → 확정
- 1개만 → 마스터 검토 대기

### 3.4 Layer D · Safe Rollback (안전 복귀)

**목적**: 시스템 신뢰 붕괴 조짐 감지 시 즉시 v1.7 방안 F로 복귀.

#### 3.4.1 자동 rollback 트리거

**셀 단위**:
- 해당 셀에서 3 연속 실패 → 자유도 → L0 (Locked · pick 모드)
- gauge 20%p 이상 급락 (rolling 20 within 5 시도) → 자유도 -1 단계

**시스템 단위**:
- 최근 30 창작 전체 성공률 < 60% → 전 셀 L1로 하향
- 마스터 kill switch 발동 → 전 셀 L0 즉시 복귀 (v1.7 방안 F 완전 복귀)

#### 3.4.2 마스터 kill switch UI

```bash
# 셀 단위 kill
node scripts/creation-rollback-check.mjs --kill --cell CM1-EQ-이차,I-EQV,4

# 전 시스템 kill
node scripts/creation-rollback-check.mjs --kill-all --reason "품질 회귀 감지"
```

kill 이벤트는 `bank/kill-log.md`에 자동 append · Layer C 회고 학습 자산으로 편입.

## §4. 실패 원인 카탈로그 F1~F10 (v0 초안)

Layer C 원인 분류 스키마의 초기 카탈로그. 실측 후 F11~ 확장.

### F1 · 통찰 얕음 (Insight Shallowness)

**정의**: 창작 문항이 절차 조합에 머무름 · 진정 변별 P1~P6 카드 부재.

**감지**: A1 `insight-depth-check.mjs` depth_score < 6 · P 카드 count = 0.

**대응**: problem-author 프롬프트에 "저노출 통찰 유형 (I-SC·I-VF·I-SYM·I-XU) 최소 1개 카드 삽입 의무" 강화.

**연관 메모리**: `feedback_first_draft_completeness_5axis` · `feedback_difficulty_system_v4`

### F2 · 자연어 부자연 (Unnatural Korean)

**정의**: 발문·답지의 한국어가 어색·직역체·번역투.

**감지**: F1~F7 부자연 표현 카탈로그 (bank/4점-패턴-카탈로그 §9 답지 세련도) 매칭 · standard-check.mjs YELLOW.

**대응**: 후기 iteration 원본 발문 stem을 프롬프트에 few-shot 삽입 · 자연어 template pool 확장.

**연관**: `feedback_solution_cp_count` v2.0 F1~F7

### F3 · 자기복제 (Self-Replication)

**정의**: 이전 회차 또는 원본 anchor와 통찰 카드·구조 시그니처 일치.

**감지**: A1 `anchor-neighbors.mjs` 유사도 ≥ 0.8 · `structure-signature-check.mjs` RED.

**대응**: `origin-pattern-tagger.mjs` 미리 실행 · top-3 원형 태그 후 회피 pool 강제.

**연관**: `feedback_no_self_replication` · 마스터 지적 `2026-06-25-자기복제-철저금지.md`

### F4 · 교육과정 침투 (Curriculum Violation)

**정의**: CM1 슬롯에 CM1 밖 개념·용어 (역행렬·여사건·이중근호 등) 침투.

**감지**: A1 `cm1-curriculum-check.mjs` · `cm1-vendor-out-of-scope.mjs` RED.

**대응**: 프롬프트에 CM1-교과과정.md §"최우선 RED 요약" 명시적 편입.

**연관**: `feedback_curriculum_terms` · `feedback_cm1_curriculum_single_source`

### F5 · 답 유일성 위반 (Answer Non-Uniqueness)

**정의**: 문항의 답이 유일하지 않음 · 조건 부족 · 다중 해석 가능.

**감지**: A2 independent-solve agent가 2개 이상 답 도출 · mathjs 검증에서 다중 해 발견.

**대응**: 프롬프트에 "출제 후 마스터 조건 완결성 자체 검수 의무" 강화 + 조건 카드 최소 개수 gate.

### F6 · 발문 모호 (Ambiguous Wording)

## §5. 필요 신규 도구·자산 (Phase A + B 총 8종)

### 5.1 Phase A 도구 (2~3 세션 · 판정 신뢰도 확립)

#### 5.1.1 `scripts/llm-pairwise-rank.mjs` (F6 · Layer A3)

**목적**: 두 문항 pair의 상대적 난이도·통찰 깊이·자연스러움을 LLM 판정.

**CLI**:
```bash
node scripts/llm-pairwise-rank.mjs \
  --p <문항P.tex or 문항P.md> \
  --q <문항Q.tex or 문항Q.md> \
  --dimension <difficulty|insight|naturalness|composite> \
  [--reverse-check]         # (P,Q) + (Q,P) 두 순서로 판정 · 일치 확인
  [--model claude-opus-4-7] # 기본
  [--report <경로>]
```

**출력**:
```yaml
p_over_q: 0.65        # P > Q 신뢰도 (0~1)
q_over_p: 0.20
equal:    0.15
reasoning: "P가 통찰 카드 I-XU를 명시적 요구 · Q는 절차 조합에 머무름"
confidence: 0.75       # 판정 신뢰도
reverse_consistent: true  # (Q,P) 재판정과 일치 여부
```

**exit code**: 0 = 판정 성공 · 1 = 신뢰도 미달 (판정 불가) · 2 = 오용.

**예상 LOC**: 300~400.

## §6. 판정 신뢰도 확보 방법론

### 6.1 신뢰도 정의

**판정 정확도** = (Layer A 판정) ∩ (마스터 판정) / (총 pair)

**목표 임계값**: ≥ 85% (Phase A 통과 조건)

### 6.2 실측 프로토콜 (Phase A-2)

```
1. 원본 pool 풍부 소단원 선정 (예: CM2-GM-원 · 6~7 정독 파일 · 200+ 원본)
2. 각 소단원에서 anchor 원본 Y 선정 (star_4·5 각 5개)
3. Agent (problem-author 임시 창작 모드)로 Y 대응 창작 X 생성 (10~20 시도)
4. Blind Twin 판정 (Layer A 3축) → 자동 판정 결과 저장
5. 마스터가 별도로 X vs Y 판정 (Blind · 어느 쪽이 창작인지 몰라야)
6. 자동 판정 vs 마스터 판정 대조 → 정확도 산출
```

### 6.3 편향 감지·완화

**편향 유형 및 완화**:

| 편향 | 감지 방법 | 완화 방법 |
|---|---|---|
| **자기평가 편향** (LLM이 자기 창작 우호) | 역방향 판정 (P,Q)·(Q,P) 일치 실측 | 3축 앙상블 · A3만 사용 X |
| **길이 편향** (긴 발문 = 어렵다 판정) | 발문 길이 통제 sample | 길이 정규화 · 발문 길이 유사 pair만 사용 |
| **최신성 편향** (익숙한 스타일 우호) | 원본 별 스타일 라벨링 | Blind (스타일 라벨 제거) |
| **템플릿 편향** (Agent 창작 특유 표현) | 창작 vs 원본 어투 diff 분석 | few-shot에 원본 stem 다양화 |

### 6.4 신뢰도 미달 시 조치

- **정확도 < 60%**: Layer A 재설계 · Phase A 재시작
- **정확도 60~75%**: 축별 가중치 조정 · A3 신뢰도 threshold 상향 (0.6→0.75)
- **정확도 75~85%**: 편향 완화 프로토콜 강화 · sample size 확대 (200→300 pair)
- **정확도 ≥ 85%**: Phase B 진입 조건 통과

**Phase B 산출물**:

**자유도 확대**: **국소 · 셀 단위 점진** (초기 L1 셀 5~10 개 · 승격 조건 충족 시 L2 확대)

### 7.3 Phase C · 자율 창작 (세션 105+ · 성숙기 · 무기한)

**C-1 자율 창작 조건**:
- 게이지 ≥ 85% 셀만 L3 (자유 창작)
- 마스터 batch 승인률 ≥ 90% 유지

**C-2 마스터 개입 축소**:
- 개별 pick·조판 개입 → batch 승인만
- kill switch 항상 유지 · 실측 monitoring

**C-3 시스템 성숙 지표**:
- L3 셀 수 (전체 active 셀 대비 비율)
- 마스터 개입 횟수 (회차당)
- 창작 성공률 (rolling · 시스템 전체)

**Phase C는 종료 시점 없음**. 지속 monitoring · 실패 감지 시 즉시 Layer D 발동.

### 7.4 Phase 진행 게이트 (Guard)

각 Phase 진입 시 마스터 명시적 승인 필수:

- Phase A → B: 판정 정확도 ≥ 85% 실측 리포트 + 마스터 명시적 "B 진입 승인"
- Phase B → C: 실측 데이터 50+ · 셀별 게이지 안정 + 마스터 명시적 "C 진입 승인"

**핵심 결론**:

> CFES는 v1.7 방안 F를 폐기하는 게 아니라 **측정·회고·안전 복귀** 시스템을 얹어 **자유도의 논리적 확장 조건**을 만드는 시스템.

> 완전 자유는 원천 불가 (마스터 batch 승인은 Phase C에서도 유지) · 현실적 최대 자유도 = **"감독하에 자율"**.
