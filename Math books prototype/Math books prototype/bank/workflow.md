## 0. 사전 점검 — 어느 책을 만드는가

**목적**: 책의 정체성을 확정해야 모든 후속 단계가 일관성 있게 흘러감.

**결정 항목**:
- **편(volume)**: 유형편 / 개념편 / 해설편 / 테스트지 등
- **과목·단원**: CM1(PL/EQ/CB) 또는 CM2(GM/ST/FN/RF)
- **대상층**: 상위권 / 중상위권 / 중위권 / 중하위권 / 하위권 (schema §3.1)
- **분량**: 총 문항 수, 페이지 수, 책 안에서 차지하는 비중
  - 디폴트 권장: **테스트지 15~20문 × 4~10페이지** / **유형편 단원당 60~150문 × 30~80페이지** (단원 분량에 따라 조정)
  - 결정 안 됐으면 사용자에게 직접 물어볼 것 — 후속 단계 모두 영향
- **참고자료 활용**: 단원 첫 진입이면 `bank/공통수학N/{단원}.md` 카탈로그(유형 분류·난이도 분포)를 먼저 통독. 기존 단원은 이미 분석된 메모(reference 메모리) 참조
- **도트 디자인**: 공수2 유형편 글로벌(회색 5도트 — `mathbook-problems.sty` 정의) 사용이 디폴트. preamble에서 `\fontsize{6.5}` 같은 오버라이드를 의도적으로 두지 않음 — test02 사례

**체크리스트**:
- [ ] 단원이 우리 교육과정 약자 표(schema §1.2)에 있는가
- [ ] 대상층 5단계 중 정확히 하나로 결정됐는가
- [ ] 분량(슬롯 수)이 결정됐는가
- [ ] 참고자료 카탈로그 통독 (단원 첫 진입 시)
- [ ] 도트 디자인 정책 확인 (글로벌 사용 또는 책 특수 오버라이드)

**함정**: "대충 상위권 정도" 같은 모호한 결정은 분포·축 가이드 자동 도출이 안 됨. 5단계 중 하나로 단정.

## 1. 계획 — `book.yaml` 작성

**목적**: 책의 슬롯 단위 청사진. 후속 출제·검수·빌드의 기준점.

**위치**: `output/{과목}/{책명}.book.yaml`

**책명 명명 규약** (기존 작업 패턴):
- **테스트지**: `test{NN}-{단원약식}` — 예: `test01-방정식부등식`, `test02-여러가지부등식`. NN은 테스트지 순서 일련번호(과목 내)
- **유형편**: `{NN}-{단원약식}` — 예: `01-도형의이동`, `04-유리함수와무리함수`. NN은 단원 번호
- **유형별 연습지**: `practice{NN}-{단원약식}` — 예: `practice01-여러가지부등식`. NN은 연습지 순서 일련번호(과목 내). 유형편보다 가벼움(개념 페이지·STEP 분류 없음, 유형 헤더 + 유형당 3~4문)
- **답지**: `{기존책명}-답지` — 예: `test02-여러가지부등식-답지`
- **단원약식**: 한글 단원명을 띄어쓰기 없이 (예: "여러 가지 부등식" → `여러가지부등식`)
- **샘플·실험**: `sample-{설명}` 별도 prefix

**§0 결정 → book.yaml 필드 매핑**:

| §0 결정 항목 | book.yaml 필드 |
|---|---|
| 편(volume) | (파일명 prefix로 — 테스트지 `test{NN}-`, 유형편 `{NN}-`) |
| 과목·단원 | `subject` + `unit` |
| 대상층 | `audience` |
| 분량 (문항 수) | `total_problems` + `slots` 개수 |
| 분량 (페이지) | `layout` 자유 텍스트 |
| 도트 디자인 | book.yaml에는 안 들어감 (preamble에서 결정) |

**필드** (schema §6 스펙):
```yaml
title: ...
subject: CM1 | CM2
unit: PL | EQ | CB | GM | ST | FN | RF
audience: 상위권 | 중상위권 | 중위권 | 중하위권 | 하위권
allowed_stars: [...]              # 사용 허용 ★ 목록
distribution: {...}               # ★별 % (합 100)
total_problems: N
layout: 자유 텍스트
notes: 자유 텍스트
slots:
  - {n: 1, star: 3, type: T01, problem_id: null, role: 도입}   # type은 유형 코드 (schema §1.3)
  - {n: 2, star: 3, type: T02, problem_id: CM2-FN-014, role: 일반}
  - ...
```

**참조**:
- 디폴트 분포: schema §3.1 — 대상층별 권장 ★ 분포 (수정 가능)
- 코드 체계: schema §1 — `{과목}-{단원}-{일련번호}`

**체크리스트**:
- [ ] `audience` 값이 schema §3.1의 5단계 중 하나
- [ ] `distribution` 합이 100%
- [ ] `allowed_stars`와 `distribution` 키 일관
- [ ] `slots`가 `total_problems`와 같은 개수
- [ ] 각 슬롯의 `star`가 `allowed_stars` 안

**함정**: `book.yaml`을 안 만들고 바로 .tex로 직진하면 검수에서 분포 정합성 검증이 안 됨 → test02 사례. 반드시 먼저.

## 2. 앵커 점검

**목적**: 신규 문제 채점 시 비교 기준 확보. 앵커 없이는 ★ 라벨이 자체 점수만으로 결정되어 **비교 표준 부재** 상태가 됨.

**확인 위치**: `bank/anchors/{과목}-{단원}.md`

**보유 현황 검토**:
- 단원당 ★1~5 × 5문 = **25문 목표** (schema §4.1)
- ★ 4·5는 추가로 **v3.1 세련도 앵커 섹션 (각 단원 5문)** 보강 — `bank/anchors/CM1-*.md`의 "★ 4·5 세련도 앵커" 섹션
- 현재 책에서 사용할 ★ 범위에 충분한 앵커가 있는가
- 부족하면 (a) **첫 진입**: 출제 후 안정적 슬롯을 §10에서 등록 (b) **보유 있음**: 그대로 사용

**전체 현황**: [`bank/INDEX.md`](INDEX.md) 앵커 보유 현황 표

**v3.1 신규**: ★ 4·5 신규 출제 시 카탈로그 패턴 적용 의무 (다음 §3에 추가). 동단원·동통찰 세련도 앵커 2문과 비교.

**체크리스트**:
- [ ] `bank/anchors/{과목}-{단원}.md` 존재 (없으면 신규 생성)
- [ ] 사용할 ★ 범위에 최소 2문씩 보유 (비교에 2개 필요)
- [ ] 첫 진입이면 §10 앵커 등록 단계를 **반드시 거칠 것** 메모

**함정**: test02 사례 — CM1-EQ 첫 진입이라 앵커 0개 상태에서 출제 → 비교 기준 부재. 본문 8축 채점은 가능하지만 "이 raw 13이 ★3로 적절한가"를 비교할 표준이 없어 검수 결과가 자체 점수만 의존.

**앵커 부족 시 §6 검수 처리** (problem-review 동작):
- 앵커 비교 항목은 "앵커 부재로 검증 생략" 보고
- 8축 점수↔★ 매핑, audience_fit, book.yaml 정합성은 그대로 검증
- 부분 검수라도 책 작성·빌드는 진행 가능 — 단 §10에서 안정 슬롯을 앵커로 등록한 뒤 다음 책 작업의 비교 기준 확보

## 3. (유형편 한정) 개념 페이지 작성

**목적**: 단원 전반의 개념·공식·TIP을 책 앞부분에 정리.

**순서 메모**: 개념 페이지도 본문의 일부 → **§4-0 본문 구조 결정과 같이 진행**. 본문 매크로·레이아웃 규약은 §4-0에서 결정한 뒤 그 위에서 작성. (§3과 §4-0이 동일 시점이지만 단계 번호를 별도로 둔 이유는 유형편 vs 테스트지 분기 명확화 — 테스트지는 §3 skip)

**참조**: CLAUDE.md "유형편 페이지 레이아웃 규칙" §개념 페이지

**변경 가능 영역** (CLAUDE.md "변경 가능/변경 금지 영역"):
- 🟢 `conceptheader` 텍스트, `defbox` 내용, 박스 간 간격, 그림 삽입
- 🔴 `conceptbanner` 구조 (사용자 사전 승인 필요)

**체크리스트**:

## 4. 슬롯별 출제 — 7요소 + 8축 + 앵커 비교 + 답지 작성

**목적**: 각 슬롯의 문제 본문 + 메타 데이터 + 답지를 결정론적으로 생성.

### 4-0. 책 본문 구조 결정 (편별로 다름)

본문 LaTeX 구조는 책 유형에 따라 다른 매크로·레이아웃 사용. 이 단계는 **CLAUDE.md에 정의된 규약 참조**, 본 워크플로우에서 복제하지 않음. §0에서 결정한 도트 디자인이 본문에 적용됨 — preamble 작성 시 일관성 확인.

| 편 | 본문 구조 참조 |
|---|---|
| 유형편 | CLAUDE.md "유형편 페이지 레이아웃 규칙" — `\stepone/two/three` 배너, `\probcolheight`/`\probcolwidth`, 좌우 minipage + `cellab`/`cellc` 셀, `\vfill` 분배, 페이지당 6문(STEP 1/2) 또는 3문(STEP 3) |
| 테스트지 | CLAUDE.md "테스트지 제작 지침" — 페이지당 2~4문, `cellab` 단일 사용, `prob` 환경 검정 번호, 5단계 도트 |
| 표지 | CLAUDE.md "유형편 페이지 레이아웃 규칙" §표지 — `\chapterintro` TikZ overlay (테스트지는 표지 없음) |

**주의**: CLAUDE.md "변경 가능/금지 영역" 표를 §4 진입 전 반드시 확인. 🔴 영역은 사용자 사전 승인 필수.

### 4-1. 출제 7요소 (schema §7 기반, 출처·변형 분리)

신규 문제 작성 시 항상 명시:

```
① 단원·유형 코드 — 형식: "{단원 코드} {단원 내 유형 코드}"
   · 단원 코드: CM2-FN (schema §1 코드 체계의 과목·단원 부분)
   · 단원 내 유형 코드: T03 (해당 단원 카탈로그에서 정의, 예: 함수 단원의 T01~T22)
   · 예시: "CM2-FN T03" = 공통수학2 함수 단원의 T03 유형
② target ★ (1~5)
③ target 대상층 (5단계 중 하나)
④ 선호 축 / 회피 축 (schema §3.2)
⑤ 앵커 2개 (같은 단원·같은 ★, 부족 시 ±1★)
⑥ 출처 (참고자료명·페이지·문제 번호) — 신규 창작은 "신규"
⑦ 변형 정책 (1순위 숫자만 / 2순위 동등 / 신규 창작)
```

※ schema §7은 본래 "출처·변형 정책"이 한 요소로 묶여 있었으나, 책 검수 추적성을 위해 본 워크플로우에서는 분리.

### 4-2. 출제 후 8축 채점

각 축 1~3점, raw = C+S+D+K+A+T+I (7~21).

| 축 | 의미 | 채점 가이드 |
|---|---|---|
| C | 개념 결합도 | 동원 개념 명시 나열 → 1/2/3 |
| S | 풀이 단계 | 식 변형·논리 추론 단계 수 |
| D | 추론 깊이 | 직접 적용(1) / 절차 변형(2) / 비표준(3) |
| K | 계산 부담 | 한 줄(1) / 중간(2) / 다단계(3) |
| A | 표현 추상도 | 구체 수치(1) / 매개(2) / 일반 함수(3) |
| T | 함정 밀도 | 없음(1) / 1~2개(2) / 다중(3) |
| I | 창의도 | 표준(1) / 비표준 학습가능(2) / 통찰 도약(3) |

**raw → ★ 매핑**: 7~9 ★1 / 10~11 ★2 / 12~14 ★3 / 15~17 ★4 / 18~21 ★5

> **schema 중복 주의**: 본 표·매핑은 schema §2의 사본. schema 갱신 시 본 문서도 같이 변경해야 정합성 유지. 향후 자동 동기화 스크립트 도입 권장.

### 4-3. 앵커 비교 (anchor_diff)

같은 단원·같은 ★ 앵커 2개 선정 후 각 축에 대해 +1/0/-1 비교 + rationale 한 줄:

```yaml
anchors: [코드1, 코드2]
anchor_diff:
  코드1: {S: +1, T: 0, rationale: "분기 1단계 더, 함정 동등"}
  코드2: {C: -1, rationale: "한 개념 적음"}
```

**검증**: 신규 raw가 앵커 평균 ±2점 안에 들어와야 함 (schema §4.3).

### 4-6. 답지 작성

문제지와 페어로 답지(`{책명}-답지.tex`) 작성. **테스트지 답지 형식이 현재 표준**, 유형편 답지는 아직 미정(첫 유형편 답지 작성 시 별도 결정 필요 — 04 유리·무리함수에는 답지 없음).

**테스트지 답지 형식** (test02 사례):

| 도구·매크로 | 용도 |
|---|---|
| `\begin{multicols}{2}` | 2단 자동 압축 |
| `\probsol[색]{번호}` | STEP별 컬러 배지 + 번호 |
| `\begin{solution}...\end{solution}` | 풀이 본문 |
| `\answer{...}` | 정답 강조 |

**STEP 묶음 패턴** (test02):
- STEP 1 (★1~2): `step1color` 파랑 배지 — `\probsol{N}` (디폴트 색)
- STEP 2 (★3): `step2color` 보라 배지 — `\probsol[step2color]{N}`
- STEP 3 (★4~5): `step3color` 빨강 배지 — `\probsol[step3color]{N}`

STEP 묶음 경계는 책마다 조정. ★1·★2가 없는 책이면 STEP 1=★2, STEP 2=★3 등.

**유형편 답지** (미정):
- 본격 유형편 답지를 처음 만들 때 다음을 결정:
  - 유형별 묶음 vs STEP별 묶음
  - 대표문제·일반문제 풀이 깊이 차별 여부
  - 컬러 배지 패턴 (유형 헤더 색과 매칭 또는 STEP 색 따름)
- 결정 후 본 §4-6을 갱신, 첫 유형편 답지를 새로운 표준 사례로

**도트 표기**: §0에서 결정한 디자인 그대로 — 글로벌 사용이면 preamble 오버라이드 없음.

**풀이 공간 규약** (사용자 결정 2026-06-06, practice01 실전 발견):
- 한 셀(`\probcolheight`)에 풀이가 자세하게 들어가지 않는 경우 **한 페이지 전체를 한 문제 풀이에 할애 가능**.
- 한 페이지로도 부족하면 **1.5페이지·2페이지까지 사용 가능**.
- 다음 문제는 자연스럽게 이어서 진행 (페이지 break를 강제하지 않음).
- 즉 답지의 페이지 수는 문제지의 페이지 수와 1:1 매칭이 아닐 수 있으며, **풀이 가독성·자세함이 페이지 수보다 우선**.

**체크리스트**:
- [ ] 모든 번호가 문제지와 1:1 대응
- [ ] 각 풀이가 단계별 명시 (논리 비약 없음)
- [ ] `\answer{}`에 최종 답
- [ ] (테스트지) STEP 묶음 색이 본문 ★ 분포와 매핑
- [ ] 풀이 잘림 없음 (한 문제 풀이가 페이지 안에 들어가거나 자연 흐름으로 다음 페이지로 연속)

## 8. PDF 빌드 — xelatex 2-pass

**기본 명령** (PowerShell — 절대 경로 권장):
```powershell
Set-Location "C:\Users\user\Desktop\Cluade Projects\Math books\output\공통수학N"
$env:TEXINPUTS = "../../templates;"
xelatex -interaction=nonstopmode {파일명}.tex
xelatex -interaction=nonstopmode {파일명}.tex
```

**2-pass 의무**: `remember picture` 기반 TikZ overlay(분할선·표지 배경)는 2회 컴파일 필수.

**유형편·테스트지·답지 모두 동일 패턴**. 답지는 multicols라 페이지 수 자동 압축.

**검증**:
- 로그에서 `Overfull` / `Underfull box` 0건
- 로그에서 `! ` (LaTeX 에러) 0건
- `Output written on ... (N pages)` 확인

**체크리스트**:
- [ ] 2회 빌드 완료
- [ ] Overfull/Underfull 0
- [ ] 페이지 수가 예상과 일치 — **예상의 출처**: `book.yaml`의 `layout` 필드(예: "5페이지 × 4문항") 또는 §0 분량 결정. 일치 안 하면 셀 높이·풀이공간 조정 검토

**함정**:
- **PowerShell working directory persistence**: 이전 명령에서 `Set-Location`했으면 같은 세션 내 다음 명령은 cwd가 그 디렉토리. **상대 경로 cd 중복 시 경로 누적 에러** (예: `output\공통수학1` 안에서 또 `output\공통수학1` 호출). 절대 경로 cd로 안전 확보 또는 cwd 점검 후 호출 — test02 빌드 중 실제 발생.
- **`output/{과목}/` 디렉토리 없음**: 단원 첫 진입이면 `New-Item -ItemType Directory` 또는 .gitkeep 확인.
- **TEXINPUTS 미설정**: 빌드는 되지만 `mathbook.cls`를 못 찾아 에러. 매번 셸 시작 시 또는 빌드 직전 설정.
- **한글 파일명·로그 truncation**: PowerShell 출력이 좁아 파일명이 잘릴 수 있음 — `Format-Table -AutoSize` 또는 절대 경로 명시.

**빌드 실패 디버깅 가이드**:
1. **`Output written on ... pages`이 안 나옴** → 컴파일 중단. 로그에서 첫 번째 `! ` (LaTeX 에러) 찾기 + 그 위 5~10줄 컨텍스트
2. **첫 번째 `!`** → 보통 매크로 오타·환경 미닫음·인코딩 문제. 자주 발생: `\dotd`/`\dote` 정의 누락, `cellab` 안 `prob` 환경 미닫음, 한글 문자 인코딩
3. **`Overfull \hbox`** → 컬럼 폭 초과. 보통 `\nob{}` 안 너무 긴 수식. 해당 슬롯의 nob 분리
4. **`Overfull \vbox`** → 셀 높이 초과. `\probcolheight` 조정 또는 보기·풀이공간 줄임
5. **TikZ `package not found`** → MiKTeX 자동 설치 알림 — Enter로 진행
6. **이미지 못 찾음** (`! LaTeX Error: File not found`) → `\graphicspath{{../../}{./}}` 경로 확인, 파일명 한글 처리

- 안정 슬롯을 다른 책에서 재활용하고 싶을 때
- §4-5의 (B) 옵션 — 정식 등록

**위치**: `bank/problems/{과목}-{단원}-{일련번호}.md`

**역할**: YAML 프론트매터 + 본문. 다른 책의 슬롯에서 `problem_id`로 인용 가능 (schema §5).

### 공통: 대상 선정 기준
- 라벨↔정★ 일치 확인 (§6 통과)
- audience_fit이 안정적 (캡 여유)
- 패턴이 단원의 표준이거나 변별점이 명확

### 10-A 앵커 작성 형식
- 비교 규약: schema §4 (앵커 비교 ±2점 등)
- **실제 표준 형식은 기존 예시 파일이 정의**: `bank/anchors/CM1-EQ.md`, `bank/anchors/CM2-RF.md`
- 필수 컬럼: 앵커ID / 출처 / 패턴 요약 / C·S·D·K·A·T·I (8축) / raw
- 본문 구조: ★별 표 + ★별 특징 한 단락 + 향후 보충 메모 + 변경 이력

### 10-B 문제 작성 형식
- YAML 프론트매터 + 본문: schema §5.2 스펙
- 핵심 필드: `id`, `unit`, `type`, `scores` (8축), `raw_total`, `star`, `anchors`, `anchor_diff`, `audience_fit`, `audience_primary`, `sources`, `variant_policy`, `status`
- `status`: `draft` → `reviewed` → `approved` 흐름 (schema §5.3)

**연쇄 갱신**:
- 10-A 앵커 등록 시: `bank/INDEX.md` **앵커 보유 현황 표** 한 줄 갱신
- 10-B 문제 정식 등록 시: `bank/INDEX.md` **문제 등록 표**에 한 줄 추가 (코드 / 단원 / 유형 / ★ / raw / audience_primary / status / 키워드)

**체크리스트**:
- [ ] 신규 앵커마다 8축 점수가 등급 범위 안 (★3=12~14, ★4=15~17, ★5=18~21)
- [ ] 코드 일련번호 단원 내 unique
- [ ] INDEX.md 갱신
- [ ] 변경 이력에 등록일·출처 기록

**함정**:
- **미완성 슬롯 등록**: 라벨↔정★ 불일치인데 앵커로 올리면 이후 신규 문제 비교 시 잘못된 기준이 됨. §6 검수 통과한 슬롯만 등록.
- **INDEX.md 갱신 누락**: 등록은 했는데 INDEX.md를 안 고치면 다음 단원 진입자가 보유 현황을 모름. 등록과 동시 갱신.
- **출처 없이 앵커 등록**: 어떤 참고자료에서 왔는지 모르면 향후 변형·교체 결정이 어려움. 신규 창작이라도 "신규" 명시.

## 10.5. 시리즈 시험지 다음 회차 출제 — DB 활용 의무 절차 (2026-06-24 v1.0)

**적용 범위**: `output/{과목}/{학교}-{시즌}-예상/N회차-문제.tex` 형태 시리즈에서 1회차 이후의 신규 회차(2회차·3회차·…) 출제.

**Why**: 회차마다 통찰 패턴이 1·2회차를 복사하는 듯한 느낌이 들면 시리즈 가치 하락. 1,801+ 문항 DB(bank/problems/)를 *적극 활용*하여 검증된 통찰을 가져오고 변형으로 새 회차 구성. 동시에 CM1 교과과정 위반(역행렬·트레이스·케해·집합기호·다중무리수)을 *출제 단계에서* 자동 회피.

### 단계 0 — 시험범위·대상층·점수 정책 확정

```
시험범위: 예) CM1 - EQ-MV·INEQ·CB·MX (소단원·소목 수준 명시 의무)
대상층:   예) 상위권 (★ 3~5)
점수 분배: 객관식 ?문 ?점 + 단답형 ?문 ?점 + 논술형 ?문 ?점 = 100점
          (각 회차마다 탄력적으로 조정 가능. 동일 분배 강제 X)
★ 분포:   예) ★ 3 = 8~10문 / ★ 4 = 7~10문 / ★ 5 = 5~7문 (탄력적)
```

### 단계 1 — 이전 회차 통찰 인덱스 자동 추출 (의무)

이전 회차 `.tex` 파일에서 발문·답지의 핵심 통찰·도구를 추출하여 *이번 회차에서 회피*할 패턴 목록 작성.

```bash
# 1·2회차 .tex에서 발문·답지 본문 통합 추출
for f in 1회차-문제.tex 1회차-답지.tex 2회차-문제.tex 2회차-답지.tex; do
  echo "=== $f ==="
  grep -nE "케일리|해밀턴|역행렬|주기|포함배제|켤레|판별식|근과 계수|치환|함수의 개수|일대일|분할|색칠|중복|이웃|양 끝|성분 합|상수항|최댓값|최솟값" $f | head -50
done > _prev_rounds_insights.txt
```

(이를 자동화한 신규 도구가 도입되면 `node scripts/extract-round-insights.mjs` 형태로 단순화 가능. 현재는 grep으로 수동.)

이전 회차의 **각 슬롯별 통찰 표** 작성:
| 회차·# | 단원 | ★ | 통찰 유형 | 핵심 도구·발문 키워드 |
|---|---|---|---|---|
| 1회·#16 | MX | 5 | I-EQV+I-RT | $A+A^{-1}=3E$ + 성분합 선형성 |
| 2회·#25 | MX+EQ+CB | 5 | I-XU+I-CON | 카드 2장 + 행렬 $(α,1;0,β)$ + 이차 + α+β 홀수 |
| ... |

→ 이번 회차에서 **이 표의 패턴과 본질 동일 통찰 사용 금지**.

### 단계 2 — bank/problems DB에서 슬롯 후보 풀 추출 (의무)

`bank-query.mjs`로 시험범위·★·통찰 유형별로 검증된 후보 추출. 1·2회차 통찰과 중복되지 않는 후보만 골라 슬롯 *후보 풀* 구성.

```bash
# CM1 행렬 ★ 4 후보 (freq=3 우선)
node scripts/bank-query.mjs --unit CM1-MX --star 4 --freq 3 --csv _mx_star4_candidates.csv --limit 30

# CM1 방정식·부등식 ★ 5 후보
node scripts/bank-query.mjs --unit CM1-EQ --star 5 --freq 3 --csv _eq_star5_candidates.csv --limit 30

# 출처별로 보고 싶으면
node scripts/bank-query.mjs --unit CM1-CB --star 4 --source SRC --csv _cb_star4_src.csv  # 시판 검증
node scripts/bank-query.mjs --unit CM1-CB --star 5 --source DI --csv _cb_star5_di.csv     # 깊이와통찰 (학원 정답률)
```

후보 풀에서 슬롯별로 1~2개씩 선택:
- DI 출처 우선 (학원 표본 정답률 검증)
- 시판 출처 보강 (SRC — 일품·쎈·바이블 등 변별력 검증)
- freq=3 빈출 패턴 우선 (학생 친숙도 적정)

### 단계 3 — 중복 회피 필터 + 교과과정 자동 차단

```bash
# 후보 풀 .md 파일에서 본문 추출
for id in $(cat _selected_ids.txt); do
  cat bank/problems/${id}.md
done > _selected_pool.txt

# CM1 교과과정 위반 자동 검사
node scripts/cm1-curriculum-check.mjs _selected_pool.txt
# → 🔴 위반 검출되면 그 후보 제외하고 다시 선택

# n-gram 중복 점검 (단계 1 통찰 표와 후보 풀 발문 매칭)
grep -nE "역행렬|케일리|tr|⋂|⋃||X||다중무리수" _selected_pool.txt
# → 단계 1 인덱스의 통찰과 겹치는 후보는 제외
```

### 단계 4 — 변형 출제 (DB 통찰 → 신규 발문)

후보 풀에서 골라낸 통찰을 **본 프로젝트 §"문제 변형 정책"**(최소 변형 1순위·동등 변형 2순위)에 따라 신규 발문으로 변형. 그대로 복사 금지.

각 슬롯의 변형 단계:
1. 후보 ID의 통찰 유형·핵심 식 추출
2. 숫자만 변경 (계수·상수) — 1순위
3. 표현 살짝 변경 (x↔y, 넓이↔합 등) — 2순위
4. 절차·통찰은 보존
5. 신규 .tex 슬롯 작성 + `bank_source: {후보ID}` 명시 (출처 추적)

신규 슬롯의 YAML 메타에 `inspired_by` 필드 추가:
```yaml
inspired_by: SRC-1GM-MX-005  # 1등급마스터 MX 005번 통찰 변형
variant_policy: 숫자만 변경
```

### 단계 5 — 회차 다양성 자체 검증

신규 슬롯 25개 작성 후 단계 1의 *이전 회차 통찰 표*와 다시 매칭:
- 본질 동일 통찰 0건 확인
- 동일 행렬·동일 함수 형식 0건 확인 (회차 내 자기복제 방지)
- 단원 분포 균형 (EQ·MX·CB·INEQ가 시험범위 비율대로)

### 단계 6 — 검수 3축 호출 (의무, [[feedback_auto_review_completed_work]])

기존 워크플로우대로 problem-review·general-purpose·solution-author·solution-review·exam-review 5종 호출.

exam-review가 단계 1·5의 통찰 인덱스를 받아 *회차 간 다양성* 정량 평가 (E2.1 패턴).
