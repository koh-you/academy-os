# 통합 자산 스키마 v2.0

## 배경 · 목적

**현행 문제** (v1.0):
- 18개 정독 파일마다 필드 형식 다름 (개념원리·RPM·고쟁이·블랙라벨·마더텅·EBS·전국연합 등)
- `tier: star_3` 정도로만 표시 · M·I·depth 미기록
- 문제 출제용 원본 은행과 난이도 실측 데이터가 별도로 관리
- problem-author agent가 원본 pick 후 시스템 판정 재계산 필요

**v2.0 통합**:
- 모든 정독 파일 = 원본 은행 + 난이도 실측 데이터 = **하나의 자산**
- 필수 필드 정합 → 자동화 도구 (bank-query·anchor-compare·structure-signature-check) 단일 인터페이스
- 벤더 라벨 → 시스템 ★ 회귀 매핑 데이터 축적 (`vendor-label-calibration.md`)
- **자산 규모 확대 → 검증 정밀도 자동 향상** 인과 사슬 확립

## 문항 엔트리 표준 (필수 필드)

```yaml
- id: <출처약자>-<과목>-<단원>-<소단원>-<원본번호>
  # 예: 쎈-CM2-GM-평면좌표-0083 · 마-CM2-GM-평면좌표-0116

  page: <원본 페이지 번호>
  vendor_label: "<원본 벤더 난이도 라벨 원문>"
  # 예: "교육청·사고력·10쪽 유형01+17쪽 유형12" · "TOUGH" · "STEP 3 행복한 일등급"

  category_type: <원본 카테고리>
  # 예: "C단계 사고력" · "STEP 1 NORMAL" · "확인체크"

  summary: |
    <발문 요지 2~4줄 요약 · 조건·구하는 것 명시 · 원문 전사 금지>

  category: <유형 카테고리 자연어>
  # 예: "각 이등분선·삼각형 유사비" · "두 점 거리 최소"

  # === 시스템 정밀 판정 (필수) ===

  M: {s: <1~3>, k: <1~3>, a: <1~3>, t: <0~3>}
  M_total: <4~12 합계>

  insights:
    - step: <풀이 단계 번호>
      type: <I-XU | I-BW | I-RT | I-EQV | I-MI | I-PD | I-SYM | I-CON | I-SC | I-VF>
      depth: <1 | 2 | 3>
      effective_depth: <depth 원값 · 자산화 유형+P신호 미매칭 시 강등>
      signal_ref: [<P1 | P2 | P3 | P4 | P5 | P6>]   # depth 3 인정 근거 (있으면)
      description: "<이 단계에서 요구되는 통찰 1~2줄>"
    # 통찰 단계 여러 개
  insight_count: <라벨링된 단계 수>

  depth_score: <max(effective_depths) × 2 + avg(effective_depths)>
  # 산식: schema.md §2.4.1

  base_star: <1~5>
  # base = depth_score 기반 or 절차형 M 기준 (schema.md §2.4.1)

  star: <1~5 · 최종 판정>
  # base ± 조정 · schema §2.4 v3.8 알고리즘

  premium: <true | false>
  # depth_score ≥ 8.5 + max(effective_depths) = 3 + insight_count ≥ 5 + signal_ref P 카드 ≥ 2 (schema §2.12)

  # === 근거 · 참조 (필수) ===

  rationale: |
    <판정 근거 1~2줄 · M·I·저노출 유형·앵커 대조 요약>

  # === 원본 은행 활용 필드 (필수) ===

  tier: <star_1 | star_2 | star_3 | star_4 | star_5 | star_5_premium>
  # star + premium 파생 (호환용 · 기존 자동화 도구 인식 유지)

  mechanism_primary: <핵심 풀이 도구·유형 자연어>

  insight_type: <절차형 | 통찰형>
  # insight_count == 0 → 절차형 · > 0 → 통찰형

  target_cohort: <상위권 | 중상위권 | 중위권 | 중하위권 | 하위권>
  # schema.md §3 대상층 5단계

  # === 관리·활용 추적 필드 (선택) ===

  anchor_status: <null | candidate | anchor>
  # 이 원본이 앵커 pool 후보인가

  usage_ref: []
  # 이 원본이 우리 시험지·유형편에 사용된 사례 (OUT-* ID 목록)

  cross_reference:
    - source: <다른 원본 id>
      relation: <"동일 학평 원본" | "구조 시그니처 근사" | "숫자만 변형" | ...>
  # 다른 자산과의 관계 (자기복제 감지·중복 배제)

  novelty_score: <0 | 1 | 2 | 3>
  # 시판 노출도 (schema.md §2.14) · 0 = 흔함 · 3 = 진정 신규

  vendor_calibration_signal:
    L1_publication_correct_rate: <null | float>
    # 시판 자산 표기 정답률 (있으면)
    L2_signature_neighbors: []
    # 시그니처 유사 이웃 id (S4 신호용)
    L3_multi_vendor_tier: []
    # 다른 벤더의 tier 라벨 목록 (S1 신호용)
    L5_confidence: <0.0~1.0>
    # 판정 신뢰도 자체 report

  # === 파생 필드 (자동 계산 · 기록 선택) ===

  friction_triggers: [<F1 | F2 | F3 | F4 | F5>]
  # schema.md §2.11 friction 트리거

  friction_verdict: "<OK | YELLOW>"
```

## 표본 vs 예측 구분 명시

**표본 (시스템 순정 판정)**:
- 위 모든 필드를 실측 채움
- `rationale`에 통찰 판별 근거 상세 기재

**예측 (벤더 라벨 회귀)**:
```yaml
- id: <원본 id>
  page: <페이지>
  vendor_label: "<라벨>"
  summary: |
    <요약>
  
  # === 예측 필드 (표본 미포함 문항) ===
  prediction_source: vendor-label-calibration v1.0
  predicted_star: <1~5>
  predicted_confidence: <0.0~1.0>
  prediction_note: |
    <회귀 근거 · 예: "쎈 B단계 대표문제 → ★ 2.8 (편차 0.7) 회귀">
  
  # tier·target_cohort 등 표본용 필드는 예측 값으로 채움
  tier: star_<n>
  target_cohort: <cohort>
```

**예측 문항은 반드시 `prediction_source` 필드로 구분 표시** → 자동화 도구가 신뢰도 차등 적용.

## 기존 v1.0 자산 마이그레이션 절차

**대상**: 기존 18개 정독 파일

**절차** (자동 + 수동):

1. **자동 필드 매핑** — `scripts/migrate-v1-to-v2.mjs` (신규)
   - 기존 필드 유지 (source·page·category_type·summary·category·mechanism_primary·insight_type·depth·tier)
   - **벤더 라벨 회귀로 신규 필드 자동 배정**:
     - M: 회귀 예측 초안 (`predicted_star` → M 프로파일 역추정)
     - insights: 기존 `insight_type`·`depth` 필드 → v2.0 insights 형식 변환
     - depth_score: 기존 `depth`에서 산출
     - base_star·star·premium·tier: 벤더 회귀 매핑 (파일럿 1 매핑 사용)
     - target_cohort: 기본값 (star 기준 자동 매핑)
     - prediction_source: `vendor-label-calibration v1.0` 표기

2. **표본 재판정** — 각 파일에서 15~20문 무작위 표본
   - 표본은 예측 필드 지우고 시스템 순정 판정
   - 회귀 편차 실측 → 회귀 함수 정정

3. **자산 신뢰도 스코어 갱신** — `weighted_confidence_score.mjs`

**마이그레이션은 Phase 2에서 착수**. Phase 1에서는 v2.0 형식 확정만.
