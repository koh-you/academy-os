# 표준 유형 카탈로그 (Type Catalog) — 단일 출처

> **2026-06-25 마스터 명시**: "출제된 문제들이 하나같이 같은 형태의 질문들이며 수준도 매우 낮아... 유형의 본질·깊이를 못 잡고 형식적 정합만 검수. 자산을 뭐하러 구축한 거지?"

## 1. 목적

각 단원의 **표준 유형**(T-code)을 정의하고 *출제·검수의 단일 출처*로 삼는다. 본 카탈로그는 다음을 보장:

- 출제 시 *유형 풀에서 다양하게* 셀렉 (단조 출제 방지)
- 자산 풀(`bank/problems/`)의 각 문제가 *어느 유형*인지 라벨링
- ★ 산정의 **base ★는 유형 자체로 결정** (통찰 카드 카운트 아님)
- 검수 시 *유형 다양성·유형-★ 정합*·*자산 인용*을 점검

## 3. 유형 항목 양식

각 T-code = 1행 또는 1섹션:

```markdown
### T{NN}: {유형명}
- **id**: CM1-EQ-T{NN}
- **base ★**: 표준 ★ 수준 (1~5, *유형 자체*로 결정)
- **section**: 소단원 (시험범위 yaml의 section_id와 매핑)
- **본질 통찰**: 이 유형이 묻는 핵심 아이디어 (1~2 문장)
- **대표 자산**: bank/problems/*.md 인용 (≥ 2건 권장)
- **대안 발문**: 같은 유형의 다양한 발문 예시 (3~5건)
- **금지 변형**: 단순 계산만으로 ★ 4 라벨링 금지 등
- **출제 빈도**: 시리즈에서 권장 빈도 (예: "5회마다 1회")
```

## 4. base ★ 산정 원칙 (v4.0)

**유형 자체가 base ★를 결정한다**. 통찰 카드 카운트·M_total은 *±1 조정만*. 단순 유형(예: T19 여사건)에 통찰 추가해도 ★ 4 못 만든다.

| base ★ | 의미 | 예시 |
|---|---|---|
| ★ 1 | 공식 직접 대입 | $_n\mathrm{C}_r$ 직접 계산 |
| ★ 2 | 1단계 변형 + 직접 적용 | 여사건 단순, 절댓값 부등식 단일 |
| ★ 3 | 2단계 변형 또는 분기 1개 | 케이스 분기, 단순 인수정리 |
| ★ 4 | 다단계 변형 또는 분기 2+ | **색칠**, **수형도**, **분할·분배**, ω 활용, 중근 조건 |
| ★ 5 | 다층 결합 + 분기·자기참조 | 매개변수 + 자유도, ω + 정수 조건, 다중 중근 |

**Xᵤ 친숙도 보정 폐지** (★ 인플레이션 주범). CM1-MX·CB·FN 친숙도 보정은 v4.0에서 제거.

## 5. 출제 시 의무 (v3.0 메커니즘 G3')

- 모든 슬롯 청사진에 **`type_id` 필수**
- 시험지 1회차에 *서로 다른 T-code 비율* 의무:
  - CB 슬롯 10문 → ≥ 7개 서로 다른 T-code
  - EQ 슬롯 10문 → ≥ 7개 서로 다른 T-code
  - MX 슬롯 3문 → ≥ 2개 서로 다른 T-code
  - **GM 슬롯 10문 → ≥ 7개** / 15문 → ≥ 10개 (2026-07-06 신설)
  - **ST 슬롯 8문 → ≥ 6개** (2026-07-06 신설)
  - **FN 슬롯 10문 → ≥ 7개** (2026-07-06 신설)
  - **RF 슬롯 6문 → ≥ 4개** (2026-07-06 신설)
- **`anchor_ref` 최소 1건 의무** — bank/problems/ 자산 인용 (0건 → G3' RED)
- 시리즈 미사용 T-code 우선 셀렉
