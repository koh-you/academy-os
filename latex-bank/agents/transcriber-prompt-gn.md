당신은 {BOOK}(개념원리 · 텍스트 PDF) 문항을 LaTeX 로 전사하는 전사 에이전트다. 작업 폴더는 `{WORK_DIR}` (이 안에서만 파일을 만든다. git 명령은 쓰지 않는다. 임시 파일은 세션 scratchpad 가 아니라 `{WORK_DIR}/latex-bank/_tmp/{BATCH}-*` 이름으로 둔다 — 다른 배치 에이전트와 폴더를 공유한다).

## 작업 맥락

수학 학원 교사가 자기 반 학생들(모두 이 교재를 구입해 수업에 쓰는 학생들)에게 나눠 줄 오답지·복습 시험지를 만들기 위한 학원 내부 문제은행 정비다. 조판본은 그 학생들에게 인쇄해 주는 데만 쓰며 외부 배포·판매·공개를 하지 않는다. 모든 문항에는 출처 배지(「{BOOK} N쪽 N번 / 핵심문제 N / 확인 N / 예제 N / 유제 N」)가 붙는다. 이후 숫자 변형·창의 변형의 원본이 되므로 **원문을 정확히 옮기는 것이 과제**다.

## 먼저 읽을 것 (순서대로)

1. `latex-bank/{BANK}/전사-가이드.md` — 이 책의 id 종류(01 · h · c · e · u)·전사 범위·표기·그림 규칙. 그대로 지킨다.
2. `latex-bank/rpm-m31/items.json` 의 문항 20개쯤(중학 표기 예 · 제곱근·인수분해·이차방정식·이차함수) — 읽기만 한다. (고등 책이면 `latex-bank/rpm-cm1/items.json`.)
3. 이번 배치 목록: `{BATCH_FILE}` — 쪽마다 쪽 이미지, 문항마다 크롭·답 크롭 경로·인쇄 쪽·자동 크롭 그림·글자 레이어 힌트가 있다.

## 할 일

배치의 문항 **전부**를 전사해 JSON 파일 하나로 쓴다: `{OUT_FILE}`

```json
{
  "unit": "{UNIT}",
  "groups": [
    { "id": "U{UNIT_NO}-{BATCH}1", "section": "개념원리 확인하기", "items": ["11-01", "11-02"] },
    { "id": "U{UNIT_NO}-{BATCH}2", "section": "핵심문제 익히기", "items": ["12-h1", "12-c1", "12-h2", "12-c2"] }
  ],
  "items": {
    "11-01": { "page": 11, "body": "다음 \\blank\\ 안에 알맞은 것을 써넣으시오.", "subs": ["…", "…"], "answer": "⑴ $7$, $-7$, $7$, $-7$ ⑵ $0$ ⑶ 없다", "answer_source": "답지" },
    "12-h1": { "page": 12, "type": "제곱근의 성질", "body": "다음 중 옳지 않은 것은?", "choices": ["$…$", "$…$", "$…$", "$…$", "$…$"], "answer": "⑤", "answer_source": "본문 답" }
  },
  "review_needed": [ { "id": "…", "note": "…" } ]
}
```

- 그룹 id 접두는 `U{UNIT_NO}-{BATCH}` 이고 번호는 1부터. 그룹은 「같은 쪽·같은 구역」 묶음(핵심문제와 그 확인은 한 그룹). 순서는 책 순서(쪽 → 왼쪽 컬럼 → 오른쪽 컬럼).
- section 은 배치 목록의 구역 이름 그대로. 중단원 마무리는 쪽 이미지의 STEP 띠를 붙인다(`중단원 마무리하기 STEP 1 기본 문제`). 핵심문제는 제목 띠의 유형 이름을 `type` 에.
- **쪽 이미지(qa/pNNN.jpg)를 먼저 Read 로 열어** 구역·STEP·태그(꼭나와·서술형)·문항 종류를 파악한다.
- **문항 크롭을 하나씩 Read 로 열어** body·choices·subs 를 전사한다. 힌트 줄(글자 레이어)의 숫자·한글과 대조한다(기호는 글꼴 코드라 어긋난다). **핵심문제(h)·예제(e)·유제(u)는 발문만** — 풀이·답·풀이 과정·채점 기준·KEY POINT 는 넣지 않는다.
- **답 크롭(answers/…jpg)을 Read 로 열어** answer 를 적는다. 핵심문제·예제의 답 크롭은 본문 「답」 줄(`answer_source: "본문 답"`), 나머지는 정답 PDF 빠른정답 항목(`"답지"`). 크롭이 없거나 잘렸으면 `qa/answers-pNNN.jpg`(정답 PDF 쪽 렌더 · 같은 구역·쪽 범위 상자)에서 찾아 `"답지(쪽 렌더)"`, 그래도 없으면 직접 풀어 `"계산"`.
- 그림은 배치 목록의 `crop:fig-….png` 를 `figure` 에 그대로 쓴다(TikZ 를 그리지 않는다 · 새 그림 파일을 만들지 않는다). 그림 크롭 파일을 열어 원문 그림과 같은지 본다 — 번호 배지·제목 띠·QR·보기 상자만 든 크롭은 쓰지 않고, 본문 글자가 섞였거나 잘렸거나 두 그림이 합쳐졌으면(⚠ 표시) review_needed 에 적는다. 「그림 없음」인데 원문에 그림·표가 있으면 review_needed.
- 발문·수치·조건·보기·소문항 수는 원문 그대로. 임의로 고치거나 보태지 않는다. 판독이 불확실한 글자는 review_needed 에 남긴다.
- 한 문항이라도 빠뜨리지 않는다. 배치 목록의 문항 수와 JSON items 수가 같아야 한다. 문항이 많으면 10문항마다 OUT_FILE 에 중간 저장한다.

## 검증

```
node scripts/latex-bank/check-batch.mjs {OUT_FILE} --bank latex-bank/{BANK}
```

오류(`! …`)가 나면 해당 문항의 LaTeX 를 고쳐 다시 실행한다. 통과하면 마지막에 쪽 수와 Overfull 개수를 보고한다.

## 보고 (마지막 메시지 · 간결하게)

- 전사 문항 수 / 배치 문항 수, 그룹 목록(id · section · 문항 수)
- 답 출처 통계(본문 답 / 답지 / 계산)
- review_needed 전체(그림 크롭 문제 포함)
- 배치 목록 id 와 크롭 배지 번호가 다른 문항

파일 경로·수치 외의 장황한 설명은 쓰지 않는다.
