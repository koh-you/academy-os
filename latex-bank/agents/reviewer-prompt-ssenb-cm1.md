## 맥락

학원 내부 오답지·시험지용으로 스캔 교재 문항을 LaTeX 로 다시 조판했다(`latex-bank/ssenb-cm1/items.json` · 규약 `latex-bank/ssenb-cm1/전사-가이드.md`). **문항 id 는 `인쇄쪽-번호`**(예 `86-47`)이고 번호는 중단원마다 01 부터 다시 시작한다(뒷단원은 3자리). 743문항 · 10단원.

문항마다 `latex-bank/ssenb-cm1/review/<id>.png` 에 **왼쪽 = 원본 스캔 크롭, 오른쪽 = 조판본**이 나란히 있다. 조판본이 원문과 내용이 같은지 확인하는 것이 과제다. **수학적 풀이는 하지 않는다**(답은 이 단계에서 비어 있고 조판본에 안 나온다).

### 원본 크롭을 믿을 수 없는 경우 (이 책에서 잦다)

1. **크롭이 없는 문항** — 「01 | 대표 문제」처럼 검은 상자 안 흰 숫자 배지는 OCR 이 못 읽어 스캔 단계에서 빠졌다. 전사 에이전트가 쪽 렌더로 넣었으므로 review 그림에 원본이 비어 있거나 다른 문항이 들어 있다.
2. **크롭 번호가 실제 배지와 어긋난 구간이 있다** — 크롭 파일 이름의 번호는 검출 순번이라 밀린 곳이 있다(예 p115~119, p133~134, p75~76, p27~30). 그래서 **왼쪽 원본이 오른쪽 조판본과 다른 문항일 수 있다.**
3. 크롭이 위·아래로 잘려 첫 줄이 안 보이거나 이웃 문항이 섞여 있을 수 있다.

**위 셋 중 하나라도 의심되면 반드시 쪽 이미지 `output/problem-bank/ssenb-cm1/qa/pNNN.jpg` 를 Read 로 열어 그 쪽에서 해당 배지 번호 문항을 찾아 대조한다.** id 목록 각 줄의 두 번째 칸이 그 쪽 이미지 경로다. 쪽 이미지가 흐려 안 읽히면 원본 PDF 에서 다시 크게 잘라 본다:

```bash
# pt 상자(x0 y0 x1 y1 · 쪽 전지 기준 533.9pt 폭)를 크게 잘라 PNG 로. 마지막 인자는 확대율.
node latex-bank/tools/crop-page.mjs ssenb-cm1 <쪽> <x0> <y0> <x1> <y1> <out.png> 4
```

두 컬럼 판이라 왼쪽 컬럼 전체는 `20 <y0> 280 <y1>`, 오른쪽 컬럼은 `285 <y0> 530 <y1>` 쯤이다. 출력 PNG 는 `latex-bank/ssenb-cm1/검수/2026-09-26/tmp/` 아래에 만든다.

**「원본과 조판본이 다른 문항이다」는 것 자체가 red 지적이 아니다.** 쪽 이미지에서 배지 번호로 확인해 조판본 내용이 그 번호 문항과 같으면 정상이고, `note` 에 「크롭 어긋남 — 쪽 이미지로 대조해 일치」라고만 적는다. 조판본이 **엉뚱한 번호의 문항**을 담고 있으면 red 다.

### 「쎈 NNNN」 연계번호

문항 오른쪽 위의 「쎈 NNNN」 이 조판본에도 실려 있다. 원본 쪽 이미지의 연계번호와 다르면 red(`where: "layout"`).

전사 에이전트가 남긴 주의사항이 `latex-bank/ssenb-cm1/work/review-needed-merged.json` 에 있다. 담당 구간 id 가 거기 언급되면 먼저 읽고 그 점을 집중해서 본다.

## 볼 것 (원본 ↔ 조판본)

1. 🔴 **내용 불일치**: 수치·부호·기호(√, 분수, 첨자, 절댓값, 각도, 행렬 pmatrix, ₙPᵣ/ₙCᵣ)·조건 문장·「(단, …)」·보기 값·보기 개수·소문항 수·「옳지 않은」 같은 부정어가 다르거나 빠짐. 원본에 있는 그림·표·보기 상자(ㄱㄴㄷ)·조건 상자·힌트 빈칸이 조판본에 없음(또는 반대). TikZ 로 다시 그린 그림·표가 원문과 구조(점 개수·라벨·길이·각 표시·표 칸·좌표축 절편)가 다름. **원문에 없는 값(답이 되는 값)이 그림에 적힘**.
2. 🟡 **조판 문제**: 수식이 줄 끝에서 끊김, 보기 배치가 어색함, 그림이 본문과 겹치거나 지나치게 크거나 작음, 번호·배지·태그(「대표 문제」「서술형」「집중공략」) 이상, 공통 지시문이 문항에 안 붙었거나 중복, 별도 줄 식이 본문에 붙어 버림.
3. ⚪ **정상**: 문제 없음(개수만 기록).

## 출력

`{OUT_FILE}` 에 JSON 하나:

```json
{ "range": "7-01~15-57", "checked": 62, "ok": 55,
  "findings": [
    { "id": "13-40", "severity": "red", "where": "body", "note": "원본 x²−4x+1, 조판본 x²+4x+1", "fix": "items['13-40'].body 의 +4x 를 -4x 로" },
    { "id": "14-47", "severity": "yellow", "where": "figure", "note": "그림이 본문보다 두 줄 아래로 밀림" },
    { "id": "115-63", "severity": "ok", "where": "layout", "note": "크롭 어긋남 — 쪽 이미지로 대조해 일치" }
  ] }
```

- `where`: body · choices · subs · hint · figure · passage · layout (`answer` 는 이 단계에서 비어 있어 검수 대상 아님).
- `fix` 는 `items.json` 을 어떻게 고칠지 한 줄(확실할 때만). 판독이 애매하면 `note` 에 「확인 필요」.
- **문항 20개쯤마다 출력 파일을 중간 저장한다.**
- 마지막 메시지: checked/ok/red/yellow 개수와 red 목록만 간결하게. 장황한 설명 금지.
